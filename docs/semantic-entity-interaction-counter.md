# 实体持续交互计数：生产、衰减与状态清除

日期：2026-10-30。深化第21研究单元。研究范围为A+21的命中协议，以及A=E+74实体上的E+95消费者；不据此推断全部实体均使用相同更新入口。偏移和掩码均为十六进制。

[原ROM证据](semantic-data/entity-interaction-counter-evidence.json)保存8个函数的可达指令、常量和区间SHA1。基线为c4d93a58f0f82c526dec8a3fdbda170336303689；本轮未运行游戏、重建或修改正式代码。

## 初始化与建立交互

06DE4的32位零写入A+20覆盖A+20..23，因此会清零A+21。37524把E+74传给06DE4，故这条实体安装链中，计数实际位于E+95。单独06E08只换描述，不等价于重做06DE4初始化。

07258在一般数值伤害之前处理一类持续交互。令S/T为源和目标组件，Ds/Dt为其缓存描述。除前面的全局及掩码筛选之外，此段要求：

- Ds[A]&21非零，且Dt[A]&04非零。
- 当前累计S[18]未含800，T[18]未含400，避免同一次处理阶段重复占用。
- 若历史S[1C]&800或T[1C]&400成立，必须S[10]==T且T[10]==S，才能继续这段历史交互。

无这两种历史标志时，代码互写S/T的+10伙伴指针，将 `(Ds[A]&F0)>>1` 同时写入双方+21，并写源临时/累计800、目标临时/累计400。计数可能为0，初始化这次仍可成立。

历史交互的再次成立条件为：

```text
source_count != 0 && ((Ds[A]&2) != 0 || target_count != 0)
```

因此Ds[A]的02位会让本次检查不要求目标计数非零；源计数仍必须非零。这一段没有每次重复接触都刷新双方计数。交互失败后也会继续进入07258后面的其他分流，而非直接证明整个碰撞无效。

这里的400/800关系和数值扣血是独立层次，暂不为它们命名具体游戏动作；详见 [命中核心](semantic-hit-damage.md)。

## E+95的衰减入口

27FC0和285E8均先按E+E索引各自回调表（08333E78/08333EA0）并执行回调，再调用370D8(E,1,1,1,1,1)取得步长k，随后执行：

```text
n = u8[E+95]
u8[E+95] = n >= k ? n-k : 0
```

这是无符号比较后的饱和减法，不会在n小于k时回绕成大值。步长并不固定为1，也不由登记函数计算。

37088读取动作新出现位F=u8[E+196]（来源见[动作历史报告](semantic-entity-action-history.md)），将五个输入权重按以下五个条件求和：低半字节非零、10、20、40、80。低半字节即使有多个位置位，也只贡献一次权重。370D8保留前四个权重，仅当u8[E+1F5]==1时保留第五个，否则把第五个权重替换为0。因此上述全1调用得到：

```text
k = bool(F&0x0F) + bool(F&0x10) + bool(F&0x20)
  + bool(F&0x40) + (u8[E+0x1F5]==1 ? bool(F&0x80) : 0)
```

k范围为0..5（第五项关闭时0..4）。F=0时k=0，计数不因这段代码减少；不能把初始值直接解释成固定持续帧数。E+196的生产已由后续动作历史研究连接；整个实体调度频率仍未换算成固定帧数。

例如n=8、F=FF时，第五项开/关分别减5/4；n=3且k=5时直接归零；F=0时n=8保持8。对FF也没有全局“不递减”豁免：在这两个入口中它同样参与减法。

## 27FC0还把计数变化反馈到动画选择

27FC0在370D8调用之前快照E+95；注意此快照已经发生在表回调之后，不是函数入口原始值。它读取s8[E+18D]：负值直接跳过反馈；正值先减1；只有原值0或减至0时，再比较计数快照与衰减后的值。

确有变化则写反馈计数4，并调用1E9FC：当前u8[E+17F]==7F时选82，否则选7F。正值尚未归零时只保存减后值，负值不写回。故这里存在更新节流，不能描述为计数每变化一次就切换动画。1E9FC设置逻辑组并刷新碰撞描述的关系见 [动画形状报告](semantic-animation-collision-shapes.md)。

## 状态入口可直接清除计数

28BD8先设置E+F=1、E+18C的02位、速度字段和其他状态，再调用1EA38(E,6,1,1)。随后若u32[E+8C]&400成立，就清除E+95：

- n<FF时直接写0。
- n==FF时分支到08028C38，原ROM指令为subs r0,#0xFF，再写回，结果同样为0。

第二个分支目标在现有自动提取文本中以gap半字出现，不能因为表面没有助记符而漏掉这个写入。这里可证明条件满足时全部u8输入都变0；不能把FF理解成这个状态中的永久值。条件不满足时本段不写E+95，之后仍调用28C48，其他调用的副作用需分别判断。

## 易混淆字段与适用边界

06E90/06F50/07058递减的是A+20的低7位并保留高位80，并非A+21。本报告补齐了E+95在上述具体实体更新入口中的衰减、反馈和清除，不把该规律泛化到所有组件。

检索还发现CF780/CFAD8含add #95，但那里寄存器原已指向E+25，实际最终地址是E+BA，不能计入E+95消费者。8C06C另有E+95清除路径，尚未展开其完整状态机。本轮不作“已找到所有写入者”的结论。

[动作历史报告](semantic-entity-action-history.md)已补齐E+196生产者，[角度报告](semantic-entity-render-angle.md)已连接E+24写入和绘制约定；继续追踪其他实体交互计数与动作历史查询。累计仍21个研究单元，不能用它计算项目语义完成率。
