# 实体碰撞组件与分类登记

2026-10-30。第21个研究单元，独立于前述地形网格与动态地形矩形：本系统使用E+74组件、24B描述链及IWRAM分类链表。[原ROM证据](semantic-data/entity-collision-registry-evidence.json)保存11个函数/BIOS包装的可达指令、常数及3份描述样本，基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。仅只读分析及独立研究文档，不改正式代码或重启提取。

地址/偏移为十六进制，计数明确按十进制；几何量沿用24.8坐标。此处尚未解释命中伤害、阵营或优先级协议，字段不凭常见引擎惯例命名。

## 三种24B结构不能混淆

| 结构 | 位置 | 关键用途 |
|---|---|---|
| 本系统ROM描述 | 如083347D4 | 头字段、连续项标记、s16偏移及u16尺寸 |
| 本系统运行时节点 | 030032E4起 | 链接、描述/组件指针、变换后位置、尺寸 |
| 既有动态地形矩形 | 020011D4起 | id/属性、当前与历史中心、最多31项 |

前两种也都是24B，但不是相同布局。E+D8中的运动形状更是另一种8B四边缘记录，见[形状来源报告](semantic-animation-collision-shapes.md)。登记是否生效不能仅凭一份矩形几何存在判断。

## 组件初始化和三个安装接口

以A为组件，实际消费者常用A=E+74。06DE4(A,descriptor,positionPtr,value)清A+18/+1C两个状态字、A+20状态字及+24/+28/+2C指针槽，保存positionPtr到A+8，保存value低16位到A+30，再调用06E08。37524随后另行写组件所有者和回调，不是06DE4自动填入。

- 06E08(A,D)：写描述指针A+0，清u8[A+36]和u8[A+3B]。
- 06E80(A,D,control)：同样写A+0，清A+36，把control低8位写A+3B；不把该值当描述条数。
- 06E18(A,D,a,b,c,d)：写描述，四参数先截u16，再分别把低8位存A+37..+3A；以它们的s16是否非负设置A+36的01/02/04/08位，清A+3B。

因此06E18的“是否提供该项”依据截断后的16位符号，不是存下来的8位符号。例：a=-1、b=4、c=-1、d=16时，四字节为FF/04/FF/10，掩码为0A。掩码后续具体控制哪些碰撞字段尚待命中处理器证实。

已有375C4在特定状态传06E80的control为4或10。本轮两个登记器均不读取A+36..+3B，说明这些安装控制在这两个登记入口中不直接决定节点数量；不能把control=4解释成登记4个矩形。

## ROM描述24B可证字段

| 偏移 | 读取类型 | 已确认用途 |
|---|---|---|
| +0 | u8 | 分类键第一分量k |
| +1 | u8 | 分类键第二分量s |
| +3、+8 | u8 | 首描述两者均0则跳过登记 |
| +B | u8 | 非0则继续下一项，步长18 |
| +10/+12 | s16 | 对位置指针读取值的X/Y偏移 |
| +14/+16 | u16 | 原样复制到节点的宽/高字段 |

+B不作为数值循环次数递减：每登记一条只测非零，再把描述指针加24B，直到某项+B为0或全局容量用尽。即便字段在数据设计上可能表示剩余量，现有循环语义也必须按实际标记保留。

首描述+3/+8筛选只在进入链前执行；后续描述并不每项重新做同样的非零检查，不能把该筛选移动进循环后声称等价。尚未给+3或+8贴伤害/抗性等具体名称。

## 全局64节点与9分类链头

G=030032E0，u8[G+3]为当前计数，节点从G+4起、24B步长。进入每项前要求计数<=63，随后加1，因此最多64个节点；不是64个实体。一个实体的描述链能贡献多项，容量不足时可能仅登记前缀。

| 节点偏移 | 含义 |
|---|---|
| +0 | 同分类next指针 |
| +4 | 对应ROM描述指针 |
| +8 | 所属组件A指针 |
| +C/+10 | 从positionPtr得到的坐标加/减描述偏移 |
| +14/+16 | 描述u16宽/高 |

链头地址G+604+4*(3*k+s)。节点插入表头，故同桶后登记的项先被遍历。索引未在登记器中检查；9个清零链头覆盖索引0..8，不据此保证任意输入k/s都合法，也暂不把分类键命名成攻击/受击/阵营。

06C90清计数后，用EEF68/SWI0C的填充8字模式清G+604..+623，再用EEF6C/SWI0B的32位填充1字清G+624..+627，合计9个链头。没有清64节点存储，旧内容靠计数和新链头失效。06C78还先清G+0/+1/+2再调用06C90，不是每次重置都清所有全局控制字节。

## 登记前倒计数与状态转存的路径差异

06E90(A)与06F50(A,flags)最开始都取u8[A+20]：低7位非零时减1，并保留80位。之后才检查描述指针。

- D==NULL：直接返回，不做A+18→A+1C的状态转存。
- 首描述+3/+8均0：不登记，但A+1C=A+18，A+18清0。
- 正常登记完或因容量满跳过/截断：同样转存再清A+18。

因此“没有登记新节点”不代表状态副作用都一样。状态转存以登记调用为周期，不能在未核对上层调度前直接命名成每显示帧历史。

## 06E90与06F50的偏移变换

06E90直接计算node.x=P.x+s16(D+10)、node.y=P.y+s16(D+12)。06F50先将flags截u8：bit0决定X偏移取反，bit1决定Y偏移取反；宽高不翻转、不交换。其他flag位在这个函数中不参与几何计算。

本轮只确认坐标构建与尺寸复制，具体包含边界及宽高如何参与相交仍待后续配对函数证实，不把它先改写成地形查询的半开包含公式。

## 实体池入口12074的选择

12074遍历实体链，u8[E+A]没有04位时不登记组件。开启时A=E+74：

| E+A标志 | 调用 |
|---|---|
| 02位为0 | 06E90，无偏移镜像 |
| 02位非0、40位为0 | 06F50，flags=(E+A&30)>>4 |
| 02位和40位都非0 | 07058，并额外传E+24字节 |

第三条变换路径本轮不展开。12074本身没有调用实体更新回调，不能把它与另一个12034登记动态地形矩形的入口混为一谈；它们使用不同实体标志、不同描述布局和不同全局表。

## 三份描述样本证明几何不等于生效

以下均为直接ROM读取，不是游戏观测：

| 描述 | k/s | +3 / +8 | dx/dy | 宽×高 | 首项登记筛选 |
|---|---|---|---|---|---|
| 083347D4 | 1/0 | 0/1 | -1/-14像素 | 16×30像素 | 通过 |
| 08334804 | 1/0 | 0/1 | -2/-10像素 | 26×22像素 | 通过 |
| 08334864 | 1/0 | 0/0 | -1/-14像素 | 16×30像素 | 跳过 |

08334864被375C4的E+18C&43覆盖路径选用：虽然几何与默认项相同，登记会跳过，并转存状态。这里可以确认组件在该筛选下不贡献新节点；不能因此推导地形运动范围也失效，后者仍来自E+D8。

默认组件16×30与默认地形14×30也确有宽度差，另一组26×22与地形28×22相差相反。不能用一个统一矩形取代两套数据。
