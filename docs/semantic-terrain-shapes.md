# 地形形状的标量公式与方向查询约定

日期：2026-10-29。深化第19个地图/地形研究单元，不增加模块计数。只读原ROM和已有汇编，保存[48项分派指针与完整首表公式](semantic-data/terrain-shape-evidence.json)。基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。没有模拟器运行或正式代码修改。

## 查询前提与单位

地形查询先从RAM网格取得tileId，再查u16属性，低4位为shape。坐标每256单位为1像素，单格0x1000单位即16像素。本报告函数局部参数u、v限定0..0xFFF；因此对它们算术右移1/2等价于非负整数除2/4向下取整。

0901C/090D4/09190/09240/0930C等所读路径都先处理shape=0及属性8000的跳过条件；shape=1有整格跨越的内联分支。不能从这些路径把8000直接命名为“单向平台”或给全部属性位赋游戏含义。

## 08312BCC：完整16项公式

定义H(u)为阈值。对编号2..D，返回函数统一为：v<H(u)时返回~v，否则0。0/1/E/F使用两个简短公共助手。

| shape | Thumb目标去低位后的函数 | H(u)或直接返回 |
|---|---|---|
| 0 | 09B04 | 0 |
| 1 | 09B08 | ~v |
| 2 | 09C74 | u>>1 |
| 3 | 09C88 | 0800+(u>>1) |
| 4 | 09CA0 | u>>2 |
| 5 | 09CB4 | 0400+(u>>2) |
| 6 | 09CCC | 0800+(u>>2) |
| 7 | 09CE4 | 0C00+(u>>2) |
| 8 | 09CFC | 1000-(u>>1) |
| 9 | 09D18 | 1000-(u>>1) |
| A | 09D34 | 1000-(u>>2) |
| B | 09D50 | 0C00-(u>>2) |
| C | 09D6C | 0800-(u>>2) |
| D | 09D88 | 0400-(u>>2) |
| E | 09B04 | 0 |
| F | 09B08 | ~v |

表中编号、常量和地址均十六进制。不能将H除256后粗化成整数像素再判断：边界比较使用完整定点低12位。

shape8与shape9的09CFC..09D18及09D18..09D34两段28B机器码完全相同。这里保留重复，不按编号对称性把9的常量“修成”另一个值，也不以此判定原游戏存在缺陷。

## ~v不是-v

ARM的mvns对应32位取反，局部v域中等价于-(v+1)。v=0也返回-1个定点单位，即-1/256像素，而不是0。这一最小单位决定相邻格的包含边界，不能在语义还原时删掉。

例：shape2、u=0800，H=0400。v=03FF时命中，返回-0400；v=0400时不命中，返回0。比较是严格小于，不能改为小于等于。

在0901C调用中：u=x&FFF，v=(~y)&FFF，即v=FFF-(y&FFF)。若首表命中，y-=~v等价于把y移到下一16像素格起点。由此可见这张表的返回值不是单独的“是否碰撞”布尔值；阈值先决定当前点是否命中，补码返回再支持跨格搜索。

在上述参数转换下，shape2命中区域满足localY>=1000-(localX>>1)；shape8/9满足localY>=localX>>1。这只是当前方向路径对应的几何条件，不把所有方向的参数u/v都认作localX/localY。

## 三张表按方向提供不同响应

| 响应表 | 已读使用者 | 实际传参及更新 |
|---|---|---|
| 08312BCC | 0901C | u=x&FFF、v=(~y)&FFF，y-=response，正Y跨格 |
| 08312C0C | 090D4、09190 | u=y&FFF、v=x&FFF，x+=response，负X调整 |
| 08312C4C | 09240、0930C | u=y&FFF、v=(~x)&FFF，x-=response，正X调整 |

后两张16项的全部目标指针也已保存，但本轮没有把它们全部宣称解码完成。代表函数说明它们不只是首表的复制：

- 09DA4：u>07FF时直接返回~v；否则算q=v-1000+2*u，q>0返回-q，否则0。
- 09DD4：u<=07FF返回0；否则算q=v-1000+2*(u-0800)，q>0返回-q，否则0。
- 09E08：u>03FF时返回~v；否则算q=v-1000+4*u，q>0返回-q，否则0。

这些是先按u分段再返回位移量的接口；不能只根据表中斜率外观，把它们都还原成返回bool的斜面判断。其他方向表的完整公式留待继续逐函数展开。

## 跨格上限与返回值不能统一

这些查询每次在16像素格内处理形状，必要时跨到相邻格继续。已读函数均用计数<=15控制继续尝试，最多16轮；耗尽返回值因方向不同：

| 查询 | 正常结果用途 | 耗尽返回 |
|---|---|---|
| 0901C | 正Y方向修正差值 | -1 |
| 09190 | 负X方向修正差值 | +1 |
| 0930C | 正X方向修正差值 | -1 |
| 090D4 | 负X查询后再经0A1B8处理额外矩形对象 | +1 |
| 09240 | 正X查询后再经0A25C处理额外矩形对象 | -1 |

±1仍是机器整数，不能因其很小就随意当成像素值，也不能将这组函数统称“失败都返回-1”。090D4/09240还有额外动态矩形对象处理，与仅查静态格的09190/0930C不完全等价。

0A1B8以02001000附近的矩形列表对候选点再做包含测试，命中时将x推到矩形左边外1个单位并重新扫描。本轮只确认该方向的附加路径；完整矩形生成、表长度和其他方向规则仍待研究。

## 边界与后续

- 当前格形状响应可能为0，即此方向不需要调整，不意味着该tile所有属性都为空。
- shapeE/F与0/1共享首表助手，不代表它们在其他高位属性、其他查询或事件中完全等价。
- 低12位、严格比较、补码的+1和跨格返回约定都需要精确保留，不能以视觉近似替代机器语义。
- 下一步追属性表/RAM网格的加载和修改来源，再补齐另两方向表及动态矩形对象生成；保持后台提取独立运行。
