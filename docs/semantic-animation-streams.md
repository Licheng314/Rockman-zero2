# 动画记录解释器与激活流程等待条件

2026-10-29 只读语义轮。解释器04B9C、设置器04B28/04B3C、Entity_SetScript(127E4)、128D4与激活对象的控制流均读取本地源码/原ROM，未改变匹配或集成产物。

## 控制块与实体字段对应

128D4把entity+0x6C交给04B9C；其8B控制块布局直接映射为：

| 控制块偏移 | 实体偏移 | 已确认用途 |
|---|---|---|
| +0 u32 | +0x6C | 由序列ID索引的记录流指针表 |
| +4 u8 | +0x70 | 动画序列ID |
| +5 u8 | +0x71 | 记录索引，参与地址计算时按signed8读取 |
| +6 u8 | +0x72 | 当前记录剩余调用计数，部分条件按signed8读取 |
| +7 u8 | +0x73 | 接近控制标记的状态，包含结束值3和循环相关值4 |

因此E8F3C对+71>3和+72<=1的比较是动画进度条件，不是B组槽位数上限检查。E8F84对+73==3的比较是动画结束边界条件。

## 两字节记录格式

流中每项2B：[value, durationOrControl]。普通项的value是后续显示记录编号：128D4按index*2读取首字节，写入渲染块entity+0x34+0x1A。普通持续时间来自第二字节。

控制项：第二字节0xFF（signed -1）表示停在前一普通记录；第二字节0xFE（signed -2）使用首字节作为新的记录索引，即跳转/循环。不能把每个负duration都认为是同一种控制指令；04B9C对FF/FE有明确分支。

既有src/Animation_Setup.c中的Entry含4个字节，是为了在首记录的两个字节之外读取下一个记录的duration（unk3）。这不证明记录步长是4。运行时04B9C和128D4都用index*2，本报告的流记录步长为2；本轮不改动已匹配C。

## 设置、推进和状态字节

04B28(control,table)：写表、id=0、index=0、timer=(table[0][1]+1)的低8位、status=0。

04B3C / Animation_Setup(control,id)：写序列id、index=0、timer=firstDuration+1。读取下一项第二字节的有符号值，若为负才设置边界状态：

- timer按signed8等于2 → status=2。
- timer按signed8等于1 → 下一项为FF则status=3，否则status=4。
- 其它 → status=1。
- 下一项第二字节非负 → status=0。

04B9C每次先对timer做8位减1。减后signed8不等于0时不推进索引；status原本非0时，timer=2写status2，timer=1根据下一记录第二字节是否FF选择3或4。status=0时保持状态不变。

减后timer等于0时先把索引加1。若新项为FF：还原之前索引、timer=1、status=3并返回。因此终止后重复调用会保持最后普通显示记录，而不是走到FF项显示首字节。

若新项为FE：索引跳到该项首字节指定的位置，status先置0；再读取跳转目标普通项的duration。没有普遍的递归跳转解释循环，不能假定连续多条控制项会自动展开。

装入新项duration后，预读下一项第二字节，若为负则按duration=2/1/其它设置状态2、3/4或1。最后把预读时临时递增的index减回当前记录。数据边界、合法索引、duration非0等由输入流约定承担，解释器不做通用长度检查。

## 动画选择器与图形资源路径

Entity_SetScript的16位参数高8位选bank、低8位选sequence。若bank改变，按实体标志entity[0xB]&4选择不同指针表：置位路径084C9800，未置位路径0842E800；并更新entity+0x1E的bank缓存。设置器末尾总会调用04B3C，即使bank相同也会重置该sequence，不能将其改成“同bank就直接return”。

128D4先推进控制块，取当前显示记录，再在特定图形标志条件下更新图块/调色板等缓存。entity+0x73的结束判断来自推进器，不能直接用是否发生了图块上传替代。

## B组激活的实际回调链

DBBFC创建界面对象类型3、subtype=1；DB954创建类型2、subtype=2。共同主表0834B8B4按类型选择生命周期表，初始化→更新→退出由对象+0xC状态和+0x14回调控制。

| 类型/子类 | 初始化 | 更新 | 结束处理分派 |
|---|---|---|---|
| 3/1 | DBA14 | DBB00 | DBB50，再按subtype选DBB88 |
| 2/2 | DB5DC | DB78C | DB7DC，再按subtype选DB86C |

初始化分派DB9C0/DB538、更新分派DBA64/DB62C以及退出分派DBB50/DB7DC有各自表；表项数量需按子类型和相邻表边界确定，不能多读一个指针就当作本表第三/第四个有效子类。

DBA14先12580初始化，再设置script 0x9A04；DB5DC设置0x440C。12580清entity[0xB]中掩码0x04对应位等图形标志，所以这两条初始化路径采用0842E800普通bank表。

DBB00和DB78C检查所属context[0]<=1且动画status!=3时继续更新128D4，否则切换到结束处理；它们都不从+71/+72读取槽容量。控制器E8F3C与对象更新间的执行顺序尚未动态核对，不把等待调用数直接换算成屏幕帧数。

## 原ROM脚本数据互证

脚本0x9A04：bank表084327D8、记录流084327FC。

```text
index 0..7: [04,04] [05,04] [06,04] [07,04]
            [08,04] [09,04] [0A,04] [0B,04]
index 8:    [00,FF]
```

E8F3C等待signed8(index)>3且signed8(timer)<=1，故它在第一段动画中后段、某记录接近结束时允许创建第二段对象。不能把index>3解释成“至少拥有4个槽”，也不能把timer<=1解释成“B槽尚未满”。

脚本0x440C：bank表084309D8、记录流08430A70。

```text
index 0..6: [12,04] [11,04] [10,04] [0F,04]
            [0E,04] [0D,04] [0C,04]
index 7:    [00,FF]
```

E8F84等待status3，然后执行37A9C/312D0增加B组、D5790压缩项目列表。第二段脚本的FF与该状态等待相互印证。槽数<2的正式检查只在312D0已证实；所读激活控制器和动画回调中未找到等价的B组容量前置检查。上游可能另有项目获得/菜单可选性约束，本轮不作不存在的全程序证明。
