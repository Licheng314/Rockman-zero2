## 预处理在暂停计数判断之前

06CD4先调用0794C，再读u8[G+2]。G+2非零时减1并直接返回，不执行当次14项配对；值为1的本次也仍跳过，下一次才恢复。它不是完全无副作用的碰撞暂停，因为0794C已经执行。

G+2为0时，清三个32位字G+628/+62C/+630，再顺序调用14项配对。暂停分支不会清这三字；它们的后续用途留待命中处理证实。此函数没有重置登记计数G+3或9链头，登记表重置仍由06C90负责。

## 0794C的按第二键预处理

取u8[G+1]的低3位。第s位为1时，遍历bucket(1,s)整条链，读取节点所属组件A：

```text
若s16[A+30] != 0：u16[A+30]=0；u32[A+18] |= 0x201
否则：u32[A+18] |= 0x200
```

不要求描述+3非零，不重新计算相交；是对选定桶的预处理。即使本次G+2将阻止几何配对，它仍可能清零这个16位数值并置状态。这里暂不把它直接命名成全体伤害/死亡，需继续确认A+30和状态位的消费。

同一组件有多个登记节点时没有去重；首次节点可清零A+30，后续节点按已清零值再OR状态，但既有201中的01位不会因此被清除。

## 双链遍历与同组件排除

两个遍历器都按来源链逐项，在每项内从目标链头开始遍历。空链直接返回；同一组件指针（nodeA+8==nodeB+8）跳过，不以描述指针、节点指针、id或组件owner字段判等。

所以同一组件的多描述不会相互处理；两个不同组件即使指向同一owner，也不由这一层排除。相交处理后继续读取目标next，目标结束后继续来源next，没有找到首项就退出或由遍历器自身删除节点。

来源节点的X/Y/宽/高在开始一轮内层循环时缓存；目标几何每对读取。next在处理调用返回后读取，不预先复制全部候选对。以下遍历顺序理解以处理器不改链结构为前提，不额外声称运行时链表绝对不可变。

## X/Y为中心参考、宽高为完整尺寸

先前登记器只确认了位置与尺寸复制，本轮相交公式进一步确证它们按中心参考和完整尺寸使用：

```text
Sw = u16(A.width) + u16(B.width)
Sh = u16(A.height) + u16(B.height)
acceptX = u32(A.x-B.x+(Sw>>1)) < Sw
acceptY = u32(A.y-B.y+(Sh>>1)) < Sh
```

两轴都成立才调用后续处理。先求尺寸和再右移，不是各自宽度先除二再相加；两个奇数宽度时这两种写法可能不同。Sw/Sh为0时该轴必不成立；单个节点的某一尺寸为0则不一定使尺寸和为0，代码没有统一逐节点拒绝零尺寸。

在坐标减法不溢出的通常域：

```text
-floor(Sw/2) <= A.x-B.x < ceil(Sw/2)
-floor(Sh/2) <= A.y-B.y < ceil(Sh/2)
```

### 负边包含、正边排除

尺寸和为偶数时，相对距离的负边界包含等号、正边界排除等号。假定Y轴已通过，两宽均100（各1像素），Sw=200：dx=-100通过，dx=+100不通过。交换参数会反转dx，所以这个边界候选谓词并非对称，不能替换成abs(dx)<Sw/2或另加一套“仅接触边缘不算相交”规则。

尺寸和为奇数5（单位为1/256像素）时，dx=-2和+2均通过，+3不通过。这是机器整数推导例子，未执行游戏。常见整像素数据可能让部分奇数情况不出现，但还原不能擅自改变泛型输入下的取整。

这是进入处理器的几何候选，不等同最终伤害/接触成立。07AAC入口仍可因全局80位、来源描述+2等条件退出；07D40也有额外状态范围检查。后续逻辑会继续影响结果，不能根据遍历调用次数统计实际命中数。

## 先登记顺序与有序处理的合成

登记器对每个桶头插，故正常情况下桶内后登记节点先遍历。调度又固定先处理k=2目标，再处理k=1目标，且每组s顺序如上。几何边界也依参数方向，三者共同决定后续处理观察到的状态顺序。
