# 双组槽位记录与状态快照（0x080311CC–0x080312EC）

## 已确认的记录布局

实体基址 +0x1FC 处有一个至少20字节的记录。证据是 sub_08031208 复制20字节，以及三个公开包装器均将实体指针加0x1FC后转交给槽位助手。

| 记录内偏移 | 已验证行为 | 证据 |
|---|---|---|
| +0x07 起 | 依 id>>3 选择标志字节，使用 id&7 选位 | sub_08031294 |
| +0x08 | A组已用数量，上限2 | sub_08031294；sub_0803126C读取 |
| +0x09 | B组已用数量，上限2 | sub_080312D0；sub_0803126C读取 |
| +0x0A、+0x0B | A组槽位单字节负载，添加时清零 | sub_08031294 |
| +0x0C、+0x0D | B组槽位单字节负载，添加时清零 | sub_080312D0 |

不能据此断言所有id有效：若id>>3大于0，标志访问将进入后续字段。真实id取值范围尚须继续追踪调用者；本轮C候选保留原地址表达式，没有新增未经证实的边界钳位。

ROM 0x083359A4的前两字节是02 02。sub_0803133C按这两个容量分组，并在相应已用数量大于1时对槽位负载降序选择排序。sub_080312EC把1基逻辑序号映射到固定容量布局的物理槽号；容量表与数量字节的用途互证。该映射助手本轮仅分析，未C匹配。

## 快照流水线

sub_080311CC依次调用以下助手。目标是一个至少0xAC（172）字节的快照缓冲区。

| sub_08031254 | 0x1E4 | 0x04 | 24 | C完整匹配并集成，函数24B |

这些区间连续覆盖实体[0x1E0,0x28C)和目标[0,0xAC)，但编排器并非按目标地址递增顺序调用。0x080EF3F0实现对齐字复制加尾部字节复制并返回目标指针，具有memcpy语义；不能据此承诺重叠缓冲区的memmove语义。

三个已匹配复制函数用定长u32结构体赋值表达，编译器自行生成LDMIA/STMIA；没有用手写汇编或原ROM字节冒充C还原。对齐要求与原LDM/STM访问一致。
