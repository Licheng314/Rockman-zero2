# 恢复调度、控制状态与全局模式门控

2026-10-29 只读语义研究。与semantic-recovery-queues.md衔接。未触碰提取器、正式源码、构建清单和自动更新文档。本轮的静态分析不提供真实帧率证明。

## 恢复调用位于上下文状态4

原ROM 0x0835E408起的指针表中：

| 索引 | Thumb目标 | 已读行为 |
|---|---|---|
| 0 | 080E3F49 | 未在本轮展开 |
| 1 | 080E405D | 未在本轮展开 |
| 2 | 080E40DD | 未在本轮展开 |
| 3 | 080E4181 | 多子系统初始化及标志设置 |
| 4 | 080E4391 | 常规更新路径，包含E5AF4恢复调度 |
| 5 | 080E4925 | 0x20起倒计数每次减2，修改3个显示相关字节，归零切换状态 |
| 6 | 080E4A5D | 本轮未完整展开 |

080E3DC8读取context[1]，索引此表并经EF118调用。这说明E4390只在这个二级状态索引4时被该分派器选择。E3DC8自身的Thumb指针又位于ROM 0x0835E3B4，其更外层调用周期尚待确认。

不能把恢复概括为“整个游戏每4帧执行”：现有证据只能证明到达E5AF4的计数每4次调用触发一次；有模式状态和早退条件。

## E4390内部：实体更新与恢复并不共享所有门控

入口读取0x0202E144字节到保存寄存器，作为本轮模式快照。

另构造布尔pending：context+0x1EE4半字非0，或（context+0x7254指针非0且E180计数非0），或0x0202E134字节非0。pending及E144非0会影响149F4入参及若干更新分支。

关键路径：

- 先调用149F4(pending || E144非0)。若该函数返回非0，调用E0E64(context,0x700)后跳到E4906返回，不经过恢复调度。
- 否则若pending非0，跳到E460C，只调用06C90，接着仍到E4610恢复调度。
- pending为0时，执行较完整的对象更新流程。E144非0会跳过其中多组12034/12004/12074调用，但仍可能抵达E4610。
- E4610调用E5AF4(context)，随后06CD4，再处理输入/菜单相关门控。

因此“实体暂不更新”不必然意味着恢复计数器暂停；而模式切换早退确实能跳过当次恢复。此区分是C重写时必须保留的控制流语义。

## 0x0202E140：更广泛的执行模式，不是专用恢复开关

直接写入证据：

- 11F94清零一组全局状态，包含E140，伴随调用12D18。
- E4180初始化时调用11F94；context+0x7254为NULL的分支随后将E140置1。
- 原ROM E1EA0附近也调用11F94后将E140置1；本轮仅核对指令窗口，未建立所在完整函数的前置条件。

消费证据：

- 39FF4的某条接触效果路径：E140非0直接调用22FEC，否则给E180加4。
- AE1E8：E140非0直接返回NULL，跳过后续对象分配。
- 1E11C：E140非0的早期路径返回0，跳过后续反馈对象处理。
- 1E56C、1E64C：E140参与另一组复制/初始化路径选择。
- 355C8等一系列碰撞相关函数也读取它。

可称为“影响对象/效果及即时处理的全局模式”，不能只凭恢复分支命名为fastHeal。是否为演示、回放、特殊场景或不同执行模式，仍需更外层上下文互证。

## 0x0202EC30+8 的bit0x10：由失效条件引发的控制状态

14DE8读取controller+0x20实体指针；controller首半字为0时直接返回0。实体非NULL时，若(entity+0x8C)字的bit0x200置位，或signed16(entity+0xA4)==0，则：

```text
flags = load16(0x0202EC30+8)
flags = (flags & 0xFFFE) | 0x10
store16(0x0202EC30+8, flags)
```

这既置bit0x10，又清bit0，不能只保留OR操作。

随后，当bit0为0且bit0x10为1时，14DE8还设置030032E0字节bit0x80，检查已有控制流指针，并视情况调用1B454为控制块+0x10设置后续指针。1B454把同一指针写入+8和+0xC，设置全局+0x12半字的bit0并清另一个计时半字。它是控制流程安装操作的证据，尚不擅自命名为某种死亡画面。

1492C初始化将全局+8半字整体清0，故这是一个已确认的清除来源；尚未穷举所有中途清除路径。

对恢复的影响由E5AF4给出：bit0x10置位会清E180并跳过E18C处理，但E18C原值保留；E150处理在标志检查之前。它与“生命值归零后禁止继续恢复”的解释相容，但不能扩大为所有资源及所有队列都被清空。

## entity+0xA4的补充证据

- 37628：实体状态bit0x200或当前值==0时，构造特殊状态结果；与14DE8的失效条件一致。
- E4390后段：进入某输入/菜单路径前，同时排除状态bit0x200及当前值==0。
- 14D3C在特定目标/全局标志条件下，将目标+0xA4的无符号16位数改为(value+1)>>1，证明该值也存在减少路径；该路径作用于controller+0x30指向的对象，不直接假定一定是玩家或常规伤害。

以上加强生命值/可存活数值的推断，尚缺“特定攻击伤害扣减”和游戏画面互证；正式字段名仍不修改。

## 效果调用1E6AC的过滤规则

1E6AC将入参截为u16。若E140非0且ID为7、8、9或12，则返回0xFFFF而不调用032EC；其余调用032EC并返回低16位。规则来自(u16)(id-7)<=2或(s16)id==12。

032EC使用ROM 0x08100A24起的8字节条目表及全局02000019作选择，并可调用EDB3C。其结构与声音请求吻合，但本轮尚未追完声音驱动；报告使用“效果/声音候选”而不把所有编号都当确定音效。
