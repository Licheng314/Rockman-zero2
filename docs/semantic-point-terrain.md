日期：2026-10-29。深化第19个地图/地形研究单元，不增加模块计数。只读汇编与原ROM，保存[完整点形状表及边界样本](semantic-data/point-terrain-evidence.json)。基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 08312B8C完整16项

参数u/v在本表的普通调用中为x/y的格内低12位，范围0..FFF。每256单位为1像素。对shape2..D定义表面阈值T(u)，助手返回：

```text
response = -max(v - T(u), 0)
```

严格v>T才非零，等于表面时返回0。这个返回量是形状助手的结果；08CFC/08D80等公共点查询用它决定是否返回完整属性，并不是把该位移量直接当作属性返回给调用者。

| shape | 函数（去Thumb位） | T(u)或直接返回 |
|---|---|---|
| 0 | 09B04 | 0 |
| 1 | 09B08 | ~v |
| 2 | 09B0C | 1000-(u>>1) |
| 3 | 09B2C | 0800-(u>>1) |
| 4 | 09B4C | 1000-(u>>2) |
| 5 | 09B6C | 0C00-(u>>2) |
| 6 | 09B8C | 0800-(u>>2) |
| 7 | 09BAC | 0400-(u>>2) |
| 8 | 09BCC | u>>1 |
| 9 | 09BE0 | 0800+(u>>1) |
| A | 09C00 | u>>2 |
| B | 09C14 | 0400+(u>>2) |
| C | 09C34 | 0800+(u>>2) |
| D | 09C54 | 0C00+(u>>2) |
| E | 09B08 | ~v |
| F | 09B08 | ~v |

表中地址、编号和常量均十六进制。0/1/E/F的“直接返回”不是阈值公式；~v为-(v+1)，v=0也返回-1个定点单位。

## 与08312BCC向下跨格表的三个关键差异

上轮[地形形状报告](semantic-terrain-shapes.md)的08312BCC不能直接替换本表。它常接收互补坐标v=(~worldY)&FFF，并用~v把搜索推进到格边，而本表接收localY并返回点到阈值的有符号量。

1. 普通斜面在表面处的响应不同。例如shape2、u=0800、localY=0C00：点助手返回0；向下搜索用v=03FF得到-0400，支持跨到下一格。若把两函数统一成相同的<=或<条件，会丢失一单位边界差异。
2. 点表shape9阈值为0800+(u>>1)，与shape8不同；跨格表shape8/9的机器码却完全相同。举u=0800、localY=0800，点表9返回0，而向下跨格表9非零。此差异有原始指令证据，不按编号对称性改写；其设计用途仍需调用者与实际场景解释。
3. shapeE在点表与1/F共享~v助手，但在跨格表与0共享返回0助手。因此“这个格在任何查询都属于同一种实心区域”不是可从低4位直接推出的结论。

这些是接口差别，不直接判为游戏漏洞。静态地形属性同时被检测、方向修正和事件逻辑使用，必须保留调用语境。

## 公共查询接口的不同契约

| 函数 | 查询内容 | 坐标保护/额外对象 |
|---|---|---|
| 08354 | 直接返回当前格完整u16属性，不测试斜面内点 | 有全局格坐标范围检查；越界返回0E01；不据此保证实际地图范围 |
| 08D80 | 根据点形状响应决定返回完整属性或0 | 本函数无统一坐标范围检查；没有动态矩形补查 |
| 08CFC | 先测试静态点形状；未命中再调09FE4动态矩形 | 有全局格坐标检查；越界0E01；动态返回还可能写02000020 |

08354读取的是RAM网格的属性映射，不是上轮069C0按ROM布局返回的属性低字节；也不是0894C按240×160屏幕区域返回的分类。三个层次的输入量纲、返回类型与特殊值均需区分。

08D80对shape1直接返回属性；shape0返回0；其余用本表结果决定命中。08CFC则通过本表判断后返回属性或走动态补查。两者都没有在此统一排除属性8000位，不能套用方向查询的过滤规则。

## 高位过滤不是一个共享规则

| 方向/接口 | 属性排除规则 |
|---|---|
| 08DE8、08EA4的负Y搜索 | 排除完整u16值恰好等于800F；不是测试任意8000位 |
| 08F50、0901C的正Y搜索 | 排除所有attribute&8000非0的值 |
| 已读水平方向搜索090D4/09190/09240/0930C | 同样按8000位排除 |
| 08354原始属性、08CFC/08D80点查询 | 不采用上述方向过滤 |

例如8001在负Y搜索中不会仅因高位8000被跳过，但在正Y搜索中会；800F在两个方向中都会被相应规则跳过。这里不把8000先命名为通用“不可碰撞位”或把800F先命名为某种具体平台，后续仍需实体操作与地图事件证据。

08DE8在静态负Y搜索后还调用0A094处理动态矩形，最多跨格尝试耗尽返回+1；08EA4为只查静态格的对应路径，耗尽也为+1。正Y的08F50则补查0A11C，耗尽返回-1。返回值、动态补查和过滤规则应一并保留，而非只还原一张几何图。
