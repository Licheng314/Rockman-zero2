# 候选坐标到碰撞捕获、等待与返程交接

本轮接续[关联信号报告](semantic-parent-associated-signals.md)，把C1交接结果之前的候选、捕获和跟随链补齐，累计仍21研究单元。[原ROM证据](semantic-data/parent-capture-protocol-evidence.json)保存7个函数732条局部可达指令、初始化回调字面池和限定分派项，基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。偏移和状态为十六进制；像素、更新次数及案例数量为十进制。

关键区别：7A60C提交的是候选坐标，不是目标对象指针；真正的对象捕获由79748碰撞回调完成。不能把两者合并为“查找最近对象并立即抓取”。

## 7A60C的候选比较有截断与坐标偏移

令P为父对象、V为提交坐标的类型22关联对象。必须P=V+28非NULL、P+CF非零，且V+D>1，助手才考虑写P+64/+68。

准备保存的点为：X=V.X（朝向10位置位），或V.X-0x800（未置位，即向左8像素）；Y=V.Y+0x500（向下5像素）。只有P+64和P+68同时为0才视为尚无候选，这对字段是坐标哨兵，不是NULL对象指针。

已有候选时，令oldX=u32[P+64]、px=P.X。先算有符号32位差，再取绝对值的低16位：R=abs(s32(wrap32(oldX-px)))&0xFFFF。新对象通过的条件为：

```text
unsigned32(px - V.X + R) <= 2*R
```

比较使用V原始X，不是准备保存的偏移后X；没有比较Y或二维距离；同距也允许覆盖，结果可依提交顺序改变。已有距离超过256像素还会因低16位截断回绕。

一个定向例子：父X=0、旧候选X=+16像素，新对象原始X=-16像素且朝向位未置，会通过同距比较，但保存点变成-24像素，反而比旧候选远。另例：旧候选距父256像素，R截成0，此时新对象只有原始X恰等于父X才通过。两例均执行原ROM核对，不能把本助手简化成精确最近距离排序。

## 主状态1B开放一次候选提交窗口

55854是1B阶段0处理器。首次初始化按全局目标X设置朝向、选择A614和描述0833C228，清P+64/+68，置CF=1、D0=1，推进动画并置F。

后续调用先推进动画，再清CF；若坐标对不全为0，且保存的X距父X在±120像素范围内（含端点），则E加一、F清0。否则调用573FC重新选动作。此处再次检查的是保存后的X，所以它与7A60C比较原始V.X并不完全一致。

这证明存在“开放提交→后续消费”的局部协议；实际对象池遍历如何安排在两次父更新之间，本轮没有执行完整调度，不能据此承诺一定每帧都能收齐所有候选。

## 类型20子类型3安装真实捕获回调

0833FDA8+3*4指向786F0初始化器，0833FDD0+3*4指向792D4更新器。786F0根据父P+64/+68计算方向，设置运动向量；两个已展开参数分支都安装组件回调08079749，组件owner指回本对象S。

初始化先把S+2C清零，并曾用S+B4/B8保存出生坐标；后续捕获回调会覆写这对字段为相对偏移。初始化还用78018创建六个附属对象请求；该工厂把传入子类型低8位加4后写入对象+10，不能把其参数4/5误认为最终对象子类型也为4/5。

本轮只静态核对初始化、方向/时间辅助调用和回调安装，没有执行完整初始向外飞行、地形检查或这些附属对象的初始化。

## 79748：一次碰撞登记双向关系

A为S的组件。回调要求当前u32[A+14]含04位，读取A+C指向的对方组件，再由其+2C取得目标实体V；要求V+9类型为22，且S+2C当前为NULL。满足时：

| 对象 | 写入 |
|---|---|
| S | +2C=V，阶段D=1，等待字节+13=16 |
| S | +B4=V.X-S.X，+B8=V.Y-S.Y，保存有符号相对偏移 |
| V | 阶段D=4、E=0，+B4=S，保存捕获者指针 |

回调没有比较V是否与S拥有同一个父对象，也不在此检查V生命周期或HP；上层碰撞登记是否限制这些组合，本轮不作未验证补全。S+2C已经非NULL时不会覆盖，即使该指针对应对象已在退出，须等其他更新处理这条关系。

此处只建立捕获，不设置C1、不扣CC，也不立即执行A2100。S、V、P的同一B4偏移分别可作相对X、捕获者指针、历史状态字节，结构还原必须按对象类型和阶段区分。

## 16次停留后反向运动，V保持相对位置

792D4在S+D==1时只递减+13，16次调用减至0后把D写2，不改本段X/Y。它不按墙上时间或已证实显示帧计时。

D==2时，每次把+12计数减1，S.X-=S+5C、S.Y-=S+60，使用此前向外运动的同一向量。正常向外计数为N且未发生其他改写时，经过N次反向更新回到起点；本轮测试从构造的捕获位置开始，未用该结论冒充已验证全部向外运动。

V的阶段4处理器7A484每次按S.X+S.B4、S.Y+S.B8更新V位置，因而保持捕获时的相对偏移，而不是把两对象坐标强行重合。阶段入口选动画3701，目标子类型2还调用12CA4参数7。

若父P主状态为9或12，7A484改V阶段为1、E=0、V+B4清零，本次不执行跟随。S的792D4也会对这两个父状态走提前停用路径。两处取消逻辑分别在各自处理器执行，不能把它们说成同一条原子操作。

返程计数减到0且目标V仍存在时，792D4按V子类型写C1，调用A2100，退场V并把P+CC减一，再退场S。已验证的“C1写入不依赖A2100返回”见前述关联信号报告。若V已退出而被清指针，则不走这一交接结果路径。

## 验证与接续

[局部核对脚本](semantic-data/parent-capture-protocol-check.py)通过798组候选坐标/16位截断/门禁例子、16组碰撞捕获边界、32条完整捕获—16次等待—返程—交接周期，以及8组父状态取消例子，共6230次局部调用。返程周期覆盖原计数1/2/16/255、四种运动方向及目标子类型1/2，逐次核对坐标、相对偏移、阶段、CC/C1与交接请求次数。

7A60C、79748、792D4及7A484执行原ROM指令；绘制/动画为空操作，A2100只记录请求并返回0。未执行碰撞配对核心、786F0实际初始化、初始向外飞行、1B完整阶段调度或真实图形。父候选窗口与回调安装本轮属于静态证据，不能把整个场景称为动态游戏验证。

接续可展开初始向外运动的地形/超时条件、78018附属对象职责及完整池遍历顺序，继续追踪父状态15的独立入口和实体资产身份。正式源码、清单和提取程序均未改变。
