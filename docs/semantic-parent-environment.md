# 父状态17的摄像机范围与重映射地形编号查询

本轮接续[九阶段报告](semantic-parent-motion-cycle.md)，解出15188、57A70及其下层0E964/11768，深化已有摄像机和地图研究单元，累计仍21。[原ROM证据](semantic-data/parent-environment-evidence.json)保存4个函数共127条局部可达指令、常量及验证指纹，基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。

## 15188返回超出摄像机矩形的程度

输入r0为摄像机C，r1指向待测坐标(X,Y)。它读取C+0x38/+0x3C的当前显示中心，不读取跟随目标、实体所属对象、震动偏移或地形。令dx=s32(wrap32(C.x-X))、dy=s32(wrap32(C.y-Y))，则返回：

```text
max(0, abs(dx)-0x7800, abs(dy)-0x5000)
```

这相当于点到中心矩形的L∞超出量：矩形半宽120像素、半高80像素，坐标为24.8定点。不是欧氏距离，也不是对象到所属对象/全局目标的距离。两轴先按32位相减，极端数值仍须保留回绕，不能用无限精度坐标相减后再套公式。

父状态55F24竖向阶段及附着飞行A2860/A292C均以0202ED18为摄像机，比较返回值是否严格大于0x4000。对正常坐标差，这等价于：横向离摄像机中心超过184像素，或纵向超过144像素；恰等于边界不触发。

15188只读待测点，不考虑对象自身宽高。在父状态中超出后转阶段3，在附着对象飞行中则走退场，两者使用同一工具但采取不同动作。函数没有直接回答“是否可见”；摄像机震动或精灵部件尺寸也不在本公式内。显示中心与震动的分工见[摄像机报告](semantic-camera.md)。

## 57A70构造采样点并选择专用窗口

令P为父对象，Q=(P.X, P基线Y-0x8000)，即采样Y在基线上方128像素。读取u16[020011D0]&0x7F，恰等于7时调用0E964(Q.x,Q.y)，否则调用11768。最后把结果截成u8返回；仅条件调用方把它当真假用。

这两个下层函数从[RAM地形编号网格](semantic-terrain-loading.md)直接读取u16编号：网格头G=020017E0，行宽w=u16[G]，编号区G+4。没有再通过020011B8属性表取形状/材质，不进行完整碰撞响应。

| 下层查询 | 坐标准入条件 | 实际网格行/列 |
|---|---|---|
| 0E964，选择值7 | unsigned32(Y-0x14000)<=0x1DFFF；普通坐标即0x14000～0x31FFF含端点 | row=s32(wrap32(Y+0x32000))>>12，col=s32(X)>>12 |
| 11768，其他选择值 | unsigned32(X-0x69000)<=0xEFFF，且s32(Y)>0x3BFFF、<=0x45FFF | row=s32(Y)>>12，col=s32(wrap32(X+0x2D000))>>12 |

准入失败返回0；成功读取u16[G+4+2*(row*w+col)]，地址运算按32位机器规则。算术右移12对应16像素格，负数向下取整。0E964没有横向窗口检查；两者都不另查网格高度、行列长度或属性表，不应当作任意输入安全的通用查询API。

换成像素便于理解：选择7允许采样Y为320～不足800像素，采样前又加800像素映射到网格；其余选择允许X为1680～不足1920、Y为960～不足1120像素，取格前把X再加720像素。它们是专用区域的坐标重映射，而不是单纯读取Q所在的未偏移地形格。此处不推断关卡内部为何采用该映射。

## 返回零有三种可能，不能混为“没有碰撞”

57A70可能因不在准入窗口、完整网格编号为0，或非零编号的低8位恰为0而返回零。例如下层返回0x0100时，包装后仍为0；0x0101则返回1。这不是属性位判断或容量检查，保留高8位与原实现行为不同。

既有三个ROM重建初始网格中，非零但低8位为零的格数分别为37、1、42；对应编号集合分别为{256}、{512}、{768,1024,1280}，均为十进制。这只证明截断差异在真实资源编号里存在，不证明父状态运行时必然查询这些格。样本未施加动态补丁，且不是选择7现场RAM截图。

父状态各生成分支实际依据的是这个低字节真假。它们的生成成功数还另受[类型0x23工厂保留槽/满池](semantic-type23-spawn.md)影响；环境查询通过不代表一定分配成功。

## 验证与接续

[局部核对脚本](semantic-data/parent-environment-check.py)执行四个函数的原ROM指令，共2163组摄像机例子、3136组下层窗口/网格例子和588组包装分派例子，合计5887次顶层局部调用。覆盖两轴内外/恰等于阈值、32位坐标回绕、两套窗口端点、多种行宽、选择字段高位被掩去、0x0100/0xAB00等完整编号被截零。

本轮没有函数空操作或返回值注入，57A70实际嵌套调用两个下层查询；RAM坐标和地形编号是构造样本。没有执行真实地图加载、完整游戏场景、父状态全链或生成器，验证范围不延伸到游戏中视觉结果。

接续可追踪573FC如何选择父主状态、此父对象的地图/资源身份，以及专用地形窗口设置来源。正式源码、清单、提取器未修改；既有ROM仅只读散列核验，不构成新构建。
