# B61B4：类型0x23生成、池保留槽与两种运动

本轮继续[父对象状态17](semantic-parent-motion-cycle.md)的生成接口，深化已有研究单元，累计仍21。B61B4创建的类型字节为0x23；它与A20A4创建的类型0x1F附着对象使用不同池入口。本轮证据支持“两个可绘制运动子类型”，尚未据此认定游戏内名称、贴图身份或攻击属性。

[原ROM证据](semantic-data/type23-spawn-evidence.json)记录7个函数399条局部可达指令、常量及生命周期表。基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。下文偏移/带0x数字为十六进制，明确标注的调用次数和案例数为十进制。

## 工厂与保留槽

B61B4的四个有效输入是r0=所属对象、r1=坐标对指针、r2低8位=子类型、r3低8位=初始参数。读取0202F084指向的池，通过06B84分配。若子类型恰为1且池+0xA的有符号16位值恰为1，直接返回NULL，不调用分配器；其他情况尝试分配，空链返回NULL。

该条件是“等于1”，不是小于等于1：正常一致的池里，空池仍由分配器空链返回处理。它使子类型1连续分配最多消耗到余一个空槽，而子类型0可继续消耗最后一个。不能由此推断该槽专供某个具体对象，或把损坏池计数当合法运行状态。

分配成功后，06B84把节点插入活动链、减少空槽数，清对象+0xA半字、+0xC/+0x10整字；工厂再写：

| 字段 | 工厂写入 |
|---|---|
| +0x9 | 类型0x23 |
| +0x25 | 1 |
| +0x14 | 初始化回调080B6225 |
| +0x20半字、+0x22字节 | 0 |
| +0x28 | 所属对象指针 |
| +0x54/+0x58 | 输入坐标副本 |
| +0x10/+0x11 | 子类型及初始参数低8位 |

B61B4不读取调用者传入的第五个栈参数。父状态17阶段5准备的P.Y+0x1000仍是调用现场事实，但不能说它会控制此对象；也没有把该值复制给对象。工厂仅保存+0x28，本轮两种更新处理器都不解引用所属对象，未见父对象死亡触发本对象清理的局部条件。

工厂没有把子类型限定到0/1；更新分派直接用+0x10索引。仅两个已知有效子类型得到解释和生命周期测试，不把其他输入一并声称为受支持。

## 初始化会立即执行第一次更新

类型表08345998的索引0x23指向08346D88，五个生命周期入口为B6225、B633D、B6355、AC5ED、06C29。B6224先写生命周期整字+0xC=1、更新回调B633D，清+0xD，然后按子类型初始化。末尾置+0xA的位0/1并立即调用B633C，由08346D9C分派：子类型0→B6374，子类型1→B6444。

因此初始化不是单纯准备数据：它已经推进一次位置/相位，子类型1的寿命也已从180减到179。后续进度估算必须包含此调用，不能等下一轮调度才算第一步。

## 子类型0：以出生点为中心的扩大椭圆

初始化选动画0x0003，清水平翻转，保存出生坐标到+0x74/+0x78，把u16半径+0x7C置0x200，+0x12清零。令S为080EF450的有符号正弦表，angle为+0x11，每次B6374先推进动画，然后：

- angle=u8(angle+6)，radius=u16(radius+0x180)。
- X=出生X+trunc0(S[(angle+64)&255]*radius/256)。
- Y=出生Y+trunc0(S[angle]*radius/2048)。

trunc0表示向零截断；原指令在负乘积上分别加0xFF或0x7FF后算术右移，不能直接以Python负数整除代替。Y幅度是X的八分之一，半径每次扩大；初始r3参数实际参与周期索引，父状态阶段5的00/20/40/60/80/A0/C0/E0由此成为八个分散初相位。

angle<=128时+0x49的位2/3组合为8，否则为12。本轮只记录绘制字段值，未赋予具体前后层名称。若动画状态+0x73==3，则+0x12加一：第一次重新选动画3，第二次把生命周期置2、回调改B6355；这次不立即隐藏，后续执行B6354才进入生命周期4。这里按动画完成事件计数，没有固定180次期限。

## 子类型1：横向摆动与单向Y积分

初始化选动画0x3703，保存出生X到+0x74，寿命u16(+0x7E)=180。它推进共享0202E188随机种子两次：第一次high&1决定翻转，第二次high低8位写+0x12相位。工厂给的r3值在本子类型不控制此相位。

每次B6444先递减寿命并以16位结果判断。减为零时，先设置生命周期2及回调，再在同次调用B6354，最终直接到4；这次不移动。不为零时，若剩余<=23，以最低位控制显示；若24～63，以低两位是否非零控制显示；大于63时不由该闪烁分支改显示位。

只有+0xD为0才推进动画和位置：phase=u8(phase+4)，X=出生X+4*S[(phase+64)&255]，Y+=trunc0(288*S[phase&127]/256)。Y使用前半周期正弦值并持续累加，和子类型0的“出生Y加位移”不同。+0xD非零只门禁移动，不停止寿命；初始寿命若被外部设0，会下溢成65535，不在此次自动退场。

180指处理器调用数，包含初始化里的第一次调用；没有证明它在完整调度器里总等于180显示帧。

## 退场与父状态生成量

B6354清+0xA的显示位0，生命周期整字+0xC置4，从类型表取最终回调06C29。它本身不归还节点；池空槽增加要等最终回收回调。通用池释放细节见[退场与回收报告](semantic-attachment-retirement.md)，本轮没有重复执行最终释放或完整对象池调度。

父状态17的随机批量请求使用子类型1，因保留槽条件和满池可少于请求数；阶段5固定八次使用子类型0，初相位依次分散。两类创建共享同一个池，因此彼此会影响可用槽。请求失败不会在工厂里排队或重试，重试与否要看调用者；已展开的父阶段按原计数继续。

子类型1实际初始化还消耗共享随机种子。上一轮只记录B61B4请求的局部测试仍有效于调用现场，但不能据此预测后续整个游戏的随机状态；真实调度何时初始化新对象将影响更长链路。
