# 仿射图块定位、裁剪与OAM写入

2026-10-30。深化第15研究单元，并与第21单元的角度差异研究连接，累计仍21单元。[指令与尺寸表证据](semantic-data/affine-piece-render-evidence.json)来自原ROM，SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。范围为03660、038E4、03BF8及关联的槽重置/OAM提交，不声称覆盖全部绘制调度。地址、字段偏移和掩码均为十六进制，像素尺寸与验证数量为十进制。

## 帧记录与整批容量检查

S是实体内E+34绘制记录，输入第二参数Q为绘制上下文。三种回调都用u8[S+1A]索引S+8指向的4字节帧头，u16偏移相对表基址定位8字节图块记录，帧头+2为数量n。

B=03002ED0，B+400处保存当前OAM写指针P。在P处于B到B+400的正常范围时，剩余项数为 `(B+400-P)>>3`。三种回调都先以完整n检查空间；不足直接返回，即使其中大部分图块随后会被裁掉也不尝试。它们对n=0另有明确出口，不进入图块循环。正常结束才把局部写指针提交回B+400；被裁掉的图块不消耗项。

这是仿射回调的行为，不能将普通033C的零数量边界或裁剪参数直接移用过来。

## 合法尺寸表是12项

每片的尺寸索引为 `(piece[1]>>6)*4 | (piece[3]>>6)`，以shape为高两位、size为低两位。083123B8与083123D0各有12个u16/s16半尺寸，单位为1/256像素：

| shape | size=0 | size=1 | size=2 | size=3 |
|---|---|---|---|---|
| 0 | 8×8 | 16×16 | 32×32 | 64×64 |
| 1 | 16×8 | 32×8 | 32×16 | 64×32 |
| 2 | 8×16 | 8×32 | 16×32 | 32×64 |

表内存的是宽/高的一半再乘256。shape=3没有在回调中被拒绝，但会越过已确认的12项表域；不能用“索引有四位”推导出16项都合法。

令Dx=s8[piece+6]*256，Dy=s8[piece+7]*256，半尺寸为Hw/Hh。U=Dx+Hw，V=Dy+Hh表示未变换的局部中心；其中03660还把U/V截为s16，038E4与03BF8没有这一步。极端图块偏移下不能抹掉这个差异。

## 03660读取已准备的矩阵

槽号来自 `(S[13]>>1)&31`，槽起点M=B+32*槽号；A/Bc/C/D分别为s16[M+6/+E/+16/+1E]，这里Bc仅为矩阵第二参数，避免与缓冲基址B混淆。其局部位置为：

```text
rx = ASR8(A*U + C*V)
ry = ASR8(Bc*U + D*V)
X = ASR8(rx + 2*(Dx-U) + worldX - Q[8])
Y = ASR8(ry + 2*(Dy-V) + worldY - Q[C])
```

world来自S+C的位置指针。乘加按32位回绕，再作带符号算术右移。这里03660读的是矩阵参数本身，不能用未量化的浮点正弦替代；矩阵的257除数和镜像规则见 [角度报告](semantic-entity-render-angle.md)。

## 两种缩放回调重新计算图块中心

038E4和03BF8不靠上述槽参数算位置，而是从S+1B的缓存角度、S+18/19镜像标志与原始u16[S+1C/1E]缩放值重新计算。在h/v为0或1的域，定义：

```text
t = (h == v ? angle : -angle) & 255
s = T[t]; c = T[(t+64)&255]
Hu = h ? -U : U
Vv = v ? -V : V
term(a,b,z) = ASR8(wrap32(a*b*z))
rx = ASR8(wrap32(term(c,Hu,scaleX) + term(-s,Vv,scaleY)))
ry = ASR8(wrap32(term(s,Hu,scaleX) + term(c,Vv,scaleY)))
X = ASR8(wrap32(rx + k*(Dx-U) + worldX - Q[8]))
Y = ASR8(wrap32(ry + k*(Dy-V) + worldY - Q[C]))
```

T为080EF450的s16表。038E4的k=2，03BF8的k=1；这两处补偿倍率是它们坐标计算的主要区别，不能把两个回调视为同一函数。对应初始化03554设置S+11低两位为3，035D8清低两位后设为1；03660对应034CC也设置为3。

注意乘积分别先右移8，再相加后右移8。此处使用原缩放字段，不采用生成OAM矩阵时“0或2的幂则除数加1”的修正。故位置与OAM采样矩阵各有自己的量化规则，不是把同一个矩阵正反复用。缩放乘积可能溢出32位，本公式保留回绕，未改成无限精度运算。

## 精确裁剪与输出属性

三种回调的粗裁剪均为：-128<=X<=239、-64<=Y<=159，包含这四个边界。不是按旋转后四角求可见范围，也不是普通033C报告中的横向上界245。

通过后，将X截9位、Y截8位，与S+10属性模板和图块前4字节做按位或，再写目标前4字节。代码不先清除图块记录里所有坐标位，因此格式本身仍有约束，不能重写成对任意原始记录安全的位域替换。attr2先写S+14，再与piece+4相加写回u16；是整体16位加法，仍可能在属性域间进位。

每项只写前6字节，写指针加8，末尾2字节保持原值。这正好保留B+6、B+E、B+16、B+1E等交错分布的仿射参数，不应在补全“空字段”时顺手清零。

## 槽重置和最终提交

E4390的共同前段在04AF4清绘制桶之后，于080E4400将0202E148清0，随后才进入多个1218C/12274对象池排队调用。这证明了一个实际的槽计数重置入口；并不声称所有绘制模式都只经这里。

03044仅将未使用OAM项的attr0写0200隐藏，保留其他半字；然后将B起完整400字节送往07000000，并把写指针重置为B。因此上述末尾半字会随整块缓冲提交，而非由各片回调单独传输。

## 验证方式与接续边界

[离线核对脚本](semantic-data/affine-piece-check.py)使用Capstone解码原ROM指令，在受限Thumb解释器中执行这三个回调，再与独立坐标公式比较。已通过951例：900组固定种子输入、48组精确裁剪边界、3组超容量输入；覆盖空帧、字节数量、缩放溢出、符号截断、属性拼接、写指针和矩阵末尾半字保留。

这是人工内存下的局部指令核对，不是完整GBA模拟、硬件画面验证或游戏运行。038E4和03BF8大量可达指令在自动提取文本中显示为gap，本轮直接依原ROM分支展开，正式汇编保持原样。
