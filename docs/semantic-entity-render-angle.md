# 实体角度：绘制矩阵、缩放与碰撞变换的差别

2026-10-30。连接第15单元的绘制记录和第21单元的实体碰撞，不新增研究单元。[证据](semantic-data/entity-render-angle-evidence.json)保存16个函数、原ROM查表和静态矩阵样例。ROM基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。未运行游戏或修改正式代码。

## 同一个角度字节的两个入口

1218C与12274都遍历对象池，仅在E+A的01可见位成立时处理对象；40位成立时才为S=E+34更新仿射参数。两者以u8[E+24]作为角度，按E+B选择：01未置位调用037B4；01置位且02未置位调用03AB0；01和02都置位调用03DC0。

12074的碰撞登记则以E+A的04位为门禁；04成立后，02未置位用06E90，02成立但40未置位用06F50，02和40成立才以同一个E+24调用07058。因此显示可见性不等于碰撞启用，绘制仿射模式也不单独保证使用特殊碰撞登记。

## 仿射槽与精确矩阵参数

两个绘制遍历入口先把0202E148计数的低5位写入S+13的bits1..5，计数不大于1E时加1；到1F后不再增加。后续对象可能复用槽31，不能声称超额对象自动被拒绝。槽的重置时机不在本轮覆盖。

三个参数函数以 `(S[13]>>1)&31` 选择03002ED0中32字节槽，在槽+6/+E/+16/+1E写四个16位参数。它们复用080EF450的256项s16表T，但不是07058的索引公式。

在初始化产生的h=u8[S+18]、v=u8[S+19]均为0或1的域，令a=u8角度：

```text
t = (h == v ? a : -a) & 255
s = T[t]
c = T[(t+64)&255]
A = sign(h) * trunc0(c*256 / divisorX)
B = sign(h) * trunc0(s*256 / divisorX)
C = sign(v) * trunc0(-s*256 / divisorY)
D = sign(v) * trunc0(c*256 / divisorY)
sign(0)=+1, sign(1)=-1
```

按A、B、C、D顺序写上述四个偏移；写入16位时截断。trunc0为EF150的有符号向零整数除法。这些是传给绘制/OAM的参数，不把它们直接当作世界坐标的前向变换。

原始角度索引表达式为 `(((255*(h^v))^a)+(h^v))&255`；h/v非布尔输入时不能套用上面的简化。每个函数最后把原角度a写S+1B，未把变号后的t写回E+24。

## 默认除数257，缩放值还会有条件加1

037B4固定divisorX=divisorY=101（十进制257），来自080038E0的真实常量。03AB0/03DC0分别读u16[S+1C]和u16[S+1E]，对每个值z先比较：

```text
u32(u32((z-1)|z)+1) == u32(2*z)
```

相等则使用z+1为除数，否则使用z。穷举全部u16域后，该条件恰好对应z=0或z是2的幂。因此0变为1，80变81，100变101，101仍101；不能简单用原字段直接除，也不只是在除数0时修正。

03AB0和03DC0的参数计算与分支协议相同，但安装它们的实体模式会选择不同绘制回调，不据此声称整个绘制行为相同。1260C调用034CC安装08003661回调、选择037B4且把E+24清0；126A0调用03554安装080038E5、选择03AB0；12738调用035D8安装08003BF9、选择03DC0。后两者把两轴缩放都设为100，经过上述调整后也使用257。共同的03430明确将回调参数写到S+4。

## 与碰撞路径无法共用同一个零角度约定

无镜像、默认除数257时，绘制参数的静态结果为：

| 角度字节 | A | B | C | D |
|---|---:|---:|---:|---:|
| 0 | 255 | 0 | 0 | 255 |
| 64 | 0 | 255 | -255 | 0 |
| 128 | -255 | 0 | 0 | -255 |
| 192 | 0 | -255 | 255 | 0 |
| 255 | 254 | -5 | 5 | 254 |

绘制角度0没有交叉项，但默认对角参数是255，并非定点单位256。相较之下，[07058碰撞报告](semantic-entity-collision-rotation.md)的角度255才保持描述中心偏移完全不变；角度0使用索引255/63。两条路径还分别采用向零除法与逐乘积算术右移，舍入也不同。

07058不读取S+1C/1E缩放字段，不缩放宽高；碰撞中心先旋转后镜像。不能把绘制参数或显示缩放直接应用到碰撞框来替代原算法。这里记录的是精确数值差异，未据此认定原程序存在视觉错误。

## 一个真实的角度生产者

43FB4在E+F==0的初始化路径调用1260C和127D0，清E+24为0，安装动画和组件描述，然后使E+F加1。同次调用随后重新读取E+F，若等于1，就执行 `E+24=u8(E+24+18)`；所以正常从状态0进入状态1的这次调用，最终角度已是18，不是0。

状态1每次进入此段都先加18，再检查E+12是否等于8；等于8也先增加角度，随后调用12580退出该仿射绘制模式。12580清E+A的40位，保留02位。127D0仅重置资源缓存并置E+B的04动态资源位，不负责设置E+A的02碰撞模式位。

因此本例证明了具体角度的生产、字节回绕和模式切换；是否在同一个实体上走07058，还须满足12074的04、02、40条件。未追踪完整实体类型及帧调度，不给出每秒转速或角色名称。
