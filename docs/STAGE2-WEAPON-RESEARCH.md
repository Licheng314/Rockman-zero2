# 阶段 2 · 武器与能力配置研究

本批以美版原 ROM（SHA1 `c4d93a58f0f82c526dec8a3fdbda170336303689`）和阶段 1 的普通难度序章站立快照为基线。四武器八个样本均已捕获，其中蓄力锁链枪使用动作重入对照。测试装备、成长值和芯片只写模拟器 RAM。需隔离受击的样本和各自对照使用相同的保护设置。

武器名称经原版画面对照校正。装备编号 2 的空中普通攻击伸出锁链枪，编号 3 则亮出回旋盾。早期测试数据中的 `shield_*` 对应编号 2，`chain_*` 对应编号 3。地址、对象类型和逐次采样以实际观测为准。

## 装备、输入和碰撞字段

| 位置 | 用途与核对范围 |
| --- | --- |
| Zero `+0x210` | 装备可用位候选。开局值 `0x03`，测试锁链枪和回旋盾分别预置 bit 2、bit 3，同时设定测试槽。本批未单独验证菜单解锁门。 |
| Zero `+0x212/+0x213` | 装备槽的武器编号。原版快照为 `0/1`，槽 0 依次设为枪/剑/锁链枪/回旋盾（0/1/2/3）后，普通攻击生成相应对象。 |
| Zero `+0x188/+0x189` | 按槽读取的蓄力计数，由 [0x08037B5C](../asm/sub_08037B5C.s)根据武器编号与槽位匹配后返回。 |
| Zero `+0x222/+0x223/+0x224` | 枪满蓄、剑蓄力和锁链枪蓄力的门控或门槛选择字段。分支分别见 [0x08036D5C](../asm/sub_08036D5C.s)、[0x08036E60](../asm/sub_08036E60.s)、[0x08036F18](../asm/sub_08036F18.s)。剑要求 `+0x223 > 2`，锁链枪在所选普通模式分支要求 `+0x224 != 0`。 |
| Zero `+0x215` | 本批满蓄枪样本中的属性选择字节。原版生成器在枪的对象等级为 2 时带到对象 `+0x12`，较低等级清零。 |
| 武器对象 `+0x09/+0x14/+0x28` | 类型字节、回调和持有者指针。对象身份以池句柄格 `0x0202F070`、类型表 `0x08336060`、类型字节三者为准。 |
| 武器对象 `+0x74/+0xAA/+0xAB` | 碰撞组件基址及其描述符指针、覆盖掩码、伤害字节。`+0xAA` bit 0 决定命中解析是否保留对象的伤害覆盖值，未启用时由描述符装入。随后 [伤害计算 0x080071B8](../asm/sub_080071B8.s)读取组件 `+0x37`，也就是对象 `+0xAB`。描述符是 24 字节，`+3` 是描述符伤害字节。 |

原版默认输入下点按 B（规范化按住位 `0x10`）为普通攻击。蓄力样本从同一快照按住 135 或 145 次更新再松开。帧号从第一次输入开始计。角色更新的地面攻击分派从 `0x08023420` 经表 `0x08333DC4` 进入 `0x08029664`。

## 原版攻击样本

| 样本 | 生成入口与对象 | 描述符及关键时序 |
| --- | --- | --- |
| 枪·普通 | [0x080396EC](../asm/sub_080396EC.s)，类型 1 | 第 1 次出现 `0x08336138`，对象伤害覆盖值 2。 |
| 枪·蓄力 | 同一类型。对象 `+0x11` 记录发射等级 | 开局成长下按住 135 次，第 136 次出现等级 1，描述符 `0x08336198`、覆盖值 6。设 `+0x222=1` 的满蓄样本第 146 次出现等级 2，属性 0 时为 `0x083361C8`、覆盖值 12。 |
| 剑·普通首斩 | [0x0803A7E0](../asm/sub_0803A7E0.s)，类型 3 | 第 3/5/7 次切换到 `0x08336594/0x083365F4/0x08336624`，三段覆盖值均为 8。 |
| 剑·蓄力 | [0x0803C29C](../asm/sub_0803C29C.s) 分配类型 8，回调表 `0x08337D74` | 按住 145 次后松开。成长值为 0 时仅有普通首斩，设为 3 后第 146 次生成 `0x08337DB0`，伤害字节 10。第 152 次切换到 `0x08337DE0`，对象伤害字节读到 `0xFF`，其特殊分支待查。 |
| 锁链枪·普通 | [0x08039DDC](../asm/sub_08039DDC.s)，类型 2 | 第 5 次出现，代表对象使用 `0x08336414`、覆盖值 4。该时刻同池有多个类型 2 对象，不能把全部对象视为相同碰撞体。 |
| 锁链枪·蓄力 | `0x0802A5FC → 0x08036F18 → 0x0802B208`，随后 [0x0802B2B8](../asm/sub_0802B2B8.s) 调用 [0x0803D46C](../asm/sub_0803D46C.s) 生成类型 11，回调表 `0x08338D38` | 按 B 145 次，松键前在 RAM 设置两槽计数为 129、清动作子状态以重入原版释放分支。成长字段 `+0x224=1` 时，第 154 次捕获类型 11 和 `0x08338D6C` 描述符链，链中攻击项 `0x08338D9C` 的伤害字节为 4。第 160、162、168 次切换描述符。相同输入和动作重入设置下 `+0x224=0` 不生成类型 11。长按后直接松键的自然流程仍未复现。 |
| 回旋盾·普通 | [0x0803C778](../asm/sub_0803C778.s)，类型 9 | 第 1 次出现 `0x08338738`。当前掩码未启用伤害覆盖，内存里的 2 不能当作该描述符的伤害，描述符 `+3` 为 0。 |
| 回旋盾·蓄力 | [0x0803CF10](../asm/sub_0803CF10.s)，类型 10 | 按住 135 次，第 136 次出现 `0x08338964`、覆盖字节 `0xFF`。第 144 次切到 `0x083389F4`、覆盖值 12，第 148 次再换到 `0x08338CA4`。 |

枪和普通剑的生成函数由 ROM 回调表交叉确认。枪的 `0x0833456C` 起始项指向 `0x080396EC`，调用入口为 [0x08033960](../asm/sub_08033960.s)。剑的 `0x08334590` 起始项指向 `0x0803A7E0`，上游调用入口为 [0x08033A1C](../asm/sub_08033A1C.s)。

## 两个改动对照

- **枪普通弹的攻击参数。** [初始化 0x0803927C](../asm/sub_0803927C.s)经 `0x08335A74` 按等级、属性和发射子型读伤害表。普通地面样本读取 `0x08335A1C`。仅在模拟器载入的内存副本把该字节 `02 → 05`，原版程序生成的攻击覆盖值是 **2 → 5 → 2**。初始位置、碰撞描述符和覆盖掩码在三次对照中一致，恢复字节后整包 SHA1 恢复。这个对照量的是发射对象参数，敌方实际 HP 差还需下一组测试。
- **剑蓄力使能。** 同一原 ROM、装备、输入和保护条件下，`+0x223=0` 松键只生成普通剑对象，设为 3 才生成类型 8。这个对照验证的是成长门的作用，成长获取路径和磁盘存档仍未确认。

## 属性与满蓄枪 EX

菜单选择经 [0x080E9350](../asm/sub_080E9350.s) 检查场景标志和拥有属性数量，[0x08037C5C](../asm/sub_08037C5C.s) 统计 Zero `+0x211` 的低四个拥有位。[0x080E8BA4](../asm/sub_080E8BA4.s) 用逻辑选择序号查拥有位并在 A 确认时写入 `+0x215`。序章同一快照清除菜单限制位后，拥有掩码 `0x01` 时同一操作维持属性 0。掩码 `0x07` 时，进入属性菜单后右移两次，再按 A，选中属性 2。测试中拥有掩码为 RAM 前置条件。

满蓄枪把 `+0x215` 设为 0、1、2、3 时，松键后枪弹等级均为 2，依次使用描述符 `0x083361C8/0x083361F8/0x08336228/0x08336258`，攻击覆盖值均为 12。序章同一目标的身份为池句柄格 `0x0202F078`、类型 1、更新回调 `0x08066A35`，本次运行地址 `0x030056FC`。在原版目标上，四个属性都会在同一次更新将 HP 从 6 降到 0。通过碰撞登记确认防御描述符是 `0x0833DC74`，其 `+8` 的抗性类别为 1。

为隔离抗性并避免 HP 截断，第二组对照把同一目标初始 HP 固定为 30，并只在模拟器内存中的 ROM 副本将 `0x0833DC7C` 从类别 1 改为 2。依属性 0、1、2、3，原抗性实测扣血为 **12、12、12、12**，类别 2 实测为 **12、9、6、18**，还原字节后复现原结果。与 [0x080071B8](../asm/sub_080071B8.s) 使用 `0x08312AFC` 的倍率一致。这组差异是受控抗性测试，原版序章目标天然使用类别 1。

枪的 EX 选属性 2 的一项。[0x08033960](../asm/sub_08033960.s)在蓄力等级为 2 时，读取 Zero `+0x218` 的 16 位启用掩码，按当前属性查表 `0x08335A8A`。属性 2 对应 `0x0008`，匹配后从发射表 `0x0833456C` 选索引 5，指向 [0x0803E9B8](../asm/sub_0803E9B8.s)。原版快照在属性 2、按 B 145 次后松开时，掩码 0 或 4 生成普通满蓄弹类型 1，掩码 8 生成 EX 类型 14、碰撞描述符 `0x08339E0C`。掩码 8 下只按 70 次仍生成等级 1 弹。目标在 EX 样本中还观测到相隔 8 次更新的连续扣血。

取得门与启用位分开。[场景脚本 0x0801CE5C](../asm/sub_0801CE5C.s) 调用 [奖励判定 0x0801D6D8](../asm/sub_0801D6D8.s)。本项由表索引 7 对应阶段值 `0x0A`、资格旗标编号 `0x49`（`0x0202EBBD` bit 1）和拥有掩码 `0x0008`。全局 `0x0202EBB4` bit 0 清零且该奖励状态进入首次判定时，若资格旗标置位且 Zero `+0x216` 尚未拥有该位，代码写入拥有位并触发文本索引 `0x0125`。直接设置 `+0x218` 的 EX 运行测试与此取得链是两份证据。资格旗标的上游评分生成未在本批动态复现。

## 恢复配置与恢复参数对照

恢复用两个菜单样本。为在序章复现完整菜单，两组在同一快照中清除全局 `0x0202EBB4` bit 1，并预置对应道具和当前生命。后续操作使用游戏原版菜单，不写存档。

- **储量槽。** [菜单可用门 0x080E93CC](../asm/sub_080E93CC.s)同时检查上述标志和拥有槽数。预置一槽 8 点储量、当前 HP 10 后，菜单确认将 HP 加至 16，槽余 2 点。由 [0x080E912C](../asm/sub_080E912C.s)逐点转移。`0x080E919C` 的计时重载只在模拟器内存副本改为 `4 → 2`，实测恢复间隔随之变为 **4 → 2 → 4** 次更新，最终 HP 和剩余储量相同。两版首次加血都在确认后第 2 次更新，原版和恢复版在第 22 次完成，修改版在第 12 次完成。
- **电子精灵 Grandie。** 从[原版文本](semantic-data/item-text.json)和[描述符](semantic-data/item-descriptors.json)对应 item 1、动作码 2。预置已获得、可使用、已成长及菜单配置后，确认消费令 `+0x20A` 清零、`+0x233` bit 1 清零、`+0x23E` bit 1 置位。退出菜单后第 130 次更新，`+0x202` bit 0 置位，基础上限仍为 16，有效上限变 32，当前 HP 从 10 增至 26，与 [0x080D6E78](../asm/sub_080D6E78.s) 的效果吻合。

## 选中字段的存档往返

快照保存入口 [0x080311CC](../asm/sub_080311CC.s)通过 `0x08031208/20/38` 把 Zero `+0x1FC/+0x210/+0x228` 三段复制到快照 `+0x1C/+0x30/+0x48`。[存档调用处 0x080E739E](../asm/stage0_code_080E7358.s)准备快照，随后将 `0x02036B30` 起的 `0x1B4` 字节交给 [写入队列 0x080021A8](../asm/sub_080021A8.s)。[写入状态机 0x08002250](../asm/sub_08002250.s)写入主副本和备份副本。[读取队列 0x080021F0](../asm/sub_080021F0.s)及[读取状态机 0x080023AC](../asm/sub_080023AC.s)读回校验通过的负载，[恢复入口 0x08030E68](../asm/sub_08030E68.s)接收负载 `+0xD4` 的角色快照。

本机对照用内存加载的调用夹具触发这组原版函数。选中字段先写入测试角色，存入模拟卡带槽 0，清零角色字段，再读到另一个缓冲区并调用原版恢复函数。写入和读取状态均为成功。下表各字节在打包、读回、角色恢复三个位置一致。未比较其他字段的语义，整块负载与写入排队时的早期快照存在差异。本机既有存档文件未写入。

| Zero 偏移 | 存档负载偏移 | 已复核字节 |
| --- | --- | --- |
| `+0x202`、`+0x204`、`+0x206` | `+0xF6`、`+0xF8`、`+0xFA` | 翻倍标志 1、拥有槽数 1、储量 8 |
| `+0x215`、`+0x216`、`+0x218` | `+0x109`、`+0x10A`、`+0x10C` | 属性 2、EX 拥有低字节 8、EX 启用低字节 8 |
| `+0x223`、`+0x23E` | `+0x117`、`+0x132` | 剑成长值 3、Grandie 已使用位 2 |

## 阶段验收与复跑入口

| 目标 | 证据 |
| --- | --- |
| 四武器各一个普通和一个蓄力样本 | 八个样本均有原版攻击对象与描述符。蓄力锁链枪使用动作重入夹具，覆盖原版松键判断与生成路径。 |
| 属性选择、应用与命中差异 | 原版菜单确认、满蓄枪四个描述符、同目标原抗性与受控抗性对照。 |
| 有界 EX 样本 | 选一项枪 EX，已实测启用位、属性和蓄力的触发差异，并核对独立的原版取得门及分派。 |
| 生命相关电子精灵与储量槽 | 各一项原版菜单实测，所选存档字段通过模拟卡带往返。 |
| 攻击参数、能力使能、恢复参数 | 枪弹攻击值、剑蓄力门和储量槽间隔均有运行对照。 |

独立复跑八个本机检查脚本通过。正式构建通过逐段终点检查，重建 ROM 的全量 SHA1 仍为 `c4d93a58f0f82c526dec8a3fdbda170336303689`。阶段 2 在这些样本边界内验收。

本机复测脚本和数据位于 `build/stage2`。`probe-weapon-samples.py`、`probe-buster-target.py` 记录攻击与 EX，`verify-buster-parameter.py` 复跑枪弹参数，`verify-chip-menu.py` 与 `verify-element-resistance.py` 复跑属性选择和抗性，`verify-tank-recovery.py`、`verify-elf-menu.py`、`verify-card-roundtrip.py` 复跑恢复与存档。
