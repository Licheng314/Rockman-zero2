# 接触范围构建与属性聚合状态

2026-10-29。深化已有地形/动态矩形研究，累计仍20单元。本轮补齐22064的范围公式、220D8及六个短属性助手，并解析224B4与上层仲裁的接口。[原ROM证据](semantic-data/contact-bounds-flags-evidence.json)保存9个函数的可达分支、常数及区间摘要；基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。没有执行游戏或修改正式源码/提取状态。

地址与字段偏移为十六进制，公式常数用0x前缀。坐标24.8，1单位为1/256像素。以下正常域公式不掩盖32位运算溢出或将原有符号/无符号比较替换成无限精度算术。

## 22064的八参数范围构建

接口暂记为：

```text
22064(P, shape, facing, pad4, pad6, padX, outCenter, outHalf)
```

shape+0/+2/+4/+6均为u16读取，不能改成s16。pad4/pad6/padX为32位输入，函数没有非负校验、饱和或最终范围有效性验证。outCenter和outHalf各写两个32位字。

令a=u16(shape+0)、b=u16(shape+2)、c=u16(shape+4)、d=u16(shape+6)，s在facing非零时为+1，否则-1：

```text
hx = trunc0((a+b+2*padX)/2)
cx = P.x + s*(a+padX-hx)
hy = trunc0((c+pad4+d+pad6)/2)
cy = P.y + c+pad4-hy
```

除二由“逻辑取符号位、加回、算术右移”实现，对通常有符号范围为向零截断。例如-3得到-1，不是直接算术右移的-2；接近溢出边界仍按原指令计算。横向padX使用两次，pad4只跟随+4边缘、pad6只跟随+6边缘，不能误写成上下都加同一个值。

22064只有一个已提取直接调用者20BD8。后者传入输入位置、第一形状、朝向及三个扩张量，输出栈上center/half供动态矩形预筛选，详见[分派报告](semantic-contact-dispatch.md)。它不是从两个历史位置直接构建扫掠盒；运动交叉检查在后续回调中另做。

## 奇数长度保留哪一侧

在长度和扩张非负的通常域，令Sx=a+b+2*padX。Sx为偶数时2*hx=Sx；奇数时2*hx=Sx-1。

| 朝向 | 精确保留的代数边界 | 奇数长度时另一侧 |
|---|---|---|
| s=+1 | cx+hx=P.x+a+padX | cx-hx=P.x-b-padX+1 |
| s=-1 | cx-hx=P.x-a-padX | cx+hx=P.x+b+padX-1 |

纵向同理，cy+hy=P.y+c+pad4始终保留；若Sy=c+pad4+d+pad6为正奇数，则cy-hy=P.y-d-pad6+1。这里是中心/半范围的代数端点，不擅自给消费它的包含测试加减端点。

十进制静态例子：P=(0,0)，shape=(3,2,4,1)，三个pad均0。hx=2、hy=2；facing非零时center=(1,2)，零时center=(-1,2)。对两个方向的水平代数范围分别是[-1,3]与[-3,1]，垂直为[0,4]。若仅a=1、b=0，则hx=0，即使原始两边之和为1也不会向上取整成半宽1；最终是否被矩形预筛选接收还取决于另一矩形及其半宽。

## 220D8不是简单的属性按位或

接口220D8(C,dir,x,y,attribute)。先按32位清除attribute的0x80位：a=attribute&0xFFFFFF7F，没有取低四位。已读1FE4C实际先把08D80返回截为u16，再以dir=2传入采样点；不把所有任意32位输入当成正常属性域。

定义：F=u16[C+8+2*dir]为本方向首属性槽；B=u16[C+0x10+2*dir]为本方向聚合状态。它们不是同一种数据，状态位0x4/0x8也不等于原始shape编号。

按实际执行顺序：

1. a精确等于0xF时调223B0，a精确等于0xE时调223D4；两助手仅F==0时分别B|=4或B|=8。属性0x10F虽低四位为F，也走普通分支，不能只测shape。
2. 其他a无条件B|=2；若(a&0xFEC0)==0，再经223A0无条件B|=1。即使F已有值，这两步也执行。
3. a有8000位时经223F8，仅F==0时B|=8000；a无8000位则无条件B&=7FFF。这不是对所有采样属性的8000位做纯OR归并。
4. a&6000非零时，若B此前尚无6000位，保存(x,y)到共享C+18/+1C；再由22420分别把属性4000和2000位OR到B。这两位的合并不受F==0限制。
5. a有1000位时经22464，仅F==0时B|=1000；没有对应的无位分支自动清1000。
6. 最后若F仍为0，写F=a，并把(x,y)保存到共享C+30/+34。若a也是0，槽仍为0，下次仍可能再次写入坐标；所以严格说是“首次槽为空时写入”，不是无条件冻结第一采样点。

C+18/+1C和C+30/+34都是上下文共享坐标对，不是每方向一对数组；各方向首次命中都可能覆盖同一坐标对。不能把它们按dir扩展成四份坐标。

顺序例子（十六进制属性，初始F=B=0）：先采a=8001，得到F=8001、B=8002；再采a=0001，F保留8001，B变为0003，8000被清除。若反过来先0001再8001，第二次因F非零不能重新设置8000，最终B仍0003。保留首属性和聚合位并不要求一直一致。

## 224B4：选中结果与辅助结果的再次仲裁

1F6AC末尾调用224B4(C,selected,aux)，返回值写C+14，恰好是dir=2的聚合半字。该函数自身读取旧u16[C+14]但不直接写回；不能误读为总是重建全部状态。

令B=旧C+14：

```text
selected == 0：返回0
selected有80位：source=selected；若aux==0先B=0
selected无80位：source=aux
source == 0：直接返回当前B
```

source非零时先清其80位，然后：source精确F→B|=4，精确E→B|=8，其他→B|=2。此处不会像220D8一样再测试FEC0并设置状态1，也不调用首属性槽限制。

之后source有8000则设置B的8000，否则清除；最后按selected（不是source）的1000位设置或清除B的1000，返回u16 B。没有在这里按source重新合并6000位。selected动态标记存在且aux==0时，旧B先清零；source==0的早返回则保留旧B，连1000更新都跳过。

这解释上层为什么同时传selected和aux：某些状态来自选择结果，某些来自辅助结果或旧聚合值；不可写成return selected&mask。仍不凭这些机械位操作给8000/1000/6000指定具体游戏机制名称。
