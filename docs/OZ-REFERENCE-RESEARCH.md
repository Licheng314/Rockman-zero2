### 物理 L/R 与逻辑映射对照

只在模拟器 RAM 把 `P+0x21C` 的四个半字从 `[1,0x200,2,0x100]` 改为 `[1,0x100,2,0x200]`，即交换逻辑冲刺与副武器的 L/R 映射。动态字段保留该映射，下+L得到逻辑副攻击输入，但不触发光柱；下+物理R仍为action2。Select+物理R仍action6、Select+物理L仍action4。

这证明**所测三项特殊组合没有随这份逻辑映射交换**，不是对所有自定义键位或攻击模式的普遍证明。对 Z2 不应照搬物理键硬编码；接入时将“攻击/冲刺/方向/修饰键”的解析与动作控制分开，兼容现有空中冲刺。

### 光柱的一条有限执行链

1. 自然下+物理R后，`0x020389E8` action为2。玩家包装器的此分支向工厂 `0x08811BDC` 传入弹体子类3、索引0..4；工厂复用 projectile 池分配，写 type `0x26`，初始化后挂扩展更新 `0x08811259`。
2. t17实测5个 kind4/type38、work0=3 对象，对应5个槽和各自实例编号。其 `+0x28` 连接 **`0x02038A2C` 代理角色**，不是实际玩家 `0x02037FA0`。日版固定源码中type38为 `PROJECTILE_OMEGA_ZERO`，这里只用名称与行为作结构锚点，不套日版地址。
3. 初始模板 `0x0887A4F8` 是友方受击类（kind1/damage0）；t25出现 `0x0887A498` **攻击类kind0/faction0/damage5/layer1**。不能把初始受击模板误称攻击伤害，也没有据此宣称实扣5HP。
4. t102动作归零，同一5个地址+实例编号对象进入phase3；t103 phase4，t104登记槽全部空。此为正常结束闭环；没有受击、死亡、切图中断或分配失败运行证明。

代码调用点的静态观察与逐次对象采样相互支持，不是CPU逐条执行追踪；输入如何写入action的精确指令仍未定位。工厂还会更新登记和绘制回调；这意味着资源恢复、判定阵营、代理关系不能被移植方案省略。

### 两项旧判断纠正及批次边界

- 第一批待查的 `0x020389E4` 在本批光柱样本中按1..102递增，是本分支动作计时读数，不再称“输入请求码”。特殊攻击也可能保持action0并挂在原动作路径上（前向波、空中散射、落石）；以后不能只扫描非零action来计数技能。

## 面向 Z2 的接入安排

**可分招重建行为，无须先全量反编译 Z3；不直接搬扩展区机器码。** Z3调用地址、代理内存、对象类型、判定及资源格式在Z2均须适配，已有三角剑光的图形转换只能复用部分知识。

| 接入部分 | 需要补齐 | 依赖较少的实施顺序 |
| --- | --- | --- |
| 输入/形态控制 | 逻辑按键与组合优先级、动作独占/退出，和Z2空中冲刺协调 | 先建立仅一招的独立状态和退出路径，不复制所有按键 |
| 弹体、判定、资源 | Z2内分配/登记/回收，友方碰撞及命中保护，所选图块/拼合/配色 | 首选前向单发波，再5发散射、光柱；先验证一个Z2对象再并发扩展 |
| 玩家外观/代理 | OZ动作帧与玩家物理状态同步；确定是否确需代理，不原样搬固定RAM | 只提取首招必要资源，复用Z2玩家移动，不引入完整Boss AI |
| 空中剑气与落石 | 原剑路径附加生成、蓄力/落地退出，资源槽冲突 | 放在基础单发与资源回收可运行后 |
| 双炮连招、跳冲七连斩 | 多段时序、目标身份/追踪、受击/目标消失中断、同目标命中间隔 | 最后；空场突进不能代替七连斩完整证据 |

第一层公共适配比之后再增加一组弹体更费工；摆姿只改表现也不能代表已实现可玩OZ。当前不承诺全部移植工期，尚未测试目标伤害和中断。

下一有限包：选**前向波或光柱中的一招**补一个普通敌人实际扣血及一次明确的中断清理，并只追必要的碰撞/归属回调；新深入函数至多3个。若继续追七连斩，须另包取得可命中目标，不在本包盲扩全招式。公开复跑入口为 `research/oz-skill-probe.py --rom <本机参考ROM>`，需要Pillow/既有核心，不需要capstone。正式Z2源码、改版和ROM均未动，无后台任务或新定时任务。
