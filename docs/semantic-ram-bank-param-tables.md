# 0x0202E590/0x0202E390 成对参数表：写入者定位与角色判定

承接 [图形库切换器 127E4](semantic-script-bank-switch.md)（其尾部消费两表合成
对象帧索引）。本轮全函数级扫描定位写入者并判定两表角色。
证据 = [ram-bank-param-writers.json](semantic-data/ram-bank-param-writers.json)
（41 写入点 / 174 纯读点，全 6375 段扫描）。
原 ROM 基线 SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 扫描方法

全 6375 段（tools/segments.json 函数边界）反汇编；凡 `ldr rX, =E590/E390`
（池值匹配）后 40 条内出现以 rX（或其派生）为基址的 `strh/strb/str` → 写入点。
结果：**41 写入点，174 纯读点**。

## 角色判定：运行时填充的"库→帧基址/参数"映射表

写侧实例（0x080C5748，状态机：e+0xD≤5 跳表分派，0x080C5xxx 群最密集）：

```
E590[i] = 0x300                    ; strh（半字）
E390[i] = 8                        ; strh（该表混用半字/字节写）
r4' = i*16 + 0x27C
→ 读 ROM 描述符 0x08432D00[r4'] 的字段（[+6]>>6 等）
→ 后续计算 ((0x300-值)<<5)+0x400 → bl 0x08002638
```

读侧（127E4 尾部，已解）：

```
e+0x48 低10位 = (u16[0x0202E590 + bank*2] + e[0x20]) & 0x3FF
e+0x49 高4位 = u8[0x0202E390 + bank*2 + e[0x22]]
```

**结论**：两表 = 库资源加载状态机在装载时写入的**每库基址/参数运行时映射**；
127E4 与其余 ~110 处引用方只读。E590 半字（帧基址类，如 0x300）、E390 字节/半字
（参数类，如 8）——与"库→对象帧索引合成"管线自洽。

## 写入者分布

| 区域 | 段 | 写入点 | 特征 |
|---|---|---|---|
| **0x080C2xxx-0x080C8xxx** | sub_080C5748(×4)/C67B8(×4)/C256C/C3400/C5008/C5AF4/C6CFC/C80E4 等 | ~20+ | 库资源加载状态机群（子状态跳表） |
| 0x08011xxx-0x08013xxx | sub_08011260/sub_08013978/sub_08012C04 | 5 | 系统初始化/装载族 |
| 零散 | 0x08040098/0x0805927C/0x0805B674/0x08061D50/0x080AA020/0x080B77E0 等 | ~15 | 各子系统对特定槽位的定点写 |

0x080C 群与 [库切换报告](semantic-script-bank-switch.md) 的三张 ROM 指针表
（0x0842E800 等）属于同一装载子系统——ROM 侧静态表 + EWRAM 侧运行时映射表的
两层设计。
