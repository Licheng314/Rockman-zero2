# 实体碰撞特殊登记：中心旋转与镜像顺序

日期：2026-10-30。继续第21研究单元，不增加全项目模块数。

本报告解释 `08007058` 及入口 `08012074`。证据来自原始ROM的可达指令、常量与完整256项查表，见 [证据](semantic-data/entity-collision-rotation-evidence.json)。数值样例为静态推导，未声称游戏运行观测。原始ROM SHA1为 `c4d93a58f0f82c526dec8a3fdbda170336303689`。

## 调用选择

12074读取实体E的标志E+A：04未置位则跳过登记；04置位而02未置位则调用06E90；02置位而40未置位则调用06F50；02和40都置位则调用07058。后者参数为组件A=E+74、镜像标志 `(u8[E+A]&0x30)>>4`、角度字节 `u8[E+24]`。该字节的生产者尚未追踪，不能据此直接规定绘制角度的游戏含义。

## 精确变换

令P为组件A+8保存的位置指针，D为当前24字节描述。dx=s16[D+10]，dy=s16[D+12]。S为080EF450开始的256项有符号16位表，缩放为256：

```text
angle = u8(angle)
q = S[(0xFF-angle)&0xFF]
c = S[(0x13F-angle)&0xFF]
rx = ASR8(c*dx) + ASR8(q*dy)
ry = ASR8(c*dy) - ASR8(q*dx)
node.x = P.x + (flags&1 ? -rx : rx)
node.y = P.y + (flags&2 ? -ry : ry)
node.width  = u16[D+14]
node.height = u16[D+16]
```

这里所有描述偏移均为十六进制。ASR8是带符号算术右移8位，负数向负无穷取整。每个乘积先分别移位，再加减；不能把乘积合并后才移位。例如angle=0、dx=dy=1时，rx=(255>>8)+(-6>>8)=-1，而(255-6)>>8=0。

角度索引含明确的一格偏移，不应改写为S[-angle]和S[64-angle]。精确的四个变换为：

| 角度字节 | rx | ry |
|---|---|---|
| 255 | dx | dy |
| 63 | -dy | dx |
| 127 | -dx | -dy |
| 191 | dy | -dx |

因此255对应恒等变换，0并非恒等变换。此表不依赖屏幕坐标方向来命名顺逆时针。

镜像发生在旋转之后。例如angle=63、dx=0x300、dy=0x400，先得(-0x400,+0x300)，再镜像X得到(+0x400,+0x300)。若先镜像输入再旋转，则得到(-0x400,-0x300)，结果不同。

## 矩形尺寸没有旋转

宽高字段直接复制，不交换、不通过角点计算新包围盒。节点仍进入既有的轴对齐矩形配对流程。默认描述083347D4的偏移为(-256,-3584)，尺寸16×30像素：angle=255保留原偏移；angle=0变为(-171,-3576)；angle=63变为(3584,-256)。这些角度下尺寸都仍是16×30，不会变成30×16。

不能将此函数概括为旋转整个碰撞框，也不能据此引入旋转矩形的窄相交检测。完整查表512字节SHA1为 `90b145e08a755429b046482c93ad450655867bbc`；证据保存了完整数值和8个默认描述样例。

## 登记与状态副作用

其余骨架与 [组件登记报告](semantic-entity-collision-registry.md) 一致：共享030032E0的64个节点，按3*D[0]+D[1]前插到030038E4开始的9个链头；D+B非零表示继续下一个24字节描述，不作为递减计数。容量在逐项登记时检查，可能仅登记描述链的一部分。

函数先读取旋转系数，并在描述NULL检查之前递减A+20的低7位计数，同时保留高位80。NULL路径不转存A+18；首描述D+3和D+8同时为零、容量耗尽或正常链尾，则将A+18转存到A+1C并清零A+18。三个登记函数均未发现对A+21的递减；该交互计数的生命周期仍需独立追踪。
