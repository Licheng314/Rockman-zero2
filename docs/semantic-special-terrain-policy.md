# 特殊地形接受策略与横向追踪

2026-10-29。补齐上一轮保留的226A8有8000策略，以及2283C/20564横向追踪；深化现有地形研究，累计仍20单元。[原ROM证据](semantic-data/special-terrain-policy-evidence.json)包含6个函数可达指令、常数和两项间接表，基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。未执行游戏、改写正式源码或干预提取。

以下地址/偏移为十六进制，公式常数以0x标明；坐标24.8。P/other只是函数接收的两组参考位置，不直接等同前后两个显示帧。普通数学表达式限定无溢出域；原32位符号/无符号比较和低级查询的±1耗尽返回仍保留。

## 226A8完整接受/拒绝规则

该函数返回原修正d或0，不直接写调用者位置。上轮1FE4C调用时policy、attribute、d、limit和threshold均明确传入，limit=1400、threshold=0C01，分别为20像素和12像素加1/256像素。

policy=0保留d；policy既非0也非1时，仅limit>0且d+limit<=0返回0，其余保留d。policy=1且attribute无8000时：threshold<=0或d+threshold>0直接保留；否则P.y<other.y或P.y+d<other.y则返回0，其余保留。

policy=1且attribute有8000时，按下面顺序判定：

```text
dy=P.y-other.y
若dy<0：返回0
dx=P.x-other.x
xp=probeX-dx
yp=probeY-dy
若08D80(xp,yp)的低四位非零：返回0
若dx==0：保留d
若P.y+d>=other.y：保留d
若floorGrid(P.y+d)>=floorGrid(other.y)：保留d
```

floorGrid(v)=v&FFFFF000。这一历史推导点检查只测试返回属性低四位，未因8000位而跳过占用。

只有上面都未结束，才向xp方向调用2283C(probeX,probeY+d,dir,abs(dx))，dir在xp>probeX时+1，否则-1。返回值>0则拒绝d，<=0继续：

```text
08EA4(xp,yp)<0：返回0
rowEnd=floorGrid(yp)+0xFFF
08EA4(xp,rowEnd)<0：保留d
08EA4(xp,rowEnd+0x1000)<0：保留d
否则：返回0
```

这不是仅按当前点和8000位决定的规则，还涉及参考位置、跨行与横向追踪结果。两次格末端探测在第一处负修正时即停止，不必都查询。

调用栈还传入形状高度及apply，226A8的可达体不读取这两个参数。它读取pad并计算传给2283C的第五栈参数，但2283C可达体不读取该第五参数。因此本段接受策略本身不执行位置应用，也不能凭参数名假定所有参数都影响当前决策。

## 2283C：先沿正Y找非零，再沿格边追踪

输入(x,y,dir,maxDistance)，正常dir为-1/+1。初始锚点：dir<=0时ax=floorGrid(x)，dir>0时ax=floorGrid(x)+FFF；ay=floorGrid(y)+FFF。状态state初始+1。

先查q=08EA4(ax,ay)。q==0时ay+=1000继续，直到非零；这段纵向循环没有独立迭代上限。q>0把state=-1并结束追踪。q<0则令surfaceY=ay+q，继续查相邻一最小单位处：

```text
r=08EA4(ax+dir,surfaceY+0x200)
r==0：state=0，结束
r>0：state=-1，结束
r<0但u32(r+0x300)>0x200：state=0，结束
其余：继续追踪
```

最后一项在通常整数域恰是-300<=r<=-100，也就是在向正Y偏移2像素的取样点上，接受1..3像素的负修正区间；边界包含等号。r=-301或-FF会结束为state=0，不是继续。

继续时ax+=dir*1000，检查u32((ax-x)+2000)<=4000；通常域等价于ax-x处于[-32,+32]像素。超出立即返回0，不论maxDistance多大。通过则用当前ay继续下一列；ay不会每列重新设为最初y所在格。

正常结束时dist=abs(ax-x)：只有state==0且dist<=maxDistance返回+dist，否则返回-dist。dist=0时两种符号结果都为0；另有越过硬32像素范围直接返回0的路径。因此：

- 正值：state=0且距离未超传入限制。
- 负值：可能是超出限制，也可能state=-1，即使距离很小。
- 0：可能零距离，也可能硬范围退出等情形，不能统一当成无障碍。

传入距离限制与硬32像素范围是两层不同条件。它不是逐像素横向扫描，也不是一个通用bool命中测试。

## 1F418：当前点失败后的格两端补查

读取08333AFC两项Thumb表：模式0→0930C正X静态推出，模式1→09190负X静态推出。

先在(x,y)调用所选查询，非零立即返回。若为0，则依序查左格边floorGrid(x)、右格边floorGrid(x)+FFF；首个非零查询值再加“该格边X-x”的偏移返回，两端均0才返回0。

表只确认两项，正常mode为0/1；不把紧接其后的另一张表当成更多方向项。返回值包含边界偏移，不能只解释为原点局部形状助手的位移。

## 20564：方向和竖向探针的一致性检查

20564(x,y,mode,reach)先取q=1F418(x,y,mode)。mode0只保留正q，mode1只保留负q；符号不符直接0。reach>0时原比较为：

```text
u32(q-1+reach) <= 2*(reach-1)
```

通常域即abs(q)<reach。例如reach=1000，绝对值FFF可通过这一层，1000不通过。reach<=0跳过此距离检查，不表示后续必通过。

令x1=x+q，读取08354(x1,y)属性A。若(A&800F)!=0且(A&8000)==0，返回0；形状0或8000位存在可继续。然后x2=x1-1+2*mode（正常模式即向输入方向退一最小单位），在x2建立上下探针：

```text
u=08EA4(x2,y)
若u32(u+0x3FF)<=0x3FF：top=y+u+1；否则top=y-0x400
v=0901C(x2,y)
若u32(v)<=0x3FF：bottom=y+v-1；否则bottom=y+0x400
```

要求bottom-top>3FF，否则返回0。随后以4像素差调整探针，使用F(z)=1F418(x2,z,mode)：

- y-top<=3FF：令bottom=top+400，仅F(top)==F(bottom)时返回原q。
- 否则bottom-y<=3FF：令top=bottom-400，仅F(top)==F(bottom)时返回原q。
- 两边都更远：若F(y)==F(top)，立即返回原q；否则只有F(y)==F(bottom)才返回原q。

比较的是查询结果相等，不要求等于0，也不是在整个竖向区间每点都测试。其余路径返回0。函数不写原坐标；也没有把底层耗尽±1独立标成错误，不能脱离具体输入约束声称它验证了整块区域必然可通行。

## 227C8与22810的返回值转换

227C8按08D80(x,y)的8000位选助手：无位→22810，有位→2283C。22810先把dir逻辑右移31位，得到mode=dir为负时1、非负时0，再调用20564(...,1000)。q==0返回0；否则m=abs(q)-1，m<=传入maxDistance返回m，超出返回-m。

这与2283C按状态/距离编码不同，虽然两个助手共享227C8的同一返回位置。abs(q)==1也会变成0，不能把这组接口抽象成同一个布尔判断或同一种距离含义。
