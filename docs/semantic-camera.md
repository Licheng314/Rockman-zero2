# 摄像机模式、跟随与震动到绘制坐标

日期：2026-10-29。第18个研究单元。只读汇编与美版原ROM，报告和[配置/地址证据](semantic-data/camera-evidence.json)独立保存，不改变后台提取。基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 摄像机结构与绘制器的连接

C=0202ED18，由全局控制G=0202EC30的+E8位置得到。1492C调用14F38初始化，14AD8路径调用14F74执行模式回调，再调用14F80产生震动偏移，最后14F9C在有效模式下提交该摄像机关联的绘制队列。它不同于脚本上下文X=0202EC40。

| C偏移（十六进制） | 已证实用途 |
|---|---|
| +0 | 指向C+38的当前显示中心坐标 |
| +4 | 指向C+28的震动偏移坐标 |
| +10 | 关联绘制上下文指针 |
| +14 | 模式更新回调 |
| +18 | 模式字节 |
| +19 | 跟随标志及精确插值选择值 |
| +1C | 模式首次进入状态 |
| +22 | 插值进度u16 |
| +28/+2C | 当前震动偏移x/y |
| +30/+34 | 目标/跟随中心x/y |
| +38/+3C | 当前显示中心x/y |
| +40/+44 | 模式1的每次更新增量x/y |
| +48 | 跟随目标坐标指针 |
| +4C/+54 | 跟随偏移x/y |
| +50/+58 | 模式2的偏移增量x/y |
| +5C/+60/+64/+68 | 模式4使用的左/右/上/下边界 |

坐标通过右移8用于像素显示，采用24.8定点表示。参数结构中的某些偏移为signed16扩展，不能全部按像素整数加载后再统一乘256。

14F38通过033A8把C+0连到C+38，随后明确把C+4改指向C+28；033DC读取的正是这对坐标指针。

## 模式与44B配置

14FBC写模式，清首次进入状态、插值状态及计时字段，并从083261A4取回调，不在此检查模式索引范围。已核实的5项：

| 模式 | 回调 | 确认行为 |
|---|---|---|
| 0 | 151E8 | 空回调 |
| 1 | 151EC | 目标中心逐次加C+40/+44，再调用1504C更新显示中心 |
| 2 | 1521C | 跟随偏移先加偏移增量；目标指针有效时读其坐标+偏移，再更新显示中心 |
| 3 | 15260 | 跟随目标、地图分类/边界修正、限速及纵向平滑 |
| 4 | 15378 | 类似跟随，并额外按C+5C..+68限制视口边缘 |

14FD8的非NULL参数为44B配置：+0模式、+1标志；模式1取+4/+8为初始目标；+C/+10为增量；+14/+16/+18/+1A的signed16分别写跟随偏移/增量；+1C..+28四个s32写边界。配置会清目标坐标指针和插值计时，不自动为模式3/4提供有效跟随对象。

脚本04→1BCF0调用14FD8；对非模式1且描述符选择的实体存在时，把entity+54接到C+48。配置标志08还会把目标中心立即设到实体坐标。脚本07/0也能接第一个实体作为跟随目标，设置模式3及一次性立即跟随标志。

实际脚本08326778的04命令指向0832655C配置：模式3、标志08，其余42B全0。它使用模式3的地图修正，不应把其中全0边界当作模式4有效世界范围。

## 跟随速度与边界不是同一层

15260/15378先读跟随目标坐标和偏移，再用083A0/083D4查询地图分类与修正量；本轮只确认这些调用及返回值用法，不展开地图分类表。15260可按标志10/20分别忽略相应修正量。

两函数的标志08允许直接设目标中心；否则横向目标每次最多移动：模式3为0x400=4像素，模式4为0x380=3.5像素。纵向按(7*old+desired+bias)>>3更新，old<desired时bias=7，否则0。这是定点方向取整的平滑式，不用浮点平均代替。

模式4在跟随候选值上检查：centerX±120像素是否越左/右界、centerY±80是否越上/下界，分别补回半视口尺寸。没有通用边界排序/最小宽高校验；若范围小于视口或左右颠倒，不能声称结果仍满足所有边界。限幅后还可能经过目标限速和显示插值，亦不保证显示中心每一时刻都在新范围内。

1504C是另一层“目标中心→显示中心”：参数恰好1走约1/4差值插值，恰好2/4走带递增权重的插值；其他值直接复制目标到显示中心，并清标志08。它按完整参数值比较，不是先抽出低几位。因而不能把任意组合标志都解释成同一平滑模式，或把08理解成永远保持立即跟随。

## 震动事件不会按距离衰减

15518(strength,positionPtr)将非零u8强度与位置的x/y写入0202EEC0起的12B事件项。普通队列容量16，计数在+19C，首项强度在+4，每次入队还写下一项强度0作为终止标志。满队列直接返回，无成功返回码供调用者区分；存下位置不等于消费时真的使用位置。

15570(incomingPosition,out)实际没有使用传入r0的位置；扫描事件只读取每项强度，不读取保存的x/y。幅度A取max(上一轮保留幅度, 每个strength<<8)，不是求和，也不是按与摄像机距离加权。由此不能因为函数签名形状就命名为“按距离衰减的震动”。

非零有效幅度时，用080EF450的正弦表和+19E相位，以及31位LCG状态生成x/y偏移；两个分量的计算和随机扰动并不完全对称。代码在小幅度时写0输出，结束时保留floor(15*A/16)，清当轮队列计数和首强度。这里衰减按调用次数，不按已证明的秒数。

154CC完整初始化随机种子、相位和保留幅度，再通过154F4清两组事件队列。156A8还消费另一组从+ D0附近开始的强度通道；本轮仅记录其存在，不把它与15570的二维偏移合并。两个消费者所接收的r0位置参数在已读函数内均不用于空间衰减。

模式0时，脚本辅助1BBFC另有15570调用并把结果右移8写显示偏移字段；模式非0的正常摄像机更新通过14F80写C+28/+2C。不能认为所有震动都只来自一个固定调用点。

## 最终屏幕坐标的精确连接

033DC把C中心和震动分别取整到像素，形成绘制原点：

```text
originX = ((centerX >> 8) + (shakeX >> 8) - 120) << 8
originY = ((centerY >> 8) + (shakeY >> 8) - 80) << 8
```

注意它分别右移两个分量，再相加；不是先将中心与震动相加再右移。负数和小数域可能产生不同取整结果。

普通033C回调随后算(entityCoord-origin)>>8，再加小图块的dx/dy；翻转、粗裁剪和属性打包见[对象绘制报告](semantic-object-drawing.md)。所以实体与摄像机同中心、震动0时，实体锚点在屏幕(120,80)，不是(0,0)。

一个只用整数像素的静态例子：中心(300,200)、震动(1,-2)得到原点(181,118)；实体锚点(310,210)、32×32部件偏移(-16,-16)，最终左上角(113,76)。此例仅验证公式连接，不是模拟器截图或固定场景位置。
