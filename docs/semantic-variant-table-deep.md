## 结构突破：所谓"变体表"就是状态数组的一段

类型 0x20 的相位数组 `0x0833FD94` 实际共 **27 槽（0-26）**，槽 27 起为非代码数据：

| 槽 | 地址 | 角色 |
|---|---|---|
| 0 | 0x08078085 | fn[0] |
| 1 | 0x080780A9 | **薄分派器 → 0x0833FDD0[e[0x10]]**（D=1 相位） |
| 2 | 0x080780C1 | **薄分派器 → 0x0833FDF8[e[0x10]]**（D=2 相位） |
| 3 | 0x08065A05 | 共享状态退出 |
| 4 | 0x08006C29 | 共享退役 |
| 5-14 | 0x080780D9-0x080789FD | 发射初始化族（fn[8]=786F0 等） |
| **15-26** | 0x08078AC1-0x080795E9 | **变体处理器 0-11（=0x0833FDD0 别名）** |

即：**0x0833FDD0 = 0x0833FD94 + 15×4**，"变体表"不是独立表——变体处理器本身就是
状态数组的合法槽位；0x0833FDF8 = +25×4，D=2 分派表的有效项（槽 25/26）恰是
变体 10/11 的一次性生成处理器。此前"110 槽状态表"的说法按此修正为 27 槽。

## 共享拆除块（7 个变体入口处指令序列完全一致，27 条）

变体 0/1/4/6/7/8/9 入口处同一段"捕获会话中止"序列（仅属主门禁条件与寄存器名不同）：

```
门禁不满足时:
  e[0xA] &= ~1; e[0xA] &= ~2        ; 清标志位 0/1
  e[0x8C..0x94] = 0                  ; 三字段清零
  e[0xA] &= ~4
  D(0xC) = 3
  e[0x14] = 0x0833D990[e[9]]->[0xC]  ; fn[3] 共享状态退出
```

门禁差异：变体 0 要求属主 D==9 且相位≤1；变体 1 额外豁免属主 D==0x12；
变体 4/6/7/8/9 仅要求属主相位≤1。变体 2/5 无门禁（纯运动学/空操作）。

## 结构模式：成对变体族

- **偏移对**：{4, 6, 8} 偏移 0x400；{7, 9} 偏移 0x600 —— 同行为两种站位宽度；
- **一次性对**：10/11 完全同构（GCC 对相同源生成的两份实例）；
- **空操作**：5 与槽 6（0x080782BD `bx lr`）——"无行为"也是合法状态。

## 对既有解读的修正

1. **"110 槽状态表"→ 27 槽**：0x0833FD94 数组以槽 26 结束（0x4000100 起为数据）；
2. **"变体表 0x0833FDD0"** 并非独立结构 = 槽 15-26 别名；
3. **D=2 相位**：fn[2] 分派表（槽 25 起）仅 2 个有效项 = 变体 10/11 处理器——
   D=2 + e[0x10]∈{0,1} → 生成产物 + 立即退役（打击/引爆相位，"返程"名义下的
   终结路径）。**D=2 的写入者未定位**（飞行体代码区无 `str #2→[0xC]`，
   应由属主状态机槽 5-14 之外的代码写入）——列入开放问题。
