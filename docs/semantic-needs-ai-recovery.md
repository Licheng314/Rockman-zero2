## 工具根因修复（tools/extract_func.py）

`disasm_bfs(start, cap)` 按字节距离扩展，不知晓已注册邻段；候选区间随之包含
邻段（如 sub_08022590 的 BFS 延伸到 0x080226A8，吞掉已注册的 sub_0802263E），
触发 `Candidate overlaps an existing segment` 自拒绝。

修复：main() 在 BFS 前**钳位 cap 至最近已注册邻段起点 -2**（-2 = Thumb 最小
指令长，防边界指令落入邻段）。两处迭代：初版漏 off-by-one（边界指令仍落入），
修正后一次通过。

## 教训（方法论）

1. **失败清单的错误文本 ≠ 当前真实阻断点**——批量工具的状态文件会保留过期
   元数据，区分分析必须以"当前状态复算"为准（本例：清单错误 vs segments.json
   实况交叉）；
2. 单一系统性根因（BFS 越界）可以伪装成上百条"深层原因"；
3. 受控扫尾 = 每候选独立事务 + 全 ROM SHA1 门 + 自动回滚——与"盲目重跑批量
   队列"的本质区别在于前者可归因。
