# ZCode 现役任务：评分与战斗衔接语义研究

2026-11-08。此文件是唯一现役 ZCode 任务书，取代旧夜间提取、阶段 1 分工和 2026-10-30 交接。总范围见[语义路线](SEMANTIC-ROADMAP.md)，当前研究事实见[HANDOVER](HANDOVER.md)。历史额度和截止时间不沿用；本轮按有限目标停止，额度充足不构成扩大范围的理由。

## 可直接交给 ZCode 的提示词

你接手 Rockman Zero 2 美版原版的语义研究，在 `D:\NewStudio\Decompilation\public-release-clean-20261101` 的 `main` 工作。先读 `AGENTS.md`、`docs/HANDOVER.md`、`docs/CONTINUE.md`、`docs/SEMANTIC-ROADMAP.md` 和本文件。先核对分支、Git 状态、原 ROM SHA1 与写入锁，保留已有成果。不在 `Rockman-zero2-mod` 工作，不切换改版分支，不制作或发布新 ROM。

本轮顺序执行 **2A 评分研究 → 2B 动作与实际连击研究**。完整任务最多新增深入研究 30 个 Z2 函数（2A 最多 10，2B 最多 20）；首次各至多 5 个。依赖也计入对应上限，复用既有研究不重复计数。批量扫描和采样交给脚本，AI 用于解释控制流、对照 Z3 和设计有区分力的验证。不要按 Token 消耗、文档篇数、静态断言数或 C 函数数冲刺。

### 工作包 A：阶段 2A，评分与能力记录

目标是对一个关卡解释“分项输入 → 结算 → 总分/等级 → 一个已知 EX 资格门”，并确定终极装甲与精灵记录是否造成惩罚、通过什么字段造成惩罚。禁止预设评论中的机制一定正确。

1. 复用 `docs/semantic-hit-consumers.md`、`docs/STAGE2-WEAPON-RESEARCH.md`。候选入口 `0x080141FC`（评分读取）、`0x08014360`（伤害记录累计）、`0x0801D6D8`（选定奖励判定）只作起点。重新核对原版；旧 C 注释“E-crystals”已被消费者证据纠正，不据名称推断含义。
2. 在一个可重复关卡结算场景，记录实际经过的分项公式、阈值、舍入、上限、重置/累计/结算写入者；不普查所有关卡阈值。
3. 至少三组控制条件：普通装甲基线、仅切换终极装甲、仅改变精灵使用记录。把拥有、装备、使用记录、当前效果分开。比较程序内分项和结算显示，控制时间、受伤等其他因素。若条件必须通过 RAM 夹具构造，明确它不是自然取得流程。
4. 对选中惩罚字段检查跨关/普通存档恢复是否保留；只复用已知存档入口，不扩展完整存档格式。奖励只追阶段 2 已定位的一个资格门。

验收项 A1：分项字段、公式、读写时机表；A2：三组对照及惩罚来源结论；A3：总分/等级与结算显示对应；A4：选定字段生命周期与一个奖励门的联系。函数上限 10、结算场景 1。结算子程序调用夹具不能称完整通关；不能自然到达的链路标未验证。

### A/B 检查点

先独立重跑 A 的脚本，记录 A1–A4 为通过/未完成/有界受阻，保存可复跑证据与提交检查点，不能自行把受阻改为完成。A 全部通过可继续 B；A 在三轮明确假设或函数上限后受阻，也可转做不依赖该阻塞的 B 项，并保留 A 的未完成状态。不得扩大 A 预算、重试同一失败直到耗尽额度，或将 A/B 成果混为一个完成百分比。构建基线或工程完整性异常时停止整个任务，不转包掩盖异常。

### 工作包 B：阶段 2B，有限动作链与实际连击

目标是分别解释输入是否接受、动作是否切换、目标是否真的继续扣血。核心仅普通剑三连斩、蓄力斩、升龙、下戳；枪弹只作混合链前置。最多 20 个新增深入函数、2 个场景、2 类目标（普通敌人及一名可重复测试 Boss）。未取得 Boss 样本则保留未完成，不能外推全部敌人。

1. 先核对 Z2 中各样本招式与使能条件。记录按住/新按/松开、缓冲或取消窗口、动画事件、攻击对象生成/销毁，以及速度/重力的实际写入者。没有缓冲同样是有效结论。
2. 只验证三条假设链：三连斩→升龙；蓄力斩→三连斩；枪弹→蓄力斩→三连斩→升龙→下戳。保留失败链和失败位置，不要求原版必须支持它们，不替换成更容易成功的序列。
3. 升龙短按与长按作对照，记录速度、位移、状态和退出原因，解释招式轨迹与通用跳跃的关系。可在既定场景调查受击、落地和碰顶；位置不足时替换样本，不超场景上限。
4. 独立追命中规则：攻击等级/优先关系、目标保护计数、同一攻击的重复命中、属性和命中停顿。逐次记录目标身份与 HP；动作接上但不扣血必须单独解释，禁止全局关闭受击保护来伪造连击成立。

验收项 B1：有限动作转换与输入窗口表；B2：三条链的成功/失败时序和实际 HP；B3：升龙短/长按轨迹与退出解释；B4：普通敌人/Boss 对照与命中门控。B2 中原版失败也是可验收结论，前提是可复现且区分输入未接受、动作被打断、未碰到目标、命中被拒绝。不给未经测量的“Z3 手感已复刻”结论。

### Z3 必须作为对照线索，而非 Z2 答案

参考 `https://github.com/mmzret/rmz3`。优先看 `src/player/zero/attack/ground/idle.c`、`src/player/zero/attack/air.c`、`src/weapon/saber.c`、`include/collision.h`，评分按问题定位。可复用现有只读参考副本；若不可读或无 Git 元数据，在当前项目被忽略的 `build/reference/rmz3` 准备固定提交的源码参考，不覆盖其他副本。

- 每批记录仓库提交、文件与符号；区分匹配 C、`NON_MATCH`/`MODERN` 解释代码与汇编引用。
- 每个问题给出“Z3 规则与证据 → Z2 候选 → Z2 验证 → 相同/不同/未定”。不按固定地址差或结构体偏移机械对应。
- Z3 是日版，当前 Z2 是美版。仅有 Z3 源码时标静态对照，不编造 Z3 运行测试；不要求为了本任务取得额外 ROM。
- Z3 检索限于 A/B 问题涉及的函数与表，不做全仓库翻译。Z3 阅读量不是新增 Z2 研究函数数，但同样受单问题三轮假设和 A/B 目标边界限制。
