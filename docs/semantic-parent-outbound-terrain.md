# 捕获对象的向外飞行、点地形停止与无目标返程

本轮补齐[捕获协议](semantic-parent-capture-protocol.md)尚未执行的向外飞行和无目标结束路径，深化已有21单元。[原ROM证据](semantic-data/parent-outbound-terrain-evidence.json)保存6个局部函数330条可达指令及点形状表；部分短形状助手没有独立汇编文件，证据直接取原ROM并按相邻已知入口标注范围。基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。

## 792D4阶段0的精确顺序

进入阶段前，父对象生命周期和状态9/12仍有提前停用门禁，失活目标也会被清指针。正常向外阶段D=0的每次调用顺序是：

1. u8[S+12]加一，记录向外更新次数；
2. S.X+=S+5C，S.Y+=S+60，使用既有运动向量；
3. 调08CFC(S.X, S.Y-0x800)，即移动后位置上方8像素；
4. 若返回值低16位非零，D+=2，直接进入返程状态，本次不减超时；
5. 否则u8[S+13]减一，结果为0也令D+=2。

不在命中当次纠正坐标、搜索地形表面或撤回本次移动。转D=2后当前调用结束，下一次才开始减向外计数并反向移动。因此停点可能在采样形状内部，不能说本处理器把对象精确贴在表面。

S+12和S+13是两个不同的8位计数：前者累计已走步数，后者只在未命中地形的向外调用中递减。碰撞捕获回调另会把D改1、+13改16，进入上一报告的停留路径，不能与本段飞行超时共用同一时间解释。

## 查询实际包含静态形状、动态矩形与全局范围哨兵

08CFC先把坐标算术右移12，检查格列<=0x770、格行<=0x4F5的无符号范围；负格坐标也会被排除。越出此全局范围直接返回0x0E01，于是此飞行处理器也会返程。全局范围不是当前实际地图的宽高校验，不能据此声称任意地图坐标都安全。

范围内从020017E0行宽和020017E4编号网格读取tileId，再经020011B8指向的u16属性表读取完整属性。按低4位选择08312B8C点形状函数，用坐标低12位测试。静态形状返回非零时，08CFC返回完整属性；未命中才调用09FE4补查动态矩形。完整点表公式已有[点地形报告](semantic-point-terrain.md)，本轮执行其中0/1/8/E/F几类，不冒充重测全部16类。

例如shape8以localX>>1为阈值，localY严格大于它才命中；恰等于表面不触发返程。shape1/E/F使用~localY，因此格内Y为0也可命中。属性0x8001在本查询中照常命中，不采用正Y等方向推出查询的8000过滤规则。

## 完整16位判断与先前低字节查询不同

该处理器把08CFC返回值左移16判断零，因此使用的是完整u16属性。动态矩形属性0x0100会触发返程，虽然其低8位为0；不能套用父状态57A70“网格编号低字节真假”的契约。两者不但截断宽度不同，读取的数据层也不同：这里是属性与点形状，57A70是专用窗口的地形编号。

09FE4的几何命中以正常坐标解释为：X在[cx-halfWidth,cx+halfWidth)；Y在(cy-halfHeight,cy+halfHeight]。这两个方向包含的端点不同。它返回记录的u16属性，并把当前X中心与旧X中心的差写02000020；即使记录属性为0，该几何命中也可能写这一全局值，但飞行处理器仍按返回0继续超时分支。动态矩形细节见[动态矩形报告](semantic-dynamic-rectangles.md)。

## 无目标返程不会消费关联目标计数

阶段D=2每次u8[S+12]减一，X/Y减去相同运动向量。向外计数最终减到0时，若S+2C为NULL，只停用S、清显示/控制/碰撞字段并置生命周期3及对应回调；不写父C1、不扣父CC，也不调用A2100。

这与捕获到类型22目标后的返程不同：有目标时才有C1交接结果和CC归还。不能把“返程结束”一概解释为“交接成功并消耗一个目标”。

零初值也有明确机器行为：向外超时+13从0减到255，要256次未命中更新才减到0；此时累计步数+12也恰好回绕为0。返程从0继续减到255，再经过总共256次反向调用才结束。原轨迹使用固定向量且未受外部改写时，这个256+256周期仍回到原坐标，并非一进入返程就因计数0而立即停止。

以上是8位计数边界，不证明正常初始化会提供零超时；不据此判作原版缺陷或更改实现。所有计数均按处理器调用数，尚未换算成显示帧或秒。

## 已验证范围与接续

[局部核对脚本](semantic-data/parent-outbound-terrain-check.py)通过192组实际点查询边界、68条完整向外—停止—返程路径及4组全局范围哨兵例子，共5060次局部调用。完整路径中48条由静态墙格/动态矩形命中触发，20条由超时触发，包含零计数的256次回绕；逐次比较采样位置、计数、阶段、返程坐标及父C1/CC保留。

792D4、08CFC、所用静态形状助手和09FE4均执行原ROM指令，只有128D4动画推进为空操作；没有注入地形返回值或用布尔钩子替代查询。地图编号、属性和动态矩形为构造RAM，未执行实际地图加载、786F0初始化、碰撞捕获核心或完整游戏调度。

接续可把786F0的方向、除法和超时初始化接入这些已验证路径，展开六个附属对象职责及完整池更新顺序，并继续核查父状态15的独立入口。正式源码、清单及提取程序未修改；既有ROM只作只读散列核验，本轮没有重建。
