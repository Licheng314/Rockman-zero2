# 实体碰撞相交后的属性准备、状态与回调

2026-10-30。深化第21单元，完整记录07AAC（目标分类k=2）和07D40（目标k=1）的接口层分支；07258命中核心已保存原始可达分支，完整判定留待继续。[原ROM证据](semantic-data/entity-collision-resolution-interface-evidence.json)包含4个函数/包装，基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。未执行游戏或修改正式代码。

以下用节点N/M、所属组件S/T、各自描述Ds/Dt区分。偏移/地址为十六进制，公式常数带0x；坐标24.8。状态位保持机械含义，不提前给全部位命名成伤害、格挡或无敌。

## 07D40：先应用k=2路径建立的范围

若S+18状态有100位，07D40先做额外横向范围检查：

```text
M.x - M.width <= P_s.x + (s16[S+34]<<8)
M.x + M.width >= P_s.x + (s16[S+32]<<8)
```

P_s来自S+8位置指针。两式等号都接受；这里用目标节点的整个width字段作加减，不先除二，不能用上一层标准相交半尺寸代替。

任一不成立直接返回，此时还没清本对临时状态。100位及32/34范围由先执行的k=2路径建立，说明两组有序配对不只是调用不同回调，还存在状态依赖。

## k=1的四个覆盖字段与筛选掩码

通过范围后，先清S+14/T+14两个临时状态字，把Ds/Dt写S+4/T+4作为本对描述，再按S+36的覆盖掩码决定是否从Ds补默认字节：

| 覆盖掩码位 | 有效组件字节 | 默认描述字节 |
|---|---|---|
| 01 | S+37 | Ds+3 |
| 02 | S+38 | Ds+5 |
| 04 | S+39 | Ds+6 |
| 08 | S+3A | Ds+7 |

位未设置才补默认值。由此闭合06E18的四个配置槽；没有证据把它们当成四个独立矩形数量。

S+36&06==0时，直接把u32[Ds+C]复制到S+3C；否则根据Ds+4及有效S+38/S+39重新生成32位筛选掩码。令q=u8[Ds+4]、e=u8[S+38]、f=u8[S+39]：

| 条件 | S+3C |
|---|---|
| q<=3且f&1非零 | 80000000 |
| q<=3且f&1为0 | 1<<(5*q+e+(f&2非零时1，否则0)) |
| q=4..8 | 1<<(q+10) |
| q=9..B且e==q-8 | 1<<(q+13) |
| q=9..B且e!=q-8 | 1<<(q+10) |
| q>B | 00008000 |

表中移位索引常数为十六进制。原指令用Thumb寄存器移位，异常大索引要保留低8位计数及>=32时清零等机器规则，不能用未限制范围的C移位表达式宣称完全等价。

准备后调用07258(S,T)。其入口已确认：全局G+0的80位可阻止处理；S+3C与u32[Dt+4]没有交集也会早返回。因此几何相交不保证核心接受；即便核心拒绝，本包装前面的临时状态清零、描述缓存及覆盖字节更新已经发生。

## 07AAC：k=2路径的入口拒绝与范围建立

07AAC先拒绝全局G+0的80位或Ds+2精确值4。之后按覆盖掩码04决定是否以Ds+6补S+39；有效S+39有80位则返回。这最后一种早返回仍可能已刷新S+39，与最前两种拒绝副作用不同。

继续时清S+14/T+14并缓存Ds/Dt。若S+18没有100位，先令s16[S+32]=-32768、s16[S+34]=32767。按S/T各自位置指针的基础X比较：

```text
P_s.x < P_t.x：S+34 = s16((M.x-M.width-P_s.x)>>8)
否则：S+32 = s16((M.x+M.width-P_s.x)>>8)
```

这里右移为算术右移，负数不是向零除法；结果截16位。每个候选直接覆盖对应一侧，不与已存端点取min/max。后登记链顺序及目标桶顺序因此可能影响后续k=1范围筛选。

## k=2状态写入与对方指针

若Ds+2==1、Ds+4非零且T+1C的C0位非零，写T+C=S、直接T+18|=80，并跳过常规目标临时状态设置。

其他路径写T+C=S、T+14|=40；若Dt+9有01位，另T+14|=2000。Ds+4为1或2还写u8[G+2]=4，连接上轮已确认的配对暂停计数。该写入不在特殊分支发生，也不是所有几何相交都设置暂停。

随后两条路径都写S+C=T、S+14|=120；Dt+9有01位时另S+14|=1000。注意+14是当前候选临时字，+18是累计字，+1C是登记时转存的历史字，不能当成一个状态槽。

若有效S+39有20位且旧S+18无380000位，则T+14|=40000；Dt+9有08位时，原代码重复读取同一位，依序给S+14设置80000、100000、200000。普通不变内存下三位共同置位，不能误读为分别测试三种不同描述标志。

最后S+18|=S+14，T+18|=T+14。特殊路径的T+14原本可能仍0，但增强分支可再把它置为40000，进而改变T是否有资格回调；不能据特殊分支入口就断言T永远不回调。

07AAC自身没有调用07258扣减数值核心。它与k=1路径作用不同，不将两条路径都命名为同一种伤害结算。

## 共用的回调前置条件

两处理器的尾部结构相同：先检查至少一方+24回调指针非NULL、至少一方+14临时状态非零，否则不计算载荷。之后分别检查各自“指针存在且临时状态非零”才调用该方回调。

两个总条件不是按同一方配对的合取：可能只有S状态非零、只有T有回调，仍会计算载荷但最终两方都不调用。不能擅自把总条件优化成“至少存在一个已满足所有条件的回调”而改变计算行为。

07D40会在这些检查之前调用核心07258，因此没有回调不代表没有状态或数值处理；反过来，回调条件也不等于已经扣减生命值。

## 回调载荷：尺寸加权点与中心方向

令dx=N.x-M.x、dy=N.y-M.y。两个处理器都构造栈上contact与direction：

```text
contact.x = M.x + trunc0(mul32(dx,M.width)/(N.width+M.width))
contact.y = M.y + trunc0(mul32(dy,M.height)/(N.height+M.height))
len = u16(BIOS_sqrt(u32(mul32(dx,dx)+mul32(dy,dy))))
direction.x = trunc0(s32(dx<<8)/len)
direction.y = trunc0(s32(dy<<8)/len)
```

EEF7C原指令为SWI08平方根；除法调用EF150，通常有符号域向零截断。乘法、加法和左移都先按32位截断，再进入除法，不能换成64位精确算术后声称等价。

contact是按每轴双方尺寸加权，不是无条件中心点平均。十六进制静态例子：N.x=0、M.x=200，N.width=100、M.width=300，得到contact.x=80，而不是中点100。它不是按最后一像素视觉边缘重新求交的位置。

中心重合时len可能为0，代码没有先设默认方向或跳过除法。EF150的零除路径调用EF1E4，若该处理返回则给0；本报告不替原程序添加epsilon保护，也不在没有运行证据时断言必然崩溃。

## 回调顺序与共享缓冲

先调用S.callback(S,&contact,&direction)。之后重新读取T+24指针和T+14状态，满足条件才把当前direction两个字取负，再调用T.callback(T,&contact,&direction)。

如果S回调不改缓冲，T得到反向向量及同一接触点；但它们实际收到可写的同一栈缓冲，S回调也可能改变点/向量、T的回调指针或状态。第二次使用的是这些调用后的值，不是预先复制的一份原始反向载荷。

这些指针指向处理器局部栈，不是持久对象位置字段。还原ABI和回调时应保留顺序、重读和缓冲所有权。
