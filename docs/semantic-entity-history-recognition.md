# 动作历史识别：重复方向、序列与成功缓存

2026-10-30。深化第16输入研究单元，并连接第21单元交互计数，累计仍21单元。地址、字段和掩码用十六进制；窗口与案例数量特别注明十进制。[原ROM证据](semantic-data/entity-history-recognition-evidence.json)覆盖1EDD8、1EC5C、1E91C、1E978以及真实模式流，基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 公共历史结构与方向选择

沿用 [动作历史报告](semantic-entity-action-history.md)：i=u8[E+195]指向最新动作，H=E+198为64项环；E+196是新动作位，E+197每次输入更新写FF，E+1D8/+1DC为64槽位图。

两个查询都从08333A58的指针对，按E+A的10位与u8[E+9]选择目标方向T和相反方向O。本轮类型0的实际数据是：10位未置位时T=04、O=08，置位时T=08、O=04。不能不看此表就为目标方向统一命名左右或向前。

## 1EDD8：当前边沿加历史内的同向按下次数

签名为(E,window,count)。首先要求E+196&T非零；失败直接返回0。成立后把remaining=count-1，再从i-1开始向更旧的记录比较。正常正窗口下可写成：

```text
p = (i-1)&63
sample = H[p]
window = min_unsigned(window,63)
loop:
    if sample & O: fail
    p = (p-1)&63
    older = H[p]
    if sample & ~older & T: remaining--
    sample = older
    window--
    if remaining == 0: return T
    if window == 0: fail
```

这是沿时间正向的按下边沿，通过倒序比较找到，不是数“多少条记录处于按住”。相同方向持续按住不会在每条记录中都计一次。成功返回方向掩码T，不是固定布尔1；该查询不改历史、缓存或位图。

反方向检查发生在sample上，读取older以后可能立即满足次数并返回，因此最后读取的更旧一条不一定再受反向检查。窗口也限制比较次数，而非包含当前项的记录总数：窗口11时，最多比较i-1到i-12之间的11对相邻记录。当前i的新边沿已经在入口计入。

参数没有健壮的零值门禁。窗口0仍先执行一次，再以32位减法回绕；count为1也不会直接成功，而会进入循环，历史边沿可能把remaining从0减到FFFFFFFF。只把已核实的实际调用域解释成有效操作，不将这些输入当作安全禁用参数。

## 1E91C与1E978：真实调用和保留字段

1E91C按实体类型先取08333A54的直接动作掩码。类型0为40：若E+196与40相交，便把完整掩码40写E+186并返回40；否则用08333A60给出的参数调用1EDD8。类型0参数为窗口11、次数2（均十进制）。成功将返回的T写E+186；失败返回0，但不清旧E+186。

1E978读取E+186与当前H[i]，相交为0返回1，否则返回0。因此该字段还被用于判断先前选定动作是否仍出现在当前动作中；不应把1E91C失败理解成该字段立即失效。这里不凭操作习惯把40或重复方向机制命名为具体游戏动作。

## 1EC5C：先查成功缓存，再倒序匹配两种序列

可达指令表明第二寄存器参数r1不参与筛选；实际选择模式的是第三参数r2。签名可记为(E,unused,patternId)，不能把调用点的r1当作已生效的动作类别过滤。

首先读取s8[E+197]：

- 非负：只比较其值与patternId，相等返回1，不等返回0；不重新读取历史或位图。
- 负值：进行模式扫描。常见FF来自1EAF8的每次更新；80..FE同样会落入扫描路径。

扫描从08333AAC按patternId索引指针对，每对有两条0终止的字节流，先尝试变体1，再变体0。两个变体各自从当前游标i重新开始。已验证实际模式0..3；函数没有对任意patternId做范围检查。

下表为原始模式字节，从最新向更旧匹配，省略末尾00：

| 模式 | 首试变体1 | 后试变体0 |
|---|---|---|
| 0 | 08 0A 02 | 0A 0A 02 |
| 1 | 08 0A 02 08 0A 02 | 0A 0A 02 0A 0A 02 |
| 2 | 02 0A 08 | 0A 0A 08 |
| 3 | 0A 02 08 | 0A 02 0A |

模式中的水平位是相对标记：含08时换成T，只有04时换成O；0A因含08会变为T|02。其余位保留。实际比较的是H[p]&0F与转换后的完整字节精确相等，高半字节的其他动作不参与方向匹配。

每个模式字节最多检查10条记录（十进制），达到匹配就将p倒退一项并进入下一个字节。每步重新有10次额度，不是整套模式总计10次。连续两个相同字节也要求至少两条独立记录，不能用同一条对角输入同时满足两个步骤。

任意一次检查遇到该槽位图标记非零，或H[p]&O非零，当前变体立即失败；其他不匹配但未触发否决的记录可以在本步窗口内跳过。该函数不要求E+196非零，不能把它改写成只对当前按下边沿检测的接口。

## 缓存与槽标记的实际责任

一个变体全部匹配后，1EC5C把patternId低字节写E+197，并在位图中标记最新游标i；不是把扫描经过的所有槽都标记。失败不缓存0、不改标记，仍允许随后另一请求扫描。

同一输入更新期间，成功的同模式查询可经缓存反复返回1，即使当前槽已标记；不同模式则直接返回0。下一次1EAF8把缓存写FF，只清新写入槽的标记，旧成功槽的标记会保留到它被环形覆盖。因此位图能让之后的扫描避开已标记记录，但不能描述成“同模式同次更新只返回一次成功”。

这补齐了E+197和附加位图在本查询中的用途；仍不声称所有消费者都已穷尽，也未给模式0..3附上未经游戏验证的招式名。

这是人工历史内存下的局部核对，不是游戏观测或完整CPU模拟。下一步可沿真实状态调用继续取得动作名称、请求时机和标记寿命的场景意义。正式代码、后台提取与构建保持原样。
