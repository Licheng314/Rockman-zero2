# 573FC父对象动作选择：状态恢复、历史权重与临时覆盖

本轮接续父状态研究，深化现有21单元。[原ROM证据](semantic-data/parent-action-selector-evidence.json)保存573FC完整局部控制流395条可达指令、两段17项计算跳转表和父主状态表；基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。本文状态编号和偏移统一十六进制，随机余数/表内区间与案例数量为十进制。

首先明确范围：573FC的最终输出集合是0B/0C/0D/0E/10/11/1B，不直接选择先前[准备15、创建16](semantic-attachment-parent-phases.md)和[往返17](semantic-parent-motion-cycle.md)。十六进制10/11不能和16/17混同。573FC与57820是两套选择器；目前没有把573FC当成进入15的直接证据。它们都使用B4历史字段，但更新规则有差别。

## 先恢复逻辑上的当前状态

P+D为主状态，P+C0为可恢复状态字节，P+B4为选择历史。入口按原始P+D处理：

| 原始P+D | 处理 |
|---|---|
| 0B/0C/0D | P+D=P+C0 |
| 0F/12/18 | P+D=P+C0，并禁止本次进入优先0C/0D候选分支 |
| 1B | P+D=P+C0，并禁止本次再次临时改入1B |
| 其他 | 保留P+D |

以上是两个不同开关：从1B返回不禁止0C/0D分支，从0F/12/18返回也不自动禁止再次改入1B。之后的current均指恢复后的P+D，last为B4。入口的范围判断是无符号比较，低于0B或高于1B均不访问表。

首段跳转表位于08057424，第二段位于08057518，均覆盖0B～1B。汇编文件在第一张表把数据误显示成strb/lsr，在第二张表及部分分支以gap保留字节。本轮按原ROM字面池、计算跳转和表目标追踪，没有执行这些数据伪指令，也没有修改正式汇编。

## 优先0C/0D候选与共享随机状态

每次调用先推进0202E188：seed=(seed*0x343FD+0x269EC3)&0x7FFFFFFF，high=seed>>16。这里的乘加常量为十六进制，high与后续区间为普通整数。

若首个high的低4位<=7，且入口没有禁止优先分支：last==current==0C时直接选0D，不再为候选多抽一次；否则再推进一次种子，以新high低4位<=7选0C，其他选0D。

未进入此分支时，读取u8[u32[0202EBF0]+1]，大于4走下文高配置分支，否则走低配置分支。该指针未先作NULL检查。本轮仅证实字节阈值，不把它擅自命名为难度、血量或阶段等级。

## 候选选择的区间表

每个下表行会再推进一次随机种子。只有last==current时才选相应特殊行，否则使用默认行；不能只看当前状态推测权重。

高配置（外部字节>4）：

| last==current的状态 | 使用值z | 候选区间：z → 主状态 |
|---|---|---|
| 0B | high低4位 | 0～3→10，4～7→0E，8～15→11 |
| 0E | high低4位 | 0～1→0B，2～6→10，7～15→11 |
| 10 | high低4位 | 0～1→0B，2～6→0E，7～15→11 |
| 11 | high低4位 | 0～1→0B，2～8→10，9～15→0E |
| 1B | high%18 | 0～1→0B，2～5→10，6～9→0E，10～17→11 |
| 默认或last!=current | high%20 | 0～1→0B，2～5→0E，6～9→10，10～19→11 |

低配置（外部字节<=4）：

| last==current的状态 | 使用值z | 候选区间：z → 主状态 |
|---|---|---|
| 0B | high低4位 | 0～7→10，8～15→0E |
| 0E | high低3位 | 0～1→0B，2～7→10 |
| 10 | high低3位 | 0～1→0B，2～7→0E |
| 默认或last!=current | high%10 | 0～1→0B，2～5→10，6～9→0E |

这里记录的是离散区间，不能直接当作真实游戏中的独立概率：共享种子会被其他对象推进，取余也不保证严格均匀，而且前面的优先分支和后面的覆盖仍可能改变最终结果。高配置的特殊1B行检查的是恢复后的current；它不等同“只要原始入口是1B就用这一行”。

## 临时改入1B可以丢弃已算出的候选

候选算完后，若本次不是从原始1B返回，且P+CC和P+DB均非零，再推进一次随机种子；若新high低2位非零，则：

- P+C0=current，P+D=1B；
- 保留原P+B4历史字节；
- P+E、P+F、P+DB清零，返回。

这条路径会舍弃此前已选候选，但已发生的随机推进不会撤销。若低2位为零，继续普通提交。从原始1B返回则完全跳过这一次随机抽取，即使CC/DB仍非零。本函数对CC只读，不能把DB清零误说成同时消费CC。

普通提交时，若候选是0B/0C/0D/0F，把current写入C0；然后B4=current，D=候选，E/F/DB清零。局部候选生成代码没有输出0F，尾部保留该比较并不证明本函数能选0F。临时1B覆盖与普通提交是否更新B4，是后续重放历史时必须保留的差别。

随机推进总数随路径为1～3次：例如同为0C的快速0D候选可只用一次；普通两层选择通常两次；再经过覆盖判定可多一次。不能把整个函数概括成“每次固定抽两次”。

## 验证与接续

[可重放脚本](semantic-data/parent-action-selector-check.py)对完整573FC及两个计算跳转执行9144组局部核对，比较最终D/B4/C0/E/F/DB、CC保留、共享seed和取余调用参数。覆盖全部入口状态字节，外部阈值4/5及其他值、恢复/禁止/临时覆盖、历史相同/不同、所有特殊区间表行和1/2/3次随机推进路径。

实际结果中，推进一次102例、两次5920例、三次3122例；这些是测试样本计数，不代表真实游戏概率。唯一建模外部调用是EF330无符号取余，没有调用完整调度器、动画或死亡链。

接续优先寻找主状态15的独立进入来源，追踪CC/DB/C0写入与0202EBF0外部字节身份，再将两套选择器连接到真实父对象类型。正式代码、清单、后台提取均未修改；既有ROM仅作只读散列核验。
