# 项目持久记录、成长域与三项配置列表

2026-10-29，只读语义轮。项目描述符原始字段及有证据的解释保存于[数据清单](semantic-data/item-descriptors.json)，含基线ROM SHA1、原始12B记录、有效编号、成长索引、动作码和成长门槛。未改动正式源码或后台工具。

## 表边界与有效编号

多个接口（57CC、5968、5A48、6138、61FC等）使用无符号(id-1)<=0x50，接受id1..81，拒绝0及越界。描述符基址0834A1D4、步长12，共含编号0的空记录及81个有效记录，结束地址恰为0834A5AC；后者又被5880/58A8/58D0作为类别区间表使用。代码边界和数据相邻关系相互印证。

0834A5AC的三个[firstId,count]为[1,27]、[28,27]、[55,27]，分别覆盖1..27、28..54、55..81。58D0返回所属组或-1；5880把合法组内序号映射为项目id；58A8执行逆映射，越出所选组返回-1。暂不将三个组命名为具体游戏对象类别。

## 100B项目状态块的部分布局

该块位于entity+0x228，正是31238/快照+0x48复制的100字节区。现可解释其中大部分：

| 实体偏移 | 长度 | 直接访问证据与操作级含义 |
|---|---|---|
| +0x228..0x232 | 11B | 位图A，获得接口置位；部分已获得检测读取 |
| +0x233..0x23D | 11B | 位图B，获得接口置位、确认使用清位，三项配置写入要求为1 |
| +0x23E..0x248 | 11B | 位图C，指定策略项目使用后置位，菜单拒绝再确认 |
| +0x249 | 1B | 未命名的间隔/对齐位置，未证明具体用途 |
| +0x24A..0x26F | 19×u16 | 每个成长索引的累计值 |
| +0x270..0x282 | 19×u8 | 对应成长阶段 |
| +0x283..0x28B | 9B | 其它统计/标志，部分使用已见，整体未解完 |

每个位图按id>>3选字节、id&7选位，不是(id-1)选位。81有效id需要11B，bit0对应的id0在正常接口中无效。三组是不同状态，不合并成一个布尔owned字段。

316B0/31008初始化链与以上布局一致：31008清三个11B区域、19个半字累计值和19个阶段字节（其参数是entity+0x1E0，换算偏移时必须加回这个基址）。该参数上下文不同于直接传实体的读取接口。

## 获得接口及重复调用限制

61EC(entity,id)将entity+0x228传给61FC(block,id)。61FC检查id1..81后：

1. 置位A[id]和B[id]。
2. 读取12B描述符+0的signed8成长索引g。
3. 若g!=-1，清block+0x22+2*g的u16累计值，以及block+0x48+g的阶段字节，即entity+0x24A和+0x270相应项。
4. 不清位图C。

它没有先判断A[id]是否已经置位。因此重复调用可把已成长项目重置，而旧的已使用位C仍保留。D2C60某些发放路径先查A位再调用；D6BA8接触路径本函数片段没有相同的A位检查，可能依赖事件自身一次性状态。不能把获得助手直接封装成“幂等发放”而保持原语义。

## 使用确认与三个状态的关系

6260(entity,id)清B位；描述符+1字节为0时置C位。它本身没有像61FC那样的完整id1..81前置校验，调用者必须维持合法域。项目6/7的+1=0，所以其确认使用确会清B、置C。

5BBC在A位为1但B位为0时显示另一条引用文本；否则读取描述符+6的显示引用。菜单配置EB6D4要求B位为1且C位为0，再检查成长完成，才允许写入三项列表。这支持“获得记录/未消费资格/特定已使用记录”三个操作级解释；是否还有复活、重置等游戏路径，需继续追写入者后才能正式命名为alive/dead等游戏字段。

三项列表entity+20A..20C是选配数据：EB6D4将选中项目写入selected位置，并清其它两个位置中相同id，保证该写入路径不留下重复配置。EB328也能直接清除选中列表项。未看到这些配置操作同步清A/B/C位图，因此移出列表不是从持久库存删除。

57CC按索引2→0搜索合法id，返回匹配索引或-1；57FC按3项逐一比较58D0所属类别，返回是否存在该类。列表内容可以反复配置，不能把它简单叫作尚未获得的待发奖品。

## 成长字段：19项目，其余62项无成长索引

对81个有效描述符读取signed8(+0)：取值为-1或0..18。19个非负索引各只对应一个项目，没有共享成长槽；62项为-1。

5968(entity,id)返回阶段；合法id且g==-1时返回0，非法id返回-1。

5A98返回相应累计值，5ADC从0834A5E8[g]的半字阈值数组按当前阶段取下一阈值。5A34/5A48从0834A634[g]取最大阶段并比较当前阶段；g==-1时视作已完成，非法id返回-1。调用者须注意-1不是统一的false。

59AC推进阶段：先缓存当前累计值；只要未达最大阶段，且累计值>=当前阶段阈值，就阶段+1并继续。返回“此次是否至少升了一段”的低8位布尔值，累计值本身不被扣减。比较可跨多个阈值，因此阈值应按累计域解释，不能未经证明改写成每次减去价格。

项目6/7：成长索引5/6，最大阶段各1，共用阈值数组0834A5CE的首项400。设置累计值为400并不意味着阶段立即自动更新，仍需59AC或其它阶段写入调用。这里400是静态数值门槛；货币/投喂资源的正式名称尚未从增加入口完整核实。

## 描述符字段已确认到的层级

- +0 signed8：成长索引，-1表示无成长项。
- +1：控制6260是否写C位、6138某些统计是否增加的策略字节，暂不赋具体角色类别名。
- +2：动作码；2..11的即时回调类别及0x80异步激活已见，0x80对应有效项目6/7。
- +3：原值保留，未鉴定。
- +4/+6：经半字偏移表和DE510用于显示，清单记录为显示引用编号，不伪称已解码的文本。
- +8/+10：原半字保留，未鉴定。

本轮不再将记录首字节05/06与项目id6/7混用，它们现在有独立的成长索引证据。

## 相关前置条件与继续方向

- 568C的三对象指针移除函数在非NULL目标未找到时会继续搜索；调用者需保证目标在链/数组中，不能当作有界安全查询。该函数管理entity+2A8附近活动对象关联，与三项项目id列表不同。
- 菜单确认的B位、C位和成长条件不直接证明B储量计数不超过2；容量保证仍需连到一次性项目来源和所有恢复/重置路径。
- 后续可从EC664的59AC调用追成长累计值增加/扣减资源；从描述符显示引用追文本编码；从61EC调用链查发放去重策略。
- 继续只读推进，C匹配与正式字段重命名另行安排独占写入窗口。
