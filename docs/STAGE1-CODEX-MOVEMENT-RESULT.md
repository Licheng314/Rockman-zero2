# 阶段 1 · Zero 的输入与基础移动

2026-11-07。范围是美版原 ROM（SHA1 `c4d93a58f0f82c526dec8a3fdbda170336303689`）、普通难度、序章同一个平地场景和同一套装备。实测从原 ROM 冷启动到达场景，再从同一份内存快照重放各组按键。采样单位是一次模拟器更新。

## 从按键到角色

1. [按键采样](semantic-input-state.md)把通道 0 的当前按住位图放在 `0x02000D10`。正常可控场景下，[输入路由](../asm/sub_0801B730.s)以 `0x7FFF` 掩码把它转到 `0x0202EC34`。脚本控制可以覆盖这层输出，详见[脚本控制](semantic-script-control.md)。
2. [角色更新](../asm/sub_08023420.s)先调用[角色输入映射](../asm/sub_0801EAF8.s)。后者按 `+0x10` 选择 `0x0202EC34` 或 `0x0202EC36`，把结果映射到角色自己的输入历史，再计算新按下的位。实测默认映射中，右键是 `0x08`，跳跃是 `0x20`，冲刺是 `0x40`。持续按住时，新按下位会清除，历史里的当前样本仍保留按住位。
3. 角色更新在 `0x080234CC` 附近按 `+0x0D` 分派动作判定，表在 `0x08333D6C`，地面索引 0 指向 [0x08023698](../asm/sub_08023698.s)。该函数再按 `+0x0E` 分派，站立入口 [0x080236EC](../asm/sub_080236EC.s)先检查是否仍有地面支撑，再检查跳跃边沿、冲刺请求和左右输入。冲刺请求经 [0x0801E91C](../asm/sub_0801E91C.s)判定，并须通过 [0x08031830](../asm/sub_08031830.s)的地形检查。后者失败时会恢复探测前的位置。跳跃判定在该冲刺分支之前。
4. `0x080234F8` 调用动作执行分派，表在 `0x08333D8C`。地面执行入口 [0x08025084](../asm/sub_08025084.s)再按 `+0x0E` 选择站立、走路或冲刺。空中由 [0x08025A3C](../asm/sub_08025A3C.s)继续按子状态分派。通过表找到的 Thumb 函数指针最低位为 1，本文函数地址已去掉该标志。

## 主人公字段

下表偏移相对实测场景中的活动 Zero 实例 `0x02037CF0`。这些字段在本轮按运行时字段使用。跨关卡实例地址和存档持久性未验证。

| 偏移 | 宽度 | 含义和已查到的读写入口 |
| --- | --- | --- |
| `+0x0D/+0x0E/+0x0F` | 各 8 位 | 主状态、子状态、动作执行阶段。实测地面主状态 0，空中主状态 1。地面子状态 0/1/2 对应站立/走路/冲刺。空中子状态 1/2 在本样本对应上升/下落。主更新和各动作分派读取这些值，动作判定与执行分支写入。 |
| `+0x10` | 8 位 | 角色输入映射读取的通道选择条件。本场景一直为 0，走第一路。 |
| `+0x195/+0x196/+0x198` | 8 位 / 8 位 / 64×8 位 | 环形输入索引、相对上一次的按下边沿、归一化输入历史。由 `0x0801EAF8` 更新，地面动作判定读取。 |
| `+0x54/+0x58` | 各有符号 32 位 | X/Y 位置，256 个原始单位对应 1 像素。地面走路执行把 `+0x5C` 加到 X，空中上升路径把 `+0x60` 加到 Y，碰撞分支可再修正位置。 |
| `+0x5C/+0x60/+0x68` | 各有符号 32 位 | X/Y 速度和纵向加速度，同一 256 倍定点比例。普通起跳初始化写 `+0x60` 和 `+0x68`，之后由空中更新消费。Y 减小表示向上。 |
| `+0xC4` | 32 位 | 动作设置的横向速度参数。走路初始化和后续执行、地面冲刺初始化都会写它。它和实际 X 速度 `+0x5C` 分开，原地起跳时可见 `+0xC4=512` 而 `+0x5C=0`。 |
| `+0x17F/+0xCC` | 8 位 / 32 位指针 | 实测地面冲刺期间分别为动作编号 3 和非零残影对象。速度阈值与对象创建/释放逻辑在 `0x08023420` 后半段。地址 `0x03007738` 是本次运行中的对象实例。 |
| `+0x184` | 8 位 | 普通地面冲刺计数器，由 `0x08025640` 写入 28。持续按键样本中每次更新减一，第 28 次归零。 |

## 三条动作路径

- **走路。** [0x0802538C](../asm/sub_0802538C.s)的站立起步分支把 `+0xC4` 设成 `0x80`。随后 [0x08025400](../asm/sub_08025400.s)和 [0x080254C8](../asm/sub_080254C8.s)可设成 `0x200`，另有配置条件下的 `0x280` 分支。序章实测起步每次更新 0.5 像素，进入稳定走路后每次 2 像素。
- **起跳。** 地面判定置空中状态，空中初始化经过 [0x08025A54](../asm/sub_08025A54.s) → [0x08031910](../asm/sub_08031910.s)。按前一主状态分派的表 `0x083344AC` 在地面索引 0 指向 [0x08031934](../asm/sub_08031934.s)。普通起跳分支检查跳跃边沿和地面标志，再把向上初速度写到 `+0x60`、`0x40` 写到 `+0x68`。无该分支的环境修正时，`0x080319AA` 的立即数 `0xA0` 左移 3 位，取负后得到 `-1280`，即 −5 像素/更新。实测第一步 Y 减少 5 像素，随后采到速度 −4.75，最高上升 52.5 像素，第 41 次更新落回原高度。
- **地面冲刺。** [0x08025604](../asm/sub_08025604.s)分派到[冲刺初始化 0x08025640](../asm/sub_08025640.s)，把 `+0xC4` 设为 `0xE0 << 2 = 896`，普通分支设置动作编号 3，并把 `+0x184` 初始化为 `0x1C` 后进入冲刺更新。这是计数器初值，完整可冲刺时长还取决于退出条件。实测右向冲刺每次 3.5 像素，残影指针非零。松开冲刺继续按右，下一次更新回到走路，速度降至 2，残影指针归零。只按冲刺也能进入原版地面冲刺，本样本向左移动。

## 原版复测与接续

每组从同一站立快照开始。下面的原始位只列本组相关低位。

| 输入 | 原始位与角色边沿 | 第一条可辨动作结果 |
| --- | --- | --- |
| 按跳跃 | 原始 `0x001`，角色边沿 `0x20` | 状态 `[1,1,0]`，Y 减少 5 像素 |
| 按右 | 原始 `0x010`，角色边沿 `0x08` | 状态 `[0,1,1]`，X 增加 0.5 像素 |
| 按右和冲刺 | 原始 `0x210`，角色边沿 `0x48` | 首次状态 `[0,2,1]`，X 增加 3.5 像素，残影对象存在。持续按住时，第 28 次仍移动 3.5 像素并切入走路状态，第 29 次速度降至 2，残影对象释放。 |
| 跳 6 次更新，再改按右和冲刺 8 次 | 第 7 次角色收到 `0x48` | 与「跳 6 次后仅按右」逐次对照，位置、速度、重力、动作阶段、动作编号和残影指针都一致 |

最后一组两个对照都松开了跳跃，因此两边同时进入下落，不能把这个转变归因于冲刺键。此结论限于该普通跳跃样本。

本机从工程根目录运行 `python -B build/stage1-codex-movement/probe-original-movement.py` 可复跑。脚本调用已有的 `build/air-actions/probe.py` 和本机 mGBA 核心，校验原 ROM SHA1，输出逐次采样 JSON。结果保存在本机 `build/stage1-codex-movement/original-movement-trace.json`。

## 冲刺遇阻的两条路径

[冲刺更新 0x080256C4](../asm/sub_080256C4.s)先调用 [0x08031830](../asm/sub_08031830.s)检查地形。按静态控制流，预检失败时，`0x080257AC` 将本次横向速度和局部退出判据置零，跳过计数器递减。之后如仍有地面支撑，按当前方向键转走路或站立，失去地面支撑则转空中。这个预检失败分支本轮没有运行断点样本。

预检通过时，冲刺先递减计数器，再应用横向速度并调用碰撞修正 `0x0801F5F4`。修正结果命中掩码 `0x4F` 会清零 `+0x5C`，随后仍按地面支撑和局部计数值决定状态。也就是说，位移受阻和退出冲刺是两件事。

从原版同一站立快照出发，先按方向走若干次更新，再保持方向并按冲刺。两个地形边界样本如下：

| 输入 | 首次横向受阻 | 当时的状态 |
| --- | --- | --- |
| 向左走 48 次，再按左和冲刺 | 冲刺第 21 次，X 被限制在 1214 像素 | 横速从 −3.5 降为 0，状态仍为 `[0,2,1]`，计数从 8 减到 7，残影对象保持 |
| 向右走 120 次，再按右和冲刺 | 冲刺第 5 次，X 被限制在约 1569.996 像素 | 横速从 3.5 降为 0，状态仍为 `[0,2,1]`，计数从 24 减到 23，残影对象保持 |

两个样本随后都原地维持冲刺，计数继续递减。第 28 次计数归零并转入走路，第 29 次释放残影。逐次字段变化与汇编中的「预检通过后碰撞修正」路径一致。本轮没有抓取逐指令运行轨迹。探索中另有左向样本进入状态 `[7,1,1]`，本报告未把它计作地形碰撞。

本机复测入口为 `python -B build/stage1-codex-movement/probe-dash-wall.py`，逐次记录见本机 `build/stage1-codex-movement/dash-wall-trace.json`。两次独立启动的输出逐字节一致。斜坡和其他形态未实测。阶段路线中的参数修改验收另行记录。
