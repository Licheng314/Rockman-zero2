# 父对象关联计数CC、接近信号DB与交接结果C1

本轮连接[动作选择器](semantic-parent-action-selector.md)读取的CC/DB和[缩放桥接](semantic-parent-form-bridge.md)读取的C1，深化既有21单元。[原ROM证据](semantic-data/parent-associated-signals-evidence.json)保存9个函数644条局部可达指令和5段限定表。基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。偏移、类型和状态为十六进制；次数及区间数量为十进制。

字段现有证据不支持统称为受击标志：CC在本链是成功创建后增加、相关对象退场/交接后减少的u8计数；DB由关联对象处于父对象附近时置1；C1由另一关联对象的交接结果写0/1。仍不把这些局部用途声明为所有写入者的穷尽清单。

## 池与类型编号必须一起识别

79C14使用0202F078对象池及0833D990类型表，创建类型22；工厂写所属对象到+28、坐标到+54/+58、子类型到+10、参数到+11。该池中的类型22生命周期表0833FF80为79C7D/79F89/79FA1/65A05/06C29，更新子类型1和2均指向7A128。

77FB0也使用本对象体系，创建类型20；其更新分派780A8的基表0833FDD0中，子类型3→792D5。下文交接对象S为这一类型20/子类型3，交接目标V可以是上述类型22。

这不等于初始化A2CF8创建的“类型20”辅助对象：后者使用另一类型表08343064和另一对象池。类型编号只在各自体系内解释，不能因都为20就合并结构或生命周期。

## 52E18：三次机会，成功才计数

首次进入时选择动画A60F、CD=0、CE位图=0、计数+12=0，并推进共享0202E188随机种子，以high%3写C2。它没有在这里清CC，CC来自初始化和关联对象生命周期。

每次先把+12加一，并提交强度1的震动请求。计数为2、10、42时，只有CD<=2且CC<=5才尝试一次生成；计数88时阶段E加一并清F。以上计数为十进制，计数16的倍数还请求声音96。

生成位置来自579B4；若C2为0则以子类型2调用79C14，否则用子类型1，第四参数0。返回非NULL时才CC++、CD++。无论分配成功还是失败，都置CE对应位置位，并令C2=u8(C2-1)。因此初始C2为0/1/2时，三次机会的子类型序列分别是[2,1,1]、[1,2,1]、[1,1,2]；失败也推进序列，不立即重试。

CC达到6会阻止后续生成机会；CD只计本轮成功数，CE记录本轮尝试的位置，两者不能互换。CC的增减没有饱和保护，不能用“合法计数通常很小”改写成自动夹到0～6。

## 579B4：位置避重是有限搜索

助手再推进一次随机种子，以high%6取得起始位置。B5为0时最多检查3个位置，其余最多4个；顺序为(start+i)%6。CE对应位为0就选中并停止。

若检查额度内全部位置已占用，仍返回最后检查的位置，并据此写坐标，不返回失败标志。通常本生成周期最多三次机会且CE从0开始，不会自然构成“所有六位均占”的状态；完整位图边界是接口行为核对，不是游戏中已观察到的异常。

位置X=P+B8+[4,44,84,124,164,204]像素，Y=P+BC-160像素。助手本身只读CE、不占用位置位；实际占位由52E18在工厂返回后执行。返回值是0～5的位置索引，不是成功bool。

## 7A128：DB是包含端点的父对象接近信号

类型22子类型1/2的更新先读取父指针P=child+28。若子对象状态+8C有200位，或父不存在，或父生命周期字节+C>1，走停用路径：父存在则u8(P+CC)减1；子对象生命周期置2、回调取79FA1，清碰撞相关字段和A的04位，并同次调用79FA0效果处理。效果处理本轮只记录调用，没有执行完整退场特效或最终池释放。

正常活跃时，以父u16(+D2)为横向半径R，实际条件为：

```text
unsigned32(parentX-childX+R) <= 2*R
unsigned32(parentY-childY+0x4000) <= 0x8000
```

对正常坐标差，等价于横向绝对差<=R、纵向绝对差<=64像素，端点包括在内。满足才写P+DB=1；不满足时不清DB，保留既有值。这里不比较全局玩家坐标，也不要求父已受击，不能命名为“本次被玩家命中”。

之后还调用7A60C并进入子对象运动/交互处理。本轮范围测试将这些后续运动作为钩子，未验证其完整坐标演化。上层51728在主状态处理返回后清DB，选择器573FC则在CC和DB均非零时才考虑临时1B覆盖；二者连接成“关联对象仍计数且有近旁信号”的局部条件。

停用时CC=0会减成255。正常回调切换阻止继续按活跃处理器重复扣减；该函数不是可任意重复调用且只扣一次的独立归还接口。本轮不把构造边界自动认定为实际游戏缺陷。

## 792D4：C1在交接调用之前写入

此处理器持有父P=S+28和交接目标V=S+2C。父生命周期>1或主状态9/12时提前停用S；目标已非活跃时会清S+2C。只有交接阶段的返回计数减到0、且V仍存在，才执行本轮核对的交接分支。

V子类型+10==2时写P+C1=1，否则写0；随后调用A2100(V,&S位置,u8(S+11+5或+3),反向朝向位)。C1写入发生在调用之前，且本段不依据A2100返回值修改它。由此不能说C1证明后续生成已经成功。

接着停用V、置其生命周期3/退场回调，P+CC减1，再停用S并置生命周期3。这里不会继续执行V的正常7A128更新；完整调度仍需尊重新的回调，不能强行再次扣CC。

该写入连接已有53874分流：只有旧B4==1A等相应条件成立时，C1非零才把退出选择导向状态14；C1为零走573FC。不是任意时刻C1一变1就立即变形，更不是全局永久成功标记。

## 验证与接续

[可重放脚本](semantic-data/parent-associated-signals-check.py)通过3072组位置位图/搜索边界、120个完整88次更新生成周期、210组接近端点、48组退场计数和108组交接条件，共13998次局部调用。原ROM执行位置助手、52E18、79C14/06B84、7A128和792D4对应分支，核对工厂请求、真实成功数、链式计数、随机推进、C1/DB保留与写入。

取余助手对已验证的非负操作数建模；图形/声音/震动、子对象后续运动、79FA0效果及A2100交接为空操作或记录。没有执行真实子对象初始化、完整碰撞/游戏调度或最终释放。测试不能据此推断视觉角色身份、全关卡事件频率或完整资源效果。
