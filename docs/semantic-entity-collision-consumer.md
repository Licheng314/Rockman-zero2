## 23420更新中的参考位置并不固定

关键顺序如下；外部助手的其余游戏语义未在此全部展开：

1. 先把E+54/+58保存为局部entryPosition，然后调用前置助手。
2. 若此时读取的u8[E+D]==0，调用1F478(position,C)应用已保存动态id对应的贴边/带动。
3. 当(E+C字&00FFFF00)!=00020700且状态<=7时，经08333D6C[state]执行前阶段回调，返回u8用于下一阶段分派。
4. 将entryPosition写E+B4/+B8，再把当前位置保存为局部beforeMainPosition；将C+0复制到C+4，然后调用08333D8C[选定状态]主阶段回调。
5. 重新读取u8[E+D]，若<=3则调用08333DC4[state]后阶段回调。它可能使用主阶段刚更新的状态，而不是继续沿用旧索引。
6. 后阶段结束，把beforeMainPosition写E+B4/+B8，再调用后续助手，执行两项边界检查。
7. 更晚的路径将当时当前位置复制到E+BC/+C0；后面仍有分类/效果助手，未把该点武断等同函数最终位置。

所以E+B4在主/后阶段内是更新入口的快照，阶段结束后又变成主阶段前的快照；E+BC则由较晚阶段复制。不能将两字段都命名为固定“上一帧位置”。C+4也只是此时复制的形状指针槽，不直接证明它必来自前一个显示帧。

分派表证据对前阶段保存8项、后阶段4项，均有调用点范围判断；主阶段只保存前8项作为观测前缀，不据相邻数据猜全表长度。23420在主阶段调用前没有同样的现场上限检查，合法状态域需由其生产者保证。

## 真实边界调用补正五参数接口

23420后部实际调用：

```text
1F1FC(position,C,C.shape,faceBit,1)
1F2E8(position,C,C.shape,faceBit,1)
```

faceBit来自(u8[E+A]>>4)&1；应用开关1在第五参数。1F2E8的face槽在可达体不使用，先前研究文档的四参数简写已修正为五参数，已解分支行为不变。横向两端与纵向一端的应用差异仍遵循[仲裁报告](semantic-vertical-arbitration.md)。

## 251C0：先积分X，再水平修正，再检查支撑

251C0先读E+5C和已有u16[C+C]，传给1E7B4；返回值写回E+5C。这里把1E7B4视为速度更新助手，不在未展开全部分支前假定它总做同一种摩擦。

若更新后的vx非零：

```text
E.x += vx
1F5F4(&E.position,&E.referenceB4,C,shapeA,shapeB,
       faceBit,vx,1,0,0,1)
```

形状A/B来自C+0/+4。水平选择包装的pad=1，只有一个最小定点单位，不能误称1像素；policy=0、collect=0、apply=1。返回结果与004F相与非零才把E+5C清零，不是所有非零碰撞结果都清速度，单独的动态80标记也不满足此掩码。

不论vx是否为0，随后都调用：

```text
1F57C(&E.position,&E.referenceB4,C,shapeA,shapeB,
       faceBit,0x800,0,0,1)
```

这是正向纵向查询：pad=800（8像素），policy=0、collect=0、apply=1。251C0不使用其返回值另作状态分支。该流程并不在此把E+60加到Y；不能把它描述成统一完成两轴积分的移动函数。

## 25258：类似参数，但明确消费支撑结果

25258先按E+F选择另一个子回调，然后对当前vx非零路径执行同样的X积分、水平包装及004F速度清零。之后使用同样的8像素pad进行正向纵向查询。

若返回结果低四位为0，则把旧E+D保存到E+174，写E+D=1；把旧E+E保存到E+175，清u16[E+E]，并转存/清理其他状态字节后调用25A54。这里可确认“低四位为空触发另一状态”，但仍不把具体状态1命名为某种已验证的玩家动作。

返回低四位非零则走后续显示/声音条件。是否有接触由这个消费者检查低四位，不等同“整个u16非零”，也不等同底层几何助手的位移非零。251C0与25258即使传参类似，也不是同样消费返回结果。

## 1F5F4→1F9C0如何按速度选水平通道

1F5F4先用C首两个指针补NULL形状参数，再原样转交1F9C0，返回值截为u16。正常朝向/速度域：

| face | motion | 选用 |
|---|---|---|
| 0 | <=0 | 1FA30，通道0 |
| 0 | >0 | 1FC60，通道1 |
| 非0 | >=0 | 1FA30，通道0 |
| 非0 | <0 | 1FC60，通道1 |

motion为0总选通道0；face=0的原指令先取负再比较，极值溢出仍按原32位行为，不泛化为无限精度乘法符号判断。motion用于这里选择通道，并不直接作为pad传入：该样本独立把pad=1转交下一层。

## 前阶段也可能执行支撑检查

前表状态0指向23698。该入口以E+BC为参考位置、同样pad=800/policy=0，但collect=1、apply=1，先调用1F57C，再按E+E查下一张子表。

因此一轮顶层更新中可能先有前阶段支撑检查，主阶段运动处理又查一次；两次参考位置及collect并不相同。不能仅因两个查询出现在同一更新就当作重复调用删去。动态带动也可能更早已执行，entryPosition快照仍是其前保存的值。
