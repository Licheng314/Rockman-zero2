# 实体动作历史与交互计数的输入事件依据

2026-10-30。连接第16单元输入控制和第21单元交互计数，累计仍21研究单元。地址、偏移、掩码均为十六进制。[原ROM证据](semantic-data/entity-action-history-evidence.json)包含8个函数、类型0分派首项及两个预设配置，基线SHA1为c4d93a58f0f82c526dec8a3fdbda170336303689。

## E+196确认为动作新出现位

1EAF8读取实体动作环形历史的上一条值，生成当前动作字节后，写入：

```text
u8[E+196] = current_action & ~previous_action
```

它是实体级动作的上升沿，既不是地形接触标志，也不是直接复制硬件pressed字段。此前 [交互计数报告](semantic-entity-interaction-counter.md) 的370D8正是读取这个字段计算衰减步长，因此在已分析的27FC0/285E8入口中，计数与动作输入事件有关，不能直接解释成按更新次数减少的持续帧数。

## 从控制字到动作字节

1EAF8先经1EBDC按u8[E+9]分派取得配置指针。已验证08333AC0的第0项为0803712D，进入3712C：模式u8[E+1F4]为0/1时用083347A0起的16字节预设，为2时用实体E+1E4自定义配置。其他模式本函数不钳位。

然后根据E+10是否为0，读取G=0202EC30的u16[G+4]或u16[G+6]。这是 [场景控制报告](semantic-script-control.md) 中经过脚本覆盖的held控制字，不是02000D10记录内部的+4按下边沿；两种+4不可混用。

1EBAC遍历配置的8个u16掩码，构造动作字节：

```text
mapped = OR(bit(i) for i=0..7 if (raw_control & config[i]) != 0)
```

只要求任一位重合，不要求配置掩码的所有位同时成立。自定义配置可让同一按钮同时产生多个动作位，也可能包含高位控制标志，不能假设是严格单键的一一映射。

类型0两个预设中，动作01/02/04/08分别映射Up/Down/Left/Right；10映射B，20映射A。预设0的40/80映射L/R，预设1相反。这里只确认按钮和动作位关系，不凭常见操作习惯为10/20/40/80命名游戏动作。

## 类型0后处理会保留历史位

1EAF8再按08333ABC[u8[E+9]]选择动作后处理，通过EF124的bx r4调用。类型0首项是08036C81，参数为(E,raw_control,mapped,previous_action)。036C80行为是：

- raw_control未含8000：直接返回mapped的低8位。
- 含8000：把mapped的10位替换成previous_action的10位。
- 含8000且u8[E+1F5]==1：还把80位替换成previous_action的80位。

所以脚本覆盖标志不等于所有动作都强制清零，也不等于全部照新映射更新；部分动作可以保留上一条历史值。两个被保留位在这次更新中不会产生上升沿。此处的E+1F5也与370D8是否保留第五项衰减权重相连。

## 64条环形历史的精确提交

在正常游标0..3F域，1EAF8按以下顺序执行：

1. 读取i=u8[E+195]与old=u8[E+198+i]。
2. i=(i+1)&3F，并写回E+195。旧值读取发生在屏蔽之前，不能把任意损坏游标当成安全输入。
3. 取得配置、选择控制字、执行映射和类型回调，得到current低8位。
4. E+198+i=current；E+196=current&~old。
5. 清除E+1D8或E+1DC中对应i的位：字偏移为4*(i>>5)，位号i&1F。
6. 将E+197写FF。

因此E+198..1D7为64个动作字节，E+195指向最近写入项。E+1D8/+1DC是每槽的附加位图，E+197在输入更新时重置；后续[历史识别报告](semantic-entity-history-recognition.md)已确认1EC5C使用它们做成功槽标记与模式缓存，其他消费者仍未穷尽。

1EAB0先把游标清0，调用一次1EAF8，此时游标变1；再把刚生成的动作值填满64项，最后将E+1D8和E+1DC清0。它没有在填充之后另行清E+196，不能仅凭“初始化填满同值”就断言返回时新动作位一定为0。

## 与实体更新和计数的关系

23420在状态阶段处理之前调用1EAF8，之后才调用37338、1EA94及各状态回调。因此这条真实调用链在状态处理前已准备新动作位。仍不将一次函数调用等同于固定屏幕帧或固定毫秒。

对已分析的两种交互计数入口，步长k是E+196的五组非零条件之和：方向低半字节合为一组，10/20/40各一组，80仅在E+1F5==1时另算一组。方向四位同时新出现也只贡献1，不是4；只释放动作不会产生这些上升沿。

在配置与类型处理结果不变、没有其他写入者介入时，同一动作持续按住的相邻两次动作值相同，E+196为0，这两个计数入口本次步长就是0。释放后再次按下可重新产生事件。配置或脚本合成输入改变，也可能产生新动作位，故不能直接将这些事件全部当作玩家物理按键次数。

这些结论限于已跟踪入口，不否定其他状态会直接清除或改写计数；也不据此给持续交互命名具体游戏行为。
