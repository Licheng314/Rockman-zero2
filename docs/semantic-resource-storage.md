# 储量槽与逐点恢复：只读语义研究

日期：2026-10-29。后台 batch_extract 持续运行；本轮只读取已有源和 baserom，未运行匹配、集成、split、Verify，未修改正式源码、段清单或后台状态。本文件独立于后台自动更新的 HANDOVER 和 research-notes。

## 结论及可信度

指令级已确认：实体 +0x1FC 的20字节记录包含上限参数、标志、两组已拥有槽位数及四个单字节储量。每组最多2槽，每槽上限30。使用时储量减1，同时实体+0xA4的有符号16位值加1，达到动态上限或储量为0时终止。另有按组/槽扫描、每次加1的补充助手。

高可信语义推断：这是生命值的储能／恢复槽机制，类似储能罐。上限升级、使用菜单、逐点恢复和耗尽处理共同支持该解释。尚未由游戏运行画面或已确认文本ID互证，因此本轮不将正式符号重命名为 SubTank，也不将两组的来源强行命名为特定道具或精灵。

## 地址和布局

以下 R = entity+0x1FC。

| 地址 | 操作级含义 | 证据 |
|---|---|---|
| entity+0xA4 | 恢复操作的目标16位数值 | E912C增加；D6ED0升级时增加并钳位 |
| R+1 = entity+0x1FD | 基础上限 | 37A3C读取；D6ED0加4且最大32 |
| R+6 = entity+0x202 的bit0 | 上限翻倍标志 | 37A3C、D6ED0 |
| R+7 | A组获得去重位图起始字节 | 31294 |
| R+8 / R+9 = entity+0x204 / 0x205 | A/B已拥有槽数 | 3126C、31294、312D0 |
| R+0xA..0xD = entity+0x206..0x209 | 四个槽的储量 | 37AF8、37B24、389D0、E912C |
| entity+0x17E | 数值镜像，至少升级路径会同步 | D6ED0 |

ROM 0x083359A4 起两字节为 02 02，0x083359A6 起两字节为 1E 1E。389D0同时引用两个表，分别用于组物理跨度和每槽储量上限。这两种容量不能混为一谈。

## 已还原操作（说明性伪代码，不是匹配C）

### 上限和升级

37A3C(entity)：result=R[1]；若 R[6]&1 则 result*=2；返回低8位。

22AF0(entity)：根据 entity[9] 查 ROM 0x08333B58 的函数指针表，经 EF118 间接调用并返回低8位。表第0项0x08037A3D指向37A3C；第1项0x08037A5D为返回1的小函数。故上限不能对所有实体种类硬编码为37A3C。

D6ED0：在 R[1]<=31 时，R[1]=min(R[1]+4,32)，当前值加4或8（取决于翻倍标志），再钳位到37A3C给出的上限，写回16位当前值及entity+0x17E的字节镜像。32/64是此升级路径下的正常上限，并非所有实体所有状态的无条件上限。

### 编号与两组布局

3126C / 37A60 返回两组已拥有槽数之和的低8位。

312EC 把1基逻辑序号映射到0基物理槽号。物理A组固定占槽0/1，B组固定占槽2/3，即便A组未满也不压缩B组的物理起点。正常计数域0..2中：countA=1,countB=1时逻辑1→物理0，逻辑2→物理2。越过总数返回-1；序号0也经末尾减1返回-1。调用者应保证计数字节有效。

37AAC包装编号映射；37ABC返回映射结果所属组；37AF8读取储量、失败返回-1；37B24返回储量地址、失败返回NULL。后两者ROM池常量分别位于0x08037B20、0x08037B48，均为0x206。

31294：A组同一id去重、槽数小于2时增加数量并清零新槽。未证实id的合法范围，不能删除id>>3，也不能把访问R+7+(id>>3)简化为唯一字节。312D0：B组数量小于2时增加数量并清零新槽，无同样的id位图参数。

### 单位补充：389D0

1. 全局0x0202EBB0+4的bit1置位时直接返回0。
2. 没有已拥有槽位时返回0。
3. 按A组、B组顺序；每组只遍历已拥有数量，组起点按固定跨度2前移。
4. 第一个低于该组上限30的槽储量加1。加后仍未满则调用1E6AC(0x20)，返回1；恰好加满则调用1E6AC(0x21)，返回0。
5. 已有槽全部满则返回0。因此返回0不等于没有补充，恰好填满最后一点也会返回0。声音/事件函数1E6AC在本轮尚未独立鉴定，保留数字调用。

自动汇编中389F0、38A5C等真实指令曾标成gap。上述控制流额外核对了原ROM明确分支落点，不能只看已渲染的助记符。池数据仍按数据处理，不将随意线性反汇编的结果当代码。

### 菜单入口、选择、逐点使用

E8FCC：逆序遍历逻辑槽位并累加储量；读取entity+0xA4和22AF0上限。当前值未满且总储量非0才进入交互状态，选择索引初始化为0，调用DA938(context,4)。否则退出并返回0。遍历是先执行后判断；总槽数为0时不能认定安全，本函数需要上层保证至少一个槽。不要擅自把它改成可接收任意状态的通用接口。

E9050：仅当传入状态的低字节按有符号解释大于0时处理输入。全局0x02000D10+4提供按键位；bit0/bit1走确认/取消，确认只允许非空储量。bit4/bit5走循环选择，用EF330对总槽数取模，跳过空槽。此循环依赖至少一槽非空；入口E8FCC提供该条件。仅凭这一函数不能承诺全空状态时终止。方向、键名和EF330库函数的正式名称尚未独立验证。

E912C：计时字节context+6减1；到期时选中槽储量减1，entity+0xA4加1，调用032EC(0x1F)。当前值>=22AF0上限或储量变0时清context+1并调用37B4C排序；否则context+6=4。后续还存在独立的全局标志检查与E96DC调用，不把该后续处理当作恢复逻辑的一部分。使用路径依赖确认阶段保证选中槽非空，否则字节减法会下溢。

3133C / 37B4C：每组已拥有数>1时，对该组固定容量范围做降序选择排序。当前容量=2，正常计数下仅满组触发。排序只交换储量，不改变槽位拥有数量与去重位图；因此不能用物理槽号恒定代表某个特定来源id。

DB644：按逻辑显示索引+1取得物理槽；根据组号选择0x0834BC5C或0x0834BC44半字表，储量非零时经EF2B8(value,3)+1取得显示档位；零值单独为档0。后交127E4/128D4。与菜单渲染关系吻合；EF2B8的除法语义需单独核实，不能仅凭参数3断言商或余数。

## 初始化与快照的新证据

31738 将entity+0x1E0传给30F5C；参数根据R[0]==9选择0/1。

30F5C把传入基址+0x1C视为R：模式0使R[1]=16、R[6]=0、R[7]=0、两组计数为0；模式1使R[1]=32、R[6]=0x3F、R[7]=0xFF、两组计数从02/02容量表取得。316B0接着把四槽储量置0或30，并清R[0xE..0x10]。模式1因此有四个满槽以及翻倍标志。R[0]==9的游戏模式含义尚未确认，不直接叫作某个难度或角色名。

30E68在可恢复快照存在且快照首字节为0时，将快照+0x1C的20B、+0x30的24B、+0x48的100B分别复制回entity+0x1FC、+0x210、+0x228。否则调用默认初始化链。之后重新计算上限写entity+0x17E。它并不在这条路径直接恢复所有172字节；快照前0x1C字节由其他路径处理，不能把30E68称为完整快照反向复制。

D5790操作的是entity+0x20A起的相邻项目数据，并非四槽储量起点0x206。虽然被某些相邻路径调用，本轮不将其错误命名为储量清理。

## 本轮继续核实：数学助手与间接表

原ROM逐指令核实EF2B8：无符号比较和移位减法长除法，商累计在r2，返回前r0=r2。因此它是无符号整数除法；除数为0时调用EF1E4，然后返回0（不对EF1E4是否返回作额外保证）。DB644显示档位现可写作：储量为0→档0，否则档=floor(储量/3)+1。正常0..30储量对应档0..11。

EF330：同样采用无符号比较和移位减法，返回保留在r0的余数；r0<r1路径直接返回原r0。它是无符号取余。E9050循环选择可表达为 index=(index+step+slotCount)%slotCount，step=+1或-1；在正常1..4槽范围内，加slotCount保证减1路径非负。不能推广到损坏计数或零除数。

补充函数389D0的Thumb指针0x080389D1在整个ROM中出现于0x08333B9C。它靠近0x08333B58起的一组接口指针，但本轮未确认接口表边界、步长和上层所有者，不能把邻接指针一律解释为同一函数的不同实体类型实现。22AF0的确执行table[entity[9]]间接调用；该索引的合法范围仍需追踪。
