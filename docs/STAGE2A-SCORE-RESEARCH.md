## 分项与符号语义

结算工作区 `0x0202EBF0`，累计记录由其首字段指向（本样本 `0x02036BB4`）。分项计算函数 `0x080141FC`。下面是静态读法，只有复跑样本中的输入经过运行对照，不代表全部边界已验证。

| 项 | 输入/结果 | 公式或范围 |
| --- | --- | --- |
| MISSION | 工作区 +7 / +16，u8 | 原加分值入总分；任务专属重算另有依赖 |
| 时间 | +8 u32 / +17 u8 | 计数/60 得显示秒；超出任务阈值 e≤0 为20，1..199 为20-ceil(e/10)，更大为0 |
| 击破 | +0xC u16 / +18 u8 | q=击破/(死亡+1)，q=0 为0；n=任务目标数×10/q，n≤10 为15，n>24 为0，否则25-n |
| 受伤 | +0xE u16 / +19 u8 | d=0 为15，d>75 为0，否则15-floor((d-1)/5)；输入是伤害请求累计，非严格实际损血和 |
| 重试 | +0x14 u16 / +1A u8 | 0 为15，1..4 为15-3n，大于4为0 |
| 精灵点数 | +0x10 u32 / +1B 字节 | max(-100,15-点数)，写入字节；显示可为负 |
| 本关 TOTAL | +5 字节 | 六项相加写低8位；**随后按 s8 读回加入累计记录** |
| 累计及等级 | 记录 +A 半字、+10 次数、+1 等级 | 累计相加写低16位，评定时按 s16 读取累计并有符号除以次数；等级阈值46/56/66/76/86/96，0..6=F/E/D/C/B/A/S |

原报告漏写了 TOTAL 的 `ldrsb` 与累计的 `ldrsh`，不能把所有回绕字节都当正数累计。新增边界：精灵点数68→TOTAL字节0/累计0/F；69→字节255/**累计-1**/F；115和116均因-100下限得到字节209/**累计-47**/F。上述大点数是边界夹具，不证明自然游戏能获得该点数。原“5组断言全过”也不等于这些边界已测。

基线样本：时间计数3676，击破5，受伤58，死亡2，精灵0；六项20+20+0+4+9+15=68，LEVEL C。画面完整称号为 LIGHTNING GUNMAN，本轮不对全部称号映射作验收。

### 当前可用字段与精确时机

- 六分项公式以本文件前表为准。击破 `q=0` 直接得 0 分，避免除零；分支阈值为 `n>24`。六项实际使用 `ldrb` 相加、写低8位，再把总分按 s8 读回加入低16位累计；评定累计时按 s16 读取。不能把指令说成六次有符号加载。
- `0x0801CE5C` 分支索引0依次经过资格门 `1DA44`、其它结算条件、精灵聚合 `D61B8`、评分 `141FC`（内部调用称号分类 `14384`）；索引1等待过渡，索引2显示，索引3等级显示，索引4发 EX。原 S1 的首个状态编号偏一，不能照抄为状态1/2。
- 任务字段固定为 `u16[0x0202EC30]`，循环变化的是 ROM 表索引，**不是** `byte[EC30+i]`。任务表/条件表/掩码表分别按 u8/u16/u32 读取；玩家拥有 EX 掩码在 `+0x216` **按 u16 读写**，不覆盖紧邻的 EX 装备字段。
- EX 资格读取结算前等级 >4，并先保存条件位；当关新分数随后改变等级，并不自动重新决定同一次资格。修改后的等级对后续机会的影响须按流程检查，不能直接承诺当关补发。
- 精灵使用计数 `记录+0x4C` 在旧值≤98时加1，故可到99。拥有位、使用记录、惩罚队列和效果字段应分别保留；当前少数样本不证明所有效果完全独立。队列 `+283` 写回按 u8 截断。
- 称号分类的 `记录+2` 不是 `记录+1` 等级。`14384` 根据分项按分支顺序选类别；四项收集量以总和70%的阈值选桶，更新对应连续记录后按 `表[桶*8 + 连续次数]` 生成称号索引。S1 的简化“新等级”公式撤回，本包不把称号全集算作运行验证。

### 最小改动候选及适用限制

| 候选 | 能改变什么 | 必须保留的限制 |
| --- | --- | --- |
| P1：在 `0x080D61DA` 把返回赋值 `201c` 改成 `mov r0,#0`（`0020`） | 永久开关版本可用一个半字抑制 D61B8 这一次聚合贡献，队列滚动指令仍执行 | 调用者把返回值**加到**既有 `u32[EBF0+0x10]`，不是赋值；已有值非零时不能保证 ELF=15。两字节只能实现无条件替换，不包含运行时开关 |
| P2：记录端不再添加惩罚 | 改变未来进入队列的惩罚历史 | 过去和未来历史语义不同；不得把停写当作可逆豁免。使用计数/已用标志须另行保持 |
| P3：局部覆盖 ELF 子分项 | 可以只让评分消费者给出15分，同时保留显示的使用点数和原始记录 | 是否应显示实际使用点数属于预期效果，须核对显示、总分、累计与奖励。不能仅因位于评分函数内部就排除 |

本次原始编码扫描仅找到 `0x0801CEF0` 一处 Thumb BL 调用 D61B8，没有 ARM BL/对齐函数指针字命中；这是静态候选扫描，不排除计算地址或间接调用。P1 尚不是已验证补丁。S1“ELF 恒满分、不会历史污染、关闭即恢复原版”的说法均收窄：保留队列不等于重算已累计分数、等级或撤回已发 EX。

若需要游戏内开关，必须由 Codex 找到并验证配置存储/持久性，再设计保持寄存器、栈和原 `pop r4,r5 / pop r1 / bx r1` 返回协议的钩子。S1 的直接 `bx lr` 伪代码跳过了已有压栈清理，不能使用；也没有已证明的任意空闲 RAM 位。存储位置是实现者的责任，不是让用户选择一个地址。

后续只在明确“哪些形态适用、豁免哪些分项/历史影响”后制作改版。由 Codex 自行对照原版/启用/关闭，验证分项、显示、累计、资格时机、使用记录、队列和重开/读档；夹具 68/69/115/116 的“回到68”只属于该固定输入，不是所有关卡的期望总分。本包0新增深入函数，旧12/10记录保留；停止于方案，不自动开评分改版或新任务。
