# 动态碰撞矩形与移动带动

日期：2026-10-29。第20个研究单元，区别于静态RAM地形格。已建立登记、几何查询、历史坐标匹配及实体贴附的连接，并在后续定位14AD8中的轮换入口；历史周期受更新参数控制，不能直接等同显示帧。仅只读代码/原ROM，保存[字段、边界与代码哈希证据](semantic-data/dynamic-rectangle-evidence.json)。

基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。文中的单位为24.8定点，1单位=1/256像素；边界例子为静态推导，不是实时RAM记录。

## 24B记录与31项上限

W=02001000。当前计数u8位于W+1D2，历史计数u8位于W+1D3；当前记录从020011D4、历史记录从020014D4开始，步长18（十六进制，即24字节）。

| 单条记录偏移 | 含义 |
|---|---|
| +0 | u16关联标识id |
| +2 | u16属性 |
| +4/+6 | u16半宽/半高 |
| +8/+C | 当前中心x/y |
| +10/+14 | 对应历史中心x/y；找不到历史时设为当前值 |

099BC(id,attribute,positionPtr,shapePtr)登记一项。shape前8B为s16 dx、s16 dy、u16 width、u16 height，当前中心=position+有符号偏移，半宽/高=无符号宽/高>>1。奇数宽高会丢弃最低位，不能假定采用向上取整。

它先检查currentCount+1<=31，成立才追加，因此最多31项，最后合法索引30；不能因当前/历史区相距32×24B就宣称容量32。函数没有明确统一设置成功/失败返回码，满了就跳过本次登记。

登记按id从历史列表头向后找第一项，匹配则取历史中心；无匹配则历史中心=当前中心，初次出现的位移差为0。当前列表不先去重，因此不能称id为有唯一性保障的对象句柄。

## 对象更新后的登记与查找

12034先执行实体回调，再在entity[B]&08置位时调用099BC：id来自entity[1C]，属性来自entity+26，位置来自entity+54，shape指针来自entity+30。该路径的id只读u8，而099BC接口本身保留低16位。E4390在部分对象池更新中调用12034，因此矩形由本轮对象更新贡献；不是每个可见对象都会自动有矩形。

1F3D0(id)反向扫描当前列表，返回最后一个同id项的索引；未找到返回FF。参数为32位-1时直接未找到；不要把任意u16 FFFF都自动当成同一个-1输入。当前重复id最后项优先，与登记时历史重复id第一项优先不是同一规则。

07F64初始化时清当前与历史计数。后续确认14AD8在参数低8位为0时复制有效前缀到历史区、提交historyCount并清currentCount；非零跳过。具体地址、主循环顺序及暂停实例见[快照轮换报告](semantic-rectangle-history.md)。历史值对应最近一次有效快照，不保证上一显示帧。

## 点查询边界和副作用

09FE4(x,y)从当前列表头开始，使用以下无符号比较：

```text
u32(x-centerX+halfWidth) < 2*halfWidth
u32(y-centerY+halfHeight-1) < 2*halfHeight
```

正常坐标域下等价于：横向含左不含右，纵向不含上但含下。零宽或零高永不命中；这不是四边都含或四边都不含的普通几何模板。

命中第一项时返回该项属性，并把currentX-historicalX写到02000020；不继续找其他重叠项。无命中返回0，但没有清02000020。属性本身为0的命中也可能返回0并更新副输出，所以不能只凭返回0断言“没有改变任何状态”，也不能在失败后使用旧副输出当本次结果。

例：中心(100,80)像素、半宽8/半高4。x=92命中，x=108不命中；y=76不命中，y=84命中；y=76像素再加1个定点单位就进入。边界和坐标量纲已保存在JSON。

0991C/09930可枚举同样包含条件的矩形：0991C以起始索引-1开始，09930从给定索引+1继续，耗尽返回-1。它的失败值不同于1F3D0的FF。

## 方向推离与扫过区间

0A094/0A11C/0A1B8/0A25C对候选点命中后推到对应边界，再从列表头重新扫描，直到没有响应项：

| 函数 | 返回坐标及命中后的修改 | 属性8000 |
|---|---|---|
| 0A094 | y=centerY-halfHeight，上侧边界 | 此函数不跳过 |
| 0A11C | y=centerY+halfHeight+1，下侧外1单位 | 跳过 |
| 0A1B8 | x=centerX-halfWidth-1，左侧外1单位 | 跳过 |
| 0A25C | x=centerX+halfWidth，右侧边界 | 跳过 |

四函数的比较和单位不同，不能抽象成“统一用同一种开区间/闭区间推出”。它们也没有逐次重扫的显式总次数上限；此处记录原行为，不添加研究推测的修复。

0A458还接收横向起点/终点：对特定运动方向，它把路径的中点及半长用于与矩形范围比较，再限制终点；反向分支调用已有点推离助手。这种带区间参数的路径与只检查最终点不相同。完整双方向扫掠、垂直路径及调用者约束仍待展开，不声称已证明全引擎防穿透。

090D4/09240等静态地形查询之后调用这些动态推离函数，说明两层可叠加。09FE4还在08CFC等完整属性查询的静态形状未命中分支被调用；不能把RAM地形格查询当作所有碰撞的唯一来源。

## 贴附与随矩形移动

1F478(outputPosition,attachment)从attachment+7C取关联id，经1F3D0查当前矩形；找到后先调整outputY，使其依赖矩形当前中心、半高和attachment所指自身形状记录的+4值。该形状记录不能未经核实直接套用099BC的登记描述符布局。

若矩形属性&6000非零，再将currentX-historicalX加到outputX并返回此差；否则返回0。因Y已在前面写过，返回0并不表示位置没有改变。23420的实体更新路径有明确调用，连接了记录历史位置与实体贴附行为。

1F4F0是侧面关联路径：从attachment+80查id，按方向及自身形状记录调整outputX；属性&6000非零时返回currentY-historicalY，否则0。它不是简单复制1F478后交换两个字段，仍有方向相关的一单位取整。

这些证据支持“矩形可携带贴附实体随其运动”的语义，但不把所有矩形都命名为移动平台，也不把6000中两个位逐个赋具体含义。原始关联标识、当前/历史坐标、实体动作状态机分别承担不同职责。
