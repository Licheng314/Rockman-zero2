# 对象帧、绘制桶与OAM提交

日期：2026-10-29。第15个研究单元，继续只读已有汇编/原ROM，独立写研究文件。范围限定普通绘制回调033C和关联对象路径；仿射回调未展开，不推断全部画面机制。

[实际帧记录与缓冲证据](semantic-data/object-frame-evidence.json)，美版原ROM SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。033C与127E4部分没有独立提取源，本轮从原ROM指定入口反汇编，不把常量池连续读成指令。

## 实体内的绘制记录

S=entity+34（偏移均十六进制）：

| S偏移 | 本路径中的用途 |
|---|---|
| +0 | 绘制桶的下一记录指针 |
| +4 | 绘制回调；03454设置为Thumb指针0800033D |
| +8 | 当前bank的帧头表 |
| +C | 坐标指针；12580初始化时为entity+54 |
| +10 | attr0/attr1的组合模板 |
| +14 | attr2模板，低10位tile基址，最高4位颜色槽 |
| +16 | 输出attr1高字节的异或掩码 |
| +18/+19 | 水平/垂直翻转的坐标处理标志 |
| +1A | 动画记录给出的帧编号 |

03454初始化该结构并安装033C回调，12580同时初始化entity+6C的动画流，并把entity+1E缓存bank设FF。因此仅有帧编号还不足以显示：帧表、坐标、tile/颜色模板和绘制桶都必须有效。

## 静态与动态bank路径不能混同

127E4(entity,script)把高8位作为bank、低8位作为序列。bank变化时，entity[B]&4=0从0842E800装动画表、从08414B00装帧头表；掩码04置位则从084C9800装动画表并将entity+1F资源变体缓存重置FF。两路最后都执行04B3C重置序列，不能认为bank不变就完全无动作。

静态路径还以0202E590[bank]+entity+20更新tile基址（掩码3FF），以0202E390[bank]+entity+22更新颜色槽；entity[B]&20置位时跳过自动颜色更新。这里0202E590/0202E390各项为u16，不是指针表。

128D4先执行04B9C，再把当前记录的值字节写S+1A。静态路径到此结束，不会每帧重新加载图块。动态路径从084AD300[bank]取得帧头表，以帧头+3字节判断资源变体；变体未变则不请求加载。变体改变时依bank范围选择084CC680的12B图块记录或20B图块/调色板记录，经027AC排队图块；后一范围还直接调用02AEC加载调色板，然后更新tile/颜色模板。

### 排队失败与缓存的实际顺序

128D4在调用027AC之前就把新资源变体写入entity+1F，且没有检查027AC的返回值。027AC满16项会返回-1；下次相同变体会被缓存判定跳过。因此不能声称队列满了就自动下次重试。之后变体再次改变或bank切换重置缓存时仍可能重新请求。此为代码边界，不代表已在游戏运行中复现丢图，也不在后台运行时修改加载策略。

## 颜色槽覆盖

12CA4(entity,slot)置entity[B]的20标志，将slot写entity+23，并将slot低4位合入S+15高半字节。127E4和128D4均尊重此标志，保留手动颜色槽。输入slot在机器级只按u8处理，颜色属性存储会截成4位；不能把它当作带0..15检查的安全接口。

DD17C通过该接口按持久位图选择颜色槽6或7。这与上一轮的OBJ槽6局部变白有联系，但不保证所有项目状态都使用槽6；“为bank加载颜色到6”与“本对象最终选择哪个槽”是两件事。

## 可见对象到128个绘制桶

1218C遍历对象池，entity[A]&1为可见标志；可见对象才进入04A80排队。priority由S+15的bits2..3提取（或指定0），layer来自entity+25。正常priority=0..3、layer=0..31域，桶编号为priority*32+layer。

04AF4准备0x200B桶头数组（128个指针）并清零；04A80在对应桶头插入S，故桶内是逆序链。04AA4按桶0..127遍历，每个记录经S+4回调绘制。priority/layer范围是调用约束，04A80本身不为任意layer做越界检查。

04AA4还在栈上用033DC准备24B坐标转换上下文；033C使用其中+8/+C减去对象坐标。该绘制桶与对象池活动链不是一套链，不能用一方的顺序解释另一方生命周期。

## 033C的帧表与像素位置

帧头4B：u16偏移（相对S+8的表基址）、u8小图块数量、u8资源变体。普通回调033C只用前三字节；128D4动态资源分支使用第4字节。图块列表每项8B：attr0 u16、attr1 u16、attr2 u16、signed8 dx、signed8 dy。

033C对每项从坐标指针读取24.8定点坐标，减上下文偏移后算术右移8，再加dx/dy。翻转路径改为减偏移、再减查表得到的width-1/height-1；不能写成减width/height。尺寸表由(piece[1]>>4)|(piece[3]>>6)索引，合法数据需匹配表域。

裁剪使用固定边界：-128<=x<=245、-64<=y<=159，超出则跳过该项。这是扩大边界的粗裁剪，并非按每项真实宽高精确求可见矩形。通过时将x截9位、y截8位，与模板和记录属性组合；S+16异或到attr1高字节；attr2则直接加S+14与piece.attr2后写u16，不能改写为三个互不影响的安全位域加法。

只写每个OAM项的前6B，然后目标指针加8；末2B不由此函数清零，其他路径可将其用于仿射系数。

## 项目6/7的双向互证

A8和A9两个bank都指向动画表08432ABC、序列0流08432AC0：00 01 00 FF；都使用帧表0842DA60，帧头04 00 01 00，小图块记录0842DA64为：

```text
00 00 00 80 00 00 F0 F0
attr0=0000, attr1=8000, attr2=0000, dx=-16, dy=-16
```

尺寸索引2查表为32×32，数量1。它与上一轮四段、每段4 tile的32×32资源重排吻合。成长阶段0/1切换A8/A9图块与调色板，布局和动画表共享；不能把两个阶段推断成不同尺寸或更多组合部件。

在无翻转、坐标上下文偏移为0的示例条件下，小图块左上角为(entity.x>>8)-16、(entity.y>>8)-16；这说明其相对于坐标居中，而非以坐标为左上角。最终画面位置仍由实际上下文、对象标志及坐标决定，不据静态资源假设固定屏幕位置。

## OAM容量检查与发布

缓冲03002ED0..030032D0（不含）共0x400B，128项；030032D0本身存当前写指针。033C先按整帧数量检查cursor+count*8是否严格小于030032D0，再做逐项裁剪。相等也拒绝，且整帧拒绝；因此本回调从空缓冲最多占127项，不能把所有128项都当作可用。此限制只属于033C，不外推到其他绘制器。

检查发生在裁剪之前，可能出现整帧数量超预算而拒绝，即使最终可见项本可容下。count=0也没有显式跳过循环，合法帧须有正数量；不据单个项目样本证明全表均合法。

03044把当前写指针之后的项逐项写attr0=0200隐藏；再用DMA控制84000100将完整0x400B从03002ED0送到07000000，最后把写指针重置为03002ED0。其余属性没有逐项清零。显示任务005FC先调用03044，再在后面的02544处理图块传输请求；二者职责和时间点不同。
