# 脚本控制字到实体按键映射

日期：2026-10-29。深化第16个输入研究单元，不额外增加模块计数。仅只读汇编与美版原ROM，报告和[原始证据](semantic-data/script-control-evidence.json)独立保存。基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 三套结构的连接

定义G=0202EC30全局控制结构，X=0202EC40脚本/场景上下文。149F4调用1B474(X)，后者在脚本有效时先执行1B6C4，再调用1B730整理输入。这里X不是实体指针。

| 位置 | 已确认意义 |
|---|---|
| X+C | 当前8B脚本命令指针 |
| X+10 | 第一个实体指针 |
| X+20 | 另一个实体指针 |
| X+D0 | 更新累计计数 |
| X+D4 | 脚本等待计数 |
| X+148，即G+158 | u16输入覆盖字W |
| G+4/G+6 | 两路输出控制字，正常状态分别来自两输入通道的按住值 |
| G+12 bit0 | 本路径脚本运行标志 |

偏移及位掩码均十六进制。G+4/G+6不是前一轮输入记录的pressed/repeat：它们在正常路径是两个通道的held。02000D10与02000D28各自内部才有+4边沿和+6连发，不能把两套结构的同名偏移混用。

## 1B730的三条控制路径

1. W=0：G+4=u16[02000D10]&7FFF，G+6=u16[02000D28]&7FFF，读取两通道的按住状态，而非新按或连发；本函数没有检查输入记录的状态字段+8。
2. W=FFFF：G+4和G+6均清0；若X+10实体非空，调用22FB8清它的+188/+189两个字节。第二实体X+20非空且其signed8(+8)==0时才也清这两字节。若第一实体为空，则第二实体也不会进入清理。尚不把这两个字节命名为某种具体技能状态。
3. 其他非零W：先把原W同时写G+4/G+6。若第一实体存在，再按W的1000/2000/4000分别调用1EEC4(entity,0/1/2)，把返回的按钮位OR到G+4。G+6不做这些动作展开。

因此两个输出即使先复制同一控制字，也可能最终不同；抽象动作位与8000标记未被剥掉，结果不等于一个只含低10按钮位的干净模拟按键。W=FFFF有特殊分支，不能按“全部抽象动作同时按下”解释。

## 类型0实体的按键配置

1EEC4按entity[9]索引08333ADC分派。这里只验证第0项08037505→37504，不把相邻ROM指针自动扩成这张表的合法类型范围。其他类型的接口契约待分别确认。

37504通过3712C选择按键配置，再用083347C0的索引字节取对应u16按钮掩码。本轮调用的抽象动作0/1/2，索引恰为[4,5,6]。

3712C检查entity+1F4：

- 值0/1：配置地址083347A0+16*mode。
- 值2：直接使用entity+1E4的16B自定义配置。
- 其他值没有在本函数中钳位；不能认为所有u8值都能安全选择预设。

| 配置槽 | 预设0 | 预设1 | 本轮抽象动作 |
|---|---|---|---|
| 0 | Up | Up | 未从此调用使用 |
| 1 | Down | Down | 未从此调用使用 |
| 2 | Left | Left | 未从此调用使用 |
| 3 | Right | Right | 未从此调用使用 |
| 4 | B=0002 | B=0002 | 0（W&1000） |
| 5 | A=0001 | A=0001 | 1（W&2000） |
| 6 | L=0200 | R=0100 | 2（W&4000） |
| 7 | R=0100 | L=0200 | 未从此调用使用 |

这里只把动作编号映射成按钮，不从常见游戏习惯猜它们分别对应跳跃、攻击或冲刺。自定义配置也按同一槽位读取，内容本身不限制成单个低10位按钮；多位掩码会原样并入结果。

在第一实体有效且类型0的前提下，静态实例为：

| W | 预设 | G+4 | G+6 |
|---|---|---|---|
| 8000 | 任一 | 8000 | 8000 |
| 9000 | 0或1 | 9002 | 9000 |
| A000 | 0或1 | A001 | A000 |
| C000 | 0 | C200 | C000 |
| C000 | 1 | C100 | C000 |
| FFFF | 任一 | 0000 | 0000 |

8000路径不读取物理按键，但仍输出8000标记；FFFF才是本函数的清0及附加状态清理路径。这两者不能合并成完全相同的“停控”。

## 脚本命令09怎样设定W

1B6C4从08326364按命令第0字节索引处理器。第09项08326388的Thumb指针0801C20D，处理器1C20C读取当前命令第1字节作为子操作：

| 子操作 | W写入 |
|---|---|
| 0 | 8000：覆盖真实输入，低位无动作 |
| 1 | 0000：恢复读取真实输入 |
| 2 | low16(u32(command+4) OR 8000)：按负载指定控制字 |
| 其他 | 不改W |

处理器总返回0，正常解释器会继续同一轮的下一条8B命令。负载是u32读取、u16存储，高16位被丢弃；例如负载低16位7FFF会产生FFFF特殊路径，而不是普通合成输入。本轮未验证全部脚本是否使用该组合。

解释器先检查X+D4：非零时减1并返回，本次不执行新命令。无等待时，返回0的命令推进8B后继续；返回非0也对处理器返回后的指针推进8B，但当轮退出；处理器可先把指针减8，实现重查当前条件。遇FF结束标志则清G+12 bit0并返回1。这里的FF不是动画流中的停止码，格式也不是2B动画记录。

脚本结束分支不在此处清X+148；1B474随后仍调用1B730。因此不能声称脚本结束必定自动恢复真实输入，已确认的恢复命令是09/子操作1，另有1B320初始化将W清0。完整场景退出路径是否另行复位，需要继续核对。

## 调用时序与边界

1B474先运行脚本，再计数和整理控制输出，所以命令09的写入可在同一次1B474里影响1B730。若多条即时命令连续覆写W，最终采用本轮停下时的值。没有把这种静态顺序换算成每屏幕帧必运行一次。

本报告只建立“原始输入→场景覆盖→配置按钮位”的桥，不把G+4/G+6等同于最终实体动作：动作状态机、关联实体、动画/碰撞门控仍可能再处理这些值。正常W=0路径也没有重新验证通道有效性，上一轮已记录的输入失效后旧字段保留问题仍需由模式切换流程解释。
