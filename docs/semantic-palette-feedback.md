# 调色板缓冲、软件颜色变换与成长反馈

日期：2026-10-29。只读汇编及美版原ROM，独立保存语义资料；未修改后台提取、正式清单、C源或构建产物。这是第13个研究单元，范围为已建立证据的调色板路径，不代表全项目图形系统已理解。

[原始调色板及静态时序证据](semantic-data/growth-palette-evidence.json)。基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。以下调用次数由指令静态推导，不是模拟器画面或帧率测量。

## 缓冲与发布职责

| 地址/函数 | 已确认用途 |
|---|---|
| 03002AC0..03002EBF | 0x400B软件调色板颜色缓冲，512个u16 RGB555 |
| 03002EC0/EC1/EC2 | 软件颜色系数字节，分别送入红/绿/蓝通道变换；不是硬件寄存器 |
| 02AEC(descriptor,destinationOffset) | 从描述符相对地址取颜色，按格式分支复制/解压到软件缓冲 |
| 02994 | 按系数复制或变换整个0x400B颜色缓冲，写到05000000；随后还有附加覆盖步骤 |
| 005FC任务槽2循环 | DE318字形上传后调用02994，随后继续其他显示提交，再让出任务 |

02AEC读取descriptor+4的u16长度，0则不复制；descriptor+7乘32加入destinationOffset；descriptor+0的u32是相对descriptor自身的源偏移，+6字节选择解压/直接复制。不能把相对偏移直接当绝对ROM指针。

02994的中性分支使用040000D4起的DMA寄存器，源03002AC0、目标05000000、控制84000100，传256个32位字，即整个0x400B颜色区。非中性分支由02B30/02B74/02BC4软件变换并写目标。尾部在配置长度非零时再覆盖一段目标颜色并清请求长度；不能将前面的变换视作最终目标的唯一写入者。

原ROM 080029B4比较的只有EC0与EC1。两者相同就走统一系数分支，不再独立比较EC2；因此不能把接口泛化成“总是逐个应用3个系数”。本轮成长路径三者同时写相同值，不受此差异影响。三者不同情形中的分派约束保留待查。

## 成长图像选择到颜色来源

DD070(entity,itemId)按D58D0得到类别、D58A8得到组内序号、D5968得到当前成长阶段。它从0834C2F0的类别指针表取u16脚本编号：每项目6B，每阶段2B。6B布局不意味着每项目都有3个合法成长阶段，仍须使用对应成长上限。

ECD68取脚本编号高字节作为图形bank。令B=08432D0C、entry=B+20*bank，则原色源为entry+u32(entry)，不是B+u32(entry)。每次调用都从ROM原色重新计算，故不会把前一调用的变白结果再次叠加。

DD17C在项目网格图像脚本变化时为该bank设置OBJ颜色槽6，再经02AEC把描述符颜色加载到缓冲；DCF68的配置项目图像以6+槽位索引分配OBJ颜色槽。ECD68仅直接处理OBJ颜色槽6，即缓冲+2C0起的第1..15色。

具体实例：

| 项目 | 成长阶段 | DD070脚本 | 调色板描述符 | 原色源 |
|---|---|---|---|---|
| 6 Estan、7 Peatan | 0 | A800 | 08433A2C | 084A30E8 |
| 6 Estan、7 Peatan | 1 | A900 | 08433A40 | 084A3328 |

上述两描述符长度均为0x40B，即两个16色组。ECD68只改第一个组的15个非零索引色；不能把这称为“覆盖所有64B描述符颜色”。颜色索引0被跳过，没有写透明色。

## 局部变白与全局系数是两层作用

k=root+DE8的u8。ECD68对RGB555的每个5位通道c执行：

```text
local(c,k) = c + floor((31-c)*k/48)
```

EF2B8在此做无符号除法。k=0保留原色，k=24向白色走一半，k=48为31。15次循环从源+2与目的+2开始，目的范围03002D82..03002DA0（末地址不含）。任意外部k>48没有钳位，结果会跨通道或截断；公式的颜色语义限定正常反馈0..48域。

k>=24时，它另外把EC0/EC1/EC2全部设为m=32+floor((k-24)*32/24)，k=24特别写32；k<24则不写系数，保留旧值。因此不能断言刚进入反馈的前23次一定是中性系数，须由此前界面初始化保证。正常反馈一旦到24，随后回落会在24再次写32。

m=32是中性发布；33..64走02B74，逐通道效果为：

```text
published(c,m) = (floor(c*(64-m)/32) + m-33) & 31
```

这里c是发布时软件缓冲的当前通道，而非必定来自ROM的原通道。33的附加量为0，64为31；不是常见的理想线性白色混合式，不能擅自把m-33修成m-32。低端0..31走02B30的floor(c*m/32)变暗。以上公式限0..64正常域。

k=48时，全局m=64将发布颜色变成白色；这是对整个颜色缓冲的变换，而不仅是被局部修改的OBJ槽6。它也解释了成长切换图形资源时可在白色峰值遮住色板替换，但完整可见效果仍须模拟器验证，发布尾部附加覆盖以及其他写入者不能忽略。

## 修正反馈顺序：两次小闪动在升级之前

EC59C在金额达到剩余需求且玩家确认时，初始化：state(root+4)=2、k=0、direction(root+DE9)=+1、repeat(root+DEA)=2。DE9/DEA按有符号字节读取。

EC664先k+=direction；上行时repeat不为0的峰值为24，repeat为0才用48。到峰值改direction=-1；仅48峰值切state=3并调用D59AC更新阶段。下行到0时改direction=+1并repeat--。state3由EC708调用同一个EC664，repeat<0时收束为state4，清root+DDC闪动字段。

正常初值、每次恰好调用一次且无外部篡改时：

| EC664累计调用数 | k | repeat | 行为 |
|---|---|---|---|
| 24 | 24 | 2 | 第一次小峰值，下行 |
| 48 | 0 | 1 | 第一次返回原色，上行 |
| 72 | 24 | 1 | 第二次小峰值，下行 |
| 96 | 0 | 0 | 第二次返回原色，上行 |
| 97 | 1 | 0 | 最后主闪动开始，调用032EC(28)效果/声音接口 |
| 144 | 48 | 0 | 白色峰值；D59AC推进阶段；state=3 |
| 192 | 0 | -1 | 反馈结束；state=4 |

192是反馈函数调用次数，不是已证实的192屏幕帧或秒数。资金/累计已在更早EC544提交，因此升级前有两次小闪动与主上行，不能把付款时刻、升段时刻、反馈结束混为一件事。调用D59AC后ECD68在同次调用重新取当前阶段的图形bank，k=48时本地15色无论新旧原色都输出白色。

本节修正此前成长报告对“大峰值后再小闪动”的错误顺序。正确顺序由EC59C的repeat=2初值和EC664的repeat==0分支共同确定；相同总调用数并不能验证正确的阶段更新时间。

## 前置条件、限制与后续

- itemId、成长阶段与类别必须有效，DD070不是通用越界安全接口；本轮只导出项目6/7的0/1阶段实例。
- 描述符含两个色组不代表ECD68改两个色组；缓冲局部修改不代表已经送屏。
- 不证明任意中断都能自动完成主反馈或退款；不修改正式函数以加入研究推测的保护。
