# 池管理模块全解：初始化器、每池创建函数与实体 ID 分配器

承接 [池收尾](semantic-pool-system-closeout.md)。本轮解出池结构完整布局、
自由链构建器与 10 个每池创建函数。证据基于全段反汇编（静态）。
原 ROM 基线 SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

## 池结构完整布局（0x08006AC4 初始化器确立）

| 偏移 | 字段 |
|---|---|
| +0x00 | 节点数组基址 |
| +0x04(h) / +0x05 | 标志字节 ×2 |
| +0x06(h) | **节点步长** |
| +0x08(h) | 容量 |
| +0x0A(h) | 空闲计数 |
| +0x0C | 头哨兵地址备份（06B38 注册时写 pool+0x14） |
| +0x10 | 空链头 |
| +0x14 | 活动链头锚（= 头哨兵） |
| +0x18 | 尾指针（0x08006B50 尾插分配用） |

## 0x08006AC4 池初始化器（自由链构建）

```
06AC4(pool, flags, nodes, stride, count[栈]):
  填上述头字段; 空闲计数 = count
  循环 count 次: node[0] = 前一节点(逆序链接), node[8] = flags, nodes += stride
  空链头 = 最后节点 → 自由链 = 数组逆序（弹空链 = 从高地址到低地址）
```

**容量与步长均为参数**——同一池机制支撑任意节点尺寸（修正确认：步长由调用方
传入，非固定 0x84；0x080AC534 实例传 0x84 = 该场景的实体池节点尺寸）。

## 实体 ID 分配器 0x0202E13C（新识别）

0x080AC534 在建池时为每节点分配唯一 id：`node[0x1C] = u8[0x0202E13C] + i`，
然后 `u8[0x0202E13C] += count`——**全局字节 id 计数器**，实体 id 空间按场景
累进（回绕由 u8 域决定）。

## 关键推论：句柄格 = 当前池指针（可重装）

句柄格存"当前池结构指针"且由创建函数重写——**同一句柄在不同场景可指向不同
容量/步长的池**。这解释了同一句柄格（如 F084）下观察到的不同字段跨度：
池随场景重建。开放：各创建函数的调用场景与各自的 stride/容量实参。
