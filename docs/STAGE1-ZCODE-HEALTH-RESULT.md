# 阶段 1 生命线语义报告（Z Code）

日期：2026-11-07。范围：Zero 的当前/最大生命、普通受击与受击保护、回血路径。
基线：美版原 ROM，SHA1 `c4d93a58f0f82c526dec8a3fdbda170336303689`；普通难度序章可控地面场景。
本轮为纯语义分析：游戏代码、正式构建与 ROM 保持原样（已核验 ROM SHA1、段清单未动）。

Z Code 原交付为静态研究。验收时在工程本机的 `build/air-actions/core` 下找到已有 mGBA 核心，并复用移动线的序章启动脚本做了原版复测。实测结果和仍缺的证据见第 6 节。

证据来源分三类标注：
- **静态证据** = 原 ROM 指令逐条读取 + 调用链核对（本轮完成，可复核 asm/*.s 与 ROM 字节）。
- **先前静态研究** = [储量与恢复](semantic-resource-storage.md)、[受击消费者](semantic-hit-consumers.md) 已核实内容。
- **待确认** = 尚无证据或本轮预算内未完成。

## 结论总览

| 字段 | 含义 | 依据 |
|---|---|---|
| `E+0xA4`（16 位，即组件 E+0x74 的 +0x30） | **当前生命，实际参与运算的字段** | 扣减、恢复、升级和镜像同步有静态证据。序章原版复测确认实际扣血，HUD 读取链待查。 |
| `E+0x1FD`（u8） | 基础生命上限 | 先前静态研究 + 本轮 30F5C 复核 |
| `E+0x202` bit0 | 上限翻倍标志 | 先前静态研究 |
| `E+0x17E`（u8） | **镜像字节，双重身份**：初始化/重生时=上限，运行中 23420 用当前 HP 低字节同步 | 静态证据（本轮新发现） |
| 组件 `T+0x20`（E+0x94，u8） | 受击保护计时（低 7 位）+ 独立 bit7 标志 | 静态证据 |
| `T+0x22` / `S+0x3A` | 碰撞源序列号：受击保护期间同源重复命中限制 | 静态证据 |

E = Zero 实例（候选 `0x02037CF0`）；组件 T = `E+0x74`，故 `T+0x30 == E+0xA4`（0x74+0x30=0xA4，算术恒等）。

## 1. 当前生命与有效上限

### 1.1 当前生命 = `E+0xA4`（u16），也是出生值来源【静态证据】

- 扣减写入：07258 的 `07792 ldrh r1,[r4,#0x30] / 07794 subs r1,r1,r0 / 07796 strh r1,[r4,#0x30]`（r4=组件）；07800 的 `ldrh/strh [r1,#0x30]`（0x07836-0x0783A）；078B0 的 `[r4,#0x30]`（0x0791A-0x07926）。三处 r 基址均为组件指针，组件=实体+0x74，故都落在 `E+0xA4`。
- 恢复写入：E912C 给 `entity+0xA4` 加 1（先前静态研究）。
- 升级写入：D6ED0 写回 16 位当前值并钳位（先前静态研究）。
- 出生写入：见 1.3——组件构造器 06DE4 用 `strh r3,[r0,#0x30]`（0x006DF4）把上限写入该字段。

### 1.2 有效上限 = `37A3C(E)`：基础上限按标志翻倍后取结果低 8 位【先前静态研究 + 本轮复核】

- 初始化：30E68 新开路径 → 31738 → 30F5C。30F5C 模式 0（`0x08030F6C` 附近 `mov r0,#0x10; strb r0,[R+1]`）写 `E+0x1FD=16`、`E+0x202=0`、A/B 组计数 0；模式 1 写 `E+0x1FD=32`、`E+0x202=0x3F`、位图 0xFF、计数取容量表。模式由 `31738` 依据 `[E+0x1FC]`（R[0]）是否等于 9 选择。
- 模式 1 的默认值为 32、满四槽、启用翻倍，模式 0 为 16、空槽。R[0]==9 对应的游戏模式**待确认**。

### 1.3 出生值、镜像与重生/读档/切场景【静态证据】

初始化与恢复共用入口 **30E68**：

- 有快照且快照首字节为 0：从快照 +0x1C 回拷 `E+0x1FC`（20 字节，含上限与槽）、+0x30→`E+0x210`（24B）、+0x48→`E+0x228`（100B，memcpy 0x080EF3F0）。
- 无快照：31738→30F5C 默认初始化。
- **两条路径随后都执行** `bl 37A3C` 并把结果（有效上限）写字节到 **`E+0x17E`**（0x08030ECC-0x08030ED2：`mov r2,#0xbf; lsl r2,#1; add r1,r4,r2; strb r0,[r1]`）。
- 随后 `37524`（经 0x1EEFC 处类型函数表 `0x08037525` 项间接调用）安装生命组件：**06DE4 用 `ldrb r3,[E+0x17E]` 作 `strh r3,[comp+0x30]`** —— 出生当前 HP = 镜像值 = 刚写入的有效上限。所以「出生生命」不是独立常量，而是上限经 `E+0x17E` 中转。
- 运行中 `sub_08023420` 会再把 **当前 HP 低字节** 同步进 `E+0x17E`（`add r0,r5,#0xa4; ldrh r0,[r0]; …; strb r0,[E+0x17E]`）；D6E78/D6ED0 升级路径同样同步。即镜像在初始化时刻=上限、运行时刻≈当前 HP。
- 结论限于经过这条初始化链的情况。有快照时，根据恢复的上限和标志重算镜像。无快照时，按所选模式初始化参数后再计算。重生、读档和切场景各自何时经过该链，以及快照与存档的对应关系，仍**待确认**。

### 1.4 界面显示副本

- **待确认**：HUD 血条的具体读取函数本轮未在预算内定位。已排除一个假阳性：`sub_08001E18` 虽以 `[rX,#0x30]` 半字读值，但其基址是全局 `0x02000CA0`（音频系统），目标 `0x0400012A` 是 TM2CNT_H，与生命无关。
- 已确认运行中的镜像同步。HUD 是否读镜像仍需捕获读取方，可对当前生命与镜像设读访问断点并识别绘制调用链。

### 1.5 相邻易混淆字段【静态证据，防误用】

- `E+0x1FC` 记录的 20 字节是上限/标志/槽位/储量（R 布局见储量报告），不是当前 HP。
- `E+0x210`、`E+0x228` 是快照回拷的相邻数据块，勿与储量/HP 混名。
- `sub_08015E78`/`block_08015D08` 以**半字**向某结构 +0x17E 写 0x1E（30）——基址寄存器与 Zero 实例的关系未核实，**待确认**，不能当作同一字段。
- 0794C（`strh r6,[r1,#0x30]`）是与 07800/078B0 同族的第三种扣血入口，首轮预算内未深入，**待确认**。

## 2. 普通伤害路径与受击保护

### 2.1 实际扣血指令【静态证据】

**07258（S=来源组件，T=目标组件）**，提交块：

```text
0x0777C  ldr r1, =G(0x030032E0)      ; 全局基址
0x0777E  ldrb r0,[G]; cmp #0xFE      ; 即死标志
0x07786  strh 0,[T+0x30]             ; FE → HP 直接归零
0x0778E  bl 071B8(S,T)               ; 计算本次扣减量（含倍率表，见受击消费者报告）
0x07792  ldrh r1,[T+0x30]            ; ← 实际扣血三连
0x07794  subs r1,r1,r0
0x07796  strh r1,[T+0x30]
0x07798  ldrsh r0,[T+0x30]
0x0779E  cmp r0,#0; bgt …
0x077A2  strh 0,[T+0x30]             ; s16≤0 归零
0x077A4  orr 0x400 → [T+0x14]        ; 置击败状态位
```

- 入口资格（进提交块前的主要门，0x07258-0x0777C）：全局 `G+0` bit7（0x80）置位直接退出；来源/目标 `+4` 链的组件类别与位检查；owner+2 ∈ {3,4,5} 的特殊标记分支；受击保护门（见 2.2）。
- 调用方：`sub_08007D40` 的 `0x07E8A`（碰撞解析分发），即普通敌我接触伤害的自然入口。
- 扣减量与 `14360` 伤害评分累计的关系、`07800`（显式减 1）与 `078B0`（显式量+8 位回绕）的返回值语义，均见受击消费者报告，本轮未改动。

### 2.2 受击保护（无敌计时）【静态证据】

- **进入**：命中提交后，若 `T` 的 owner+2（类型字节）∈ {1,2}，写 **`T+0x20 = 0x5A`（十进制 90）**：
  07258 `0x077D6-0x077DA`（r8=r4+0x20）、07800 `0x078A0-0x078A6`、078B0 `0x0793E-0x07940`。
  类型不在 {1,2} 的受击者不写计时（07258 的 0x077CA-0x077D4）。
- **每次组件更新递减**：组件 tick **06E90**（由组件帧循环 `sub_08012074` 的 `0x120C0` 调用）：
  `ldrb r2,[T+0x20]; 低 7 位非零则 低7位-1，bit7 原样保留，写回`（0x08006E90-0x08006EAE）。
  计数从 **90（0x5A）** 开始，普通样本中每次游戏更新递减。bit7 保留，置位来源和其余语义**待确认**。
- **生效中的门**（07258 `0x07636-0x0764C`）：读取 `T+0x20` **整个字节**。该字节非零且 `T+0x22 >= S+0x3A` 时跳到 `0x0765A`，绕过普通扣血路径。若来源序列号更大，这一道门放行，后续仍有资格检查。
- 078B0 的门槛更硬：`u8[T+0x20]` 整字节非零（含 bit7）直接返回 0；07800 不检查计时（受击消费者报告）。

### 2.3 角色受击保护 vs 同一碰撞源重复命中限制【静态证据，区分】

- 两者都实现在 07258 的同一个门里，机制不同：
  1. **倒计时**存于 `T+0x20` 低 7 位。倒计时与 bit7 共同参与整个字节的零值检查。
  2. **来源序列比较**在保护字节非零时生效。该门按序列值比较，两个来源序列相同也可以触发阻挡。命中登记时，来源 `S+0x38` 的相关位写入 `T+0x23`，`S+0x3A` 写入 `T+0x22`。序列值与具体敌人身份如何对应仍待确认。
- **待确认**：`S+0x3A` 序列号的分配节奏（每接触对每帧自增还是按碰撞登记递增）需要模拟器实测两次连续接触的数值才能定论；静态上只能确认比较方向与写入位置。

### 2.4 复现步骤（供模拟器实测）

1. 普通难度新开序章，走到第一只可接触敌人处受击。
2. 断点 `0x08007792`（07258 扣减）：观察 `r4=E+0x74`、`[r4+0x30]` 递减、`r0=071B8` 返回量。
3. 断点 `0x080077DA`：确认 `[E+0x94]` 被写 0x5A；随后断点 `0x08006E90` 每帧递减。
4. 保护期内再碰同一敌人：断点 `0x08007636` 应走 0x0765A（无扣减）；换一个来源序列号更大的碰撞源应能命中。

## 3. 回血路径（储能槽逐点恢复）【先前静态研究 + 本轮调用链复核】

自然可达路径 = 储能槽菜单逐点恢复：

- **触发条件**：E8FCC 入口——当前 HP（E+0xA4）未达 `22AF0` 上限且四槽储量总和>0 时进入交互；E9050 读 `0x02000D10+4` 键位，确认键只允许非空槽，bit4/bit5 循环选择（EF330 取余）。
- **实际写入位置**：E912C——选中槽储量（`E+0x206..0x209` 之一）减 1，**`E+0xA4` 加 1**，并调 032EC(0x1F)（音效/事件）。
- **恢复量**：每计时到期 +1；计时字节 `context+6` 载入 4、逐帧递减，到期后未满/未空则重载 4 —— 即 **约每 4 帧 1 点**。
- **封顶规则**：加一点后若 `E+0xA4 >= 22AF0(E)`（Zero 的分派项是 37A3C，含翻倍）或槽空，清除 `context+1` 并整理槽位。**E912C 返回 2**，填满时返回 0 的语义属于补充储量的 389D0。
- **自动补充（389D0）**：拾取侧按 A/B 组顺序给第一个低于 30 的槽 +1，受全局 `0x0202EBB0+4` bit1 门控；它写的是**槽储量**，不直接写 HP。
- 复现步骤（模拟器实测用）：装备至少一个储能槽并充能后，HP 未满时按菜单确认，断点 `0x080E912C` 观察 `E+0xA4` 逐 4 帧 +1、对应槽字节递减、到上限停止。

1. **HUD 血条读取函数**：未定位（预算内）。建议在模拟器对 `E+0xA4` 下写断点，血条变化时的调用栈即显示读取者。
2. **`T+0x20` bit7 的置位者与语义**（是否=「变形/无敌形态」常驻免疫）：未查。

4. **15E78/15D08 的 +0x17E 半字写**：所属结构未核实。
5. **R[0]==9 的模式语义**（新开 vs 继承）与快照恢复后 `E+0x17E` 的实际值：需读档实测。
6. 0794C 第三扣血入口与 1EF54 回调→071B8→14360 的普通接触完整链路的场景绑定：后续轮次。

## 6. Codex 验收（2026-11-07）

**工作包部分通过。** 保留生命字段、碰撞扣血与恢复槽静态分析。验收复用同一美版 ROM，从序章站立快照开始，只向模拟器发送普通输入并采样内存。

| 验收项 | 独立复核 |
| --- | --- |
| 生命字段 | 起始 `E=0x02037CF0`，`+0xA4=16`、`+0x1FD=16`、翻倍位清零、`+0x17E=16`。首次受击实际 HP 变 14，镜像当次仍为 16、下一次更新变 14。 |
| 普通受击和保护计数 | 从站立快照按左 32 次更新再松开，扣血发生在第 29、119、209 次，每次减 2。首击后 `+0x94` 逐次从 90 降到 1，区间内 HP 保持 14，第 119 次再次扣血并把计数设回 90。左冲刺和右走的对照也复现了相隔 90 次更新的扣血。 |
| 具体扣血指令及来源区别 | 汇编验证了 `0x08007796` 是该碰撞处理函数的扣血写入点。复测是逐次内存采样，未对自然受击抓到指令级断点。实测登记的 `+0x96` 均为 0，未验证更大序列号的来源例外。 |
| 一条自然回血 | `E912C` 的 HP 加一、储量减一、到上限停止通过静态复核。序章复测中的四槽始终为空，缺少自然拿到并使用有储量恢复槽的复现，因此此项未通过动态验收。 |

本机复测脚本为 `build/stage1-zcode-health/probe-health-acceptance.py`，逐次数据为同目录下的 `health-acceptance-trace.json`。

后续[阶段 1 验收](STAGE1-ACCEPTANCE.md)在序章实测另一条自然回血路径，并通过单指令对照绑定到 `0x08023018`。普通受击样本也用受击计数初始化的单指令对照绑定到 `0x08007258`。储量槽菜单路径保留静态结论。

### 敌人身体接触的集中处理候选

序章普通难度用左冲、左右走、右冲和站立五组输入复测，观察到 12 次各扣 2 HP 的身体接触。Zero 碰撞组件的来源指针（Zero `+0x80`）均指向池句柄格 `0x0202F078`、类型表 `0x0833D990`、类型 1 的三个敌人实例，实际攻击描述符均为 `0x0833DC5C`。本机复跑脚本位于 `build/air-actions/probe-contact-sources.py`。

共享入口位于 [0x08007D40](../asm/sub_08007D40.s) 调用 [0x08007258](../asm/sub_08007258.s) 之前。该处同时有攻击方组件、当前攻击描述符及受击方组件，可据此仅跳过 Zero 收到的敌人身体接触结算。敌人的身体攻击与同一对象主动使用的近身攻击可能共用来源。直接扣血有独立入口，见[受击消费者](semantic-hit-consumers.md)。

本机测试补丁在共享入口筛选当前 Zero、敌方阵营、常规攻击描述及敌人/Boss 对象类别。五组序章对照中，身体接触未扣血或触发受击保护，三组仍各观察到一次敌弹扣 2 HP，Zero 的蓄力枪仍将原版目标从 6 HP 打到 0。Boss 和共用描述符的近身攻击尚未逐项验证。导出与运行检查位于本机 `build/air-actions/build-air-v3.py`，正式原版重建不包含此测试补丁。
