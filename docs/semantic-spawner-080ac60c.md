# 生成工厂 0x080AC60C 与对象归属修正

承接 [发射初始化](semantic-parent-launch-init.md) 与 [捕获回调](semantic-parent-capture-callback.md)。
本轮在筛选生命周期分派器时意外命中**生成工厂 0x080AC60C**，由此触发对象归属的
重大修正。证据 = 原 ROM capstone 反汇编（0x080AC5F0-0x080AC680）。基线 SHA1 c4d93a58…。

## 工厂 0x080AC60C 全解码

```
factory(type_low8(r0), coords(r1)):
    r4 = 06B84(0202F084 池)            ; ★ 池节点分配器（老识别的 06B84！）
    if r4 == 0: return 0               ; 池空
    (r4 + 0x25) = 1
    r4->unk9 = 0                       ; ★ 类型 = 0
    r4->unk14 = 全局表项
    r4->unk20(half) = 0; r4->unk22 = 0
    r4->54 = coords[0]; r4->58 = coords[4]
    12580(r4)                          ; 动画初始化
    r1 = 按类型池[r6] 读字节            ; r6 = type_low8 参数的变体查表
    ...(后续)
```

- 06B84 = 早年识别的"链表转移"函数，实为**对象池分配器**（空链弹出到活动链，
  与 type23-spawn 报告的 B61B4 用法一致）；
- 本工厂产物 e[9] = **0**——使用 0x0833D990[0] = 0x0833DAF0 相位数组。

## 对象归属修正（影响前三轮的解读）

| 项 | 旧解读 | 修正后 |
|---|---|---|
| 0x08065BF8/65CF4/65A05（向外每步/返程子状态机/状态退出） | 类型 0x22 处理群 | **类型 0 对象**（工厂 0x080AC60C 产物，e[9]=0）的相位处理器 |
| 0x0833D990 第一维 | 实体类型 | 实体类型 ✓（保持），但 0x08065xxx 群对应类型 0 而非 0x22 |
| 786F0（发射初始化） | 类型 0x20 | 类型 0x20 ✓（0x0833FD94[8]，且 786F0 读自身 e[9]=0x20 索引 0x0833D990 自洽） |
| 0x08079748 捕获回调 | 786F0 对象注册 | ✓ 保持（类型 0x20 的六段链） |

即：**0x08065xxx 相位处理器群（此前三轮的解码对象）属于类型 0 对象**——
它们是另一族实体（工厂 0x080AC60C 的产物），不是飞行/捕获体本身。
解码内容（向外每步、地形采样、返程子状态机）机械上仍然成立，
仅"属于哪个对象"的归属修正。

## 类型 0x20 与类型 0 的关系（待验证假说）

同理索引 0x0833D990[0]——**每个实体类型在 0x0833D990 有自己的相位数组**。
