# 目标一语义分析分工：Z Code 生命线

Z Code 负责 Zero 的生命、普通受击、短时无敌和一条恢复路径。Codex 负责输入、动作状态、走路、跳跃和冲刺。双方以同一份美版原 ROM、普通难度和序章可控场景为基线，固定形态与装备。本轮交付是语义资料。可以观察原 ROM 在模拟器中的运行和内存变化，保持游戏代码、构建、ROM 和存档不变。

## 交给 Z Code

工作目录为 D:\NewStudio\Decompilation\public-release-clean-20261101。先读 [AGENTS](../AGENTS.md)、[工程交接](HANDOVER.md)、[操作说明](CONTINUE.md)和[阶段 1 路线](SEMANTIC-ROADMAP.md)。原 ROM SHA1 为 c4d93a58f0f82c526dec8a3fdbda170336303689。

1. **生命字段。** 在序章确认活动的 Zero 实例，找出当前生命、基础上限、有效上限和显示或重生可能使用的副本。候选实例是 0x02037CF0，候选偏移是 +0xA4、+0x1FD、+0x202 bit 0 和 +0x17E。以 [储量与恢复](semantic-resource-storage.md) 为线索，优先核对 0x08030F5C 和 0x08037A3C。候选名称只有在实际读写或屏幕变化支持后才升级为已确认。
2. **普通受击与无敌。** 选一个在序章能稳定复现的伤害来源，追到 Zero 本人的扣血写入。记录受击前后各字段的变化、进入和退出短时无敌的条件。尽量用两个独立命中事件或来源区分全局受击保护与同一个碰撞源的重复命中限制。先读 [受击消费者](semantic-hit-consumers.md) 和[扣减公式](semantic-hit-damage.md)。
3. **一条回血路径。** 找一个自然可达的回血样本，记录入口、实际加血字段、恢复量和封顶条件。优先使用序章同一场景。如果序章没有可复现的恢复样本，可使用阶段允许的第二个场景。记录具体操作以及场景变更原因。存档只记录已知的初始化或恢复关系，未知项保留。
4. **交付。** 报告写到 docs/STAGE1-ZCODE-HEALTH-RESULT.md。字段表至少给出地址或结构偏移、位宽、单位、读取者、写入者、生效条件和持久性状态。附普通受击、保护期和一次恢复的可复现步骤及观察值。把结论分别标成模拟器实测、静态证据或待确认。只读诊断脚本和日志放在 build/stage1-zcode-health。收尾运行 python tools/check_research_docs.py。

首批最多深入 5 个新增函数，确有需要时最多扩展到 8 个。每个卡点最多试 3 个明确假设，届时保留证据、阻塞和下一条可检验线索。这个工作包只覆盖 Zero 的一条普通受击和一条恢复路径。完成后交报告即可，改版 ROM、正式汇编、C 源、段清单、后台任务及远端推送均不在本轮范围。
