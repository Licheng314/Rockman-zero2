## 02544真实行为

队列Q=02000D60，计数u32[Q]，条目从Q+4起，每项12B，逆序处理。条目字段为控制字、VRAM偏移、来源/填充值。类型由控制字低2位取得。

| 类型 | 实际路径 |
|---|---|
| 0 | 调02638(来源记录,目标偏移)，不是跳过 |
| 1，长度n=控制字>>2且n<=31 | 调EEF6C，控制数量=(n>>1)&0x1FFFFF，目标加06000000 |
| 1，n>31 | 调EEF68，控制数量=(n>>2)&0x1FFFFF；不存在124B总上限 |
| 2/3 | 把来源字段作为填充值放栈，调EEF68并置01000000填充位 |

EEF68的ROM指令为SWI 0x0C，EEF6C为SWI 0x0B。旧报告二者名称和字数/字节单位混淆；本次以实际目标、参数及寄存器写入为证据，不将BIOS物理传输边界说成已硬件验证。

若Q+C8非零，队列前置先按Q+C4大小把该RAM缓冲复制到VRAM(Q+CC偏移)，再用Q+D0指定的字填充源RAM。不是无条件清VRAM。最后清队列计数。不能据此推断每个8×8图块必须单独入队。

## 02934/02994不是图块暂存链

02934配置DMA先清03002AC0起1024B缓冲，再把该缓冲复制到05000000调色板RAM，并把+400/+401/+402三字节置20。02994在三参数均为20时直接提交同一1024B到调色板RAM；其他分支调用颜色变换助手，未在本次完整执行。

因此03002AC0起前1024B是调色板数据，+400处是颜色控制参数，不是“前段图块、后段调色板”的分区。7C00的RGB555通道含义也不能写成白色，白色的三个通道需同时置满。

## 保留的有效入口与未完成项

027AC的队列去重、容量16及记录/目标偏移字段可继续使用，但“重复命中返回条目”不正确：代码返回0，满队列返回-1。已验证02544的传输分支不证明02638的所有记录格式或像素布局。

保留帧头、OAM、库/序列与ROM记录地址作为候选线索。20B索引步长和12B三字数据是否属于同一层，原报告缺少足够互证，不再把二者任何一个称作最终像素格式。E790运行时映射来源亦未收口。
