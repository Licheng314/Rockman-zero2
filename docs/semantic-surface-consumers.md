# 地形表面搜索与实体纵向纠正

2026-10-29。深化已有地形与动态矩形研究，累计仍20单元。依据原ROM可达Thumb分支及常数，连接点命中、绝对表面坐标搜索、动态候选合并和一组实体纵向纠正。没有修改正式代码或后台提取。证据见[分支/常数/调用点](semantic-data/surface-consumer-evidence.json)，基线SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689。

以下地址省略0800前缀；常数/偏移均为十六进制，计数明确标注十进制。坐标24.8，1=1/256像素。表面搜索结果是绝对Y，不能与08DE8/08F50的修正差值互换。这里不把某一消费者概括成所有玩家/敌人的统一移动算法。

## 093C4：向正Y找候选，再向负Y推出

输入(x,y)，候选c=y、计数n=0。x>>C经无符号比较必须<=77F，否则直接返回-1。y格号检查<=4FF同样采用无符号比较，只是全局边界，不保证具体关卡范围。

循环读取RAM格属性，按08312B8C点表计算占用。若非零且完整属性不等于800F，结束搜索。否则按n奇偶更新候选：

```text
n为偶数：c = ((c+1000)>>C)<<C，再减1
n为奇数：c = c+1
n++，继续检查格坐标；n>127时耗尽
```

每个格尾和下一格首都可能被检测；最多128轮更新不能简写成“跨128格”。例如从c=0123开始，未命中的候选序列为0FFF、1000、1FFF、2000……，最初还会检测输入位置本身。这里不是每轮加固定16像素。

未耗尽时调用08DE8(x,c)得到d：d<=0则候选改为c+d，再调用A2FC(x,原y,候选)；d>0直接返回0。耗尽时把7FFFFFFF作为候选交给A2FC，而不是立即返回该常数。初始y越全局范围但计数未耗尽仍会进入修正路径，不应臆加安全返回。

093C4本身未统一过滤任意8000位，而是排除整值800F。内部调用08DE8还含动态矩形修正，末尾A2FC再次做区间候选合并。

## 0958C：反向搜索与返回约定

使用08312BCC，参数u=x&FFF、v=(~c)&FFF。只有形状响应非零且attribute&8000==0才结束搜索。未命中时：偶数轮c=(c>>C)<<C，奇数轮c--；同样以n>127判断耗尽。例如0123→0000→-1，负格号下一次越全局范围，不会继续读取负索引。

未耗尽时08F50(x,c)返回d；d>=0则把c+d交给A3A0(x,原y,候选)，d<0则直接返回7FFFFFFF（原ROM常数位于08009680，不能误读成80000000）。耗尽时以候选0进入A3A0。x非法仍直接-1。

两边的0、-1、7FFFFFFF与耗尽候选没有统一的“无表面”协议；调用者必须按真实路径处理，不能仅通过正负号假定结果类型。

## 动态候选合并不是简单点查询

当前矩形列表从020011D4开始，计数020011D2，24B步长。沿用已有字段cx/cy、半宽hw、半高hh。

A2FC(x,y,c)：若c<y，直接返回A094(x,c)。否则固定h=(c-y)>>1、m=y+h，依列表顺序检查全部矩形：

```text
u32(x-cx+hw) < 2*hw
u32(m-cy+hh+h) < 2*(hh+h)
并且 c > cy-hh
=> c = cy-hh
```

h和m在扫描前只计算一次，不随c收缩重算。该路径不测8000属性位。无命中时返回原候选；后续项只能按实际条件进一步减小c。奇数长度经右移向下取整，不能凭连续几何直觉把检测区间扩到原始端点。

A3A0(x,y,c)：若c>y，直接返回A11C(x,c)。否则固定h=(y-c)>>1、m=y-h：

```text
u32(x-cx+hw) < 2*hw
u32(m-cy+hh+h) <= 2*(hh+h)
并且 c < cy+hh+1
并且 attribute&8000 == 0
=> c = cy+hh+1
```

第二项确实为<=：原ROM中cmp r2,r1之后的blo分支只排除严格大于右端的情况；A2FC对应比较排除等号。两方向的垂直包含边界、8000过滤及输出+1不同，不能做未经证明的对称化。所有加减和比较都应按原32位有符号/无符号语义保留，以上只在通常坐标域作区间解释。

## 44F20：实体按纵向运动分支纠正

输入(entity,radius)，radius先截为u16。x=entity+54、y=+58、vy=+60。先用08CFC判断点的完整u16属性是否非零，包含动态矩形补查。

| vy | 查询/写入 | 返回 |
|---|---|---|
| >0 | 点(x,y+radius)命中后，y=093C4(x,y+radius)-radius | 命中1，否则0 |
| <0 | 点(x,y-radius)命中后，y=0958C(x,y-radius)+radius | 命中1，否则0 |
| =0 | 依次检测上点和下点，不写Y | 任一点非零为1，否则0 |

本函数既不把vy加进Y，也不清vy。命中后直接应用表面搜索结果，未在该处统一检查-1/0/7FFFFFFF；不能为伪代码添加原版不存在的特殊值保护并声称等价。返回1还包括vy=0时的纯探测，不能命名成“本轮成功落地”。

## 44EA4：静止探测、纠正与重力

输入同为(entity,u16 radius)。若vy==0：先探测(x,y+radius+100)，非零立即返回1；不改变Y或vy。若为空，再探测(x,y+radius+800)，命中则Y=093C4(x,y)-radius并返回1。注意第二路径搜索参数是原y，并非刚才探测的y+radius+800。

未提前返回时调用44F20。其返回非零则清vy并返回1；否则vy+=40，若结果有符号大于700则写700，返回0。即每次未命中增加0.25像素/更新的速度增量，上限7像素/更新；不声称更新周期必等于屏幕帧，也不臆造负速度的对称限幅。

因此返回1可表示静止时下方1像素点已有占用、8像素探测后贴面、任一方向纠正或静止上下点命中。它不是精确的“刚落地事件”。

## 实际消费者42BB8确认执行顺序

42BB8初始化将vx(+5C)=0、vy(+60)=FFFFF900（-7像素/更新）。进入常规路径后：更新显示/计数，44D54计算并写X；然后Y+=vy；再调用44EA4(entity,0)。最后根据纠正/加速后的vy>=0决定推进+E状态并清+F子状态。状态推进并不是单看44EA4的返回值。

这证明至少该消费者在位置积分后纠正碰撞，并在未命中时更新重力供后续使用。不能把44EA4描述成独立完成“移动+碰撞+状态推进”的函数。实体具体种类及完整状态机尚待资源/生成入口证实，本轮不先命名为玩家或某种敌人。
