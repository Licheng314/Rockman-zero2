# 对象池收尾：注册器定位、尾插分配器发现与 4 个 C 集成

承接 [对象池全貌](semantic-object-pool-census.md)。本轮闭合池系统的三个开放点，
并完成优先级 4 的 C 匹配（4 个池函数，3 个正式集成）。
证据 = object-pool-census 系列已存档 + 本轮 src/ 四源。
原 ROM 基线 SHA1 c4d93a58f0f82c526dec8a3fdbda170336303689（每步 Verify）。

## 1. [0x0200001C] 切换格 = 池注册器写入（无运行时切换）

全 ROM 字面量扫描：0x0200001C 仅 4 处池字、全部在池函数族内部——**唯一写入者 =
0x08006B38 池注册器**（8 处调用：0x08012000 初始化区 6 处 + 0x080983A4/0x080AC5A4）。
注册器语义：`*0x0200001C = pool; pool[0xC] = pool+0x14`——全局格 = **主池指针**
（一次性注册，非场景切换上下文）。

0x08012004 = 注册+全节点析构助手（注册后遍历活动链调 node[0x14] 回调）——
池管理模块位于 0x08012000-0x08013500 区。

## 2. 新发现：0x08006B50 尾插分配器（FIFO 语义）

```
0x08006B50(pool): 空链弹出 → node.next = &pool+0x14(头哨兵)
                  node.prev = pool[0x18](尾指针) → 尾.next = node → 尾 = node
```

池头扩展语义：+0x14 = 头哨兵、+0x18 = 尾指针——**06B50 = 尾插分配（×43，
0x08039xxx-0x0803Dxxx 弹幕类为主），活动链 = FIFO**；与 06B84 头插（LIFO-ish）
形成两种调度序。分配器族全景：

| 函数 | 语义 | 调用数 |
|---|---|---|
| 0x08006B84 | 头插分配 | 348 |
| 0x08006B50 | **尾插分配（FIFO）** | 43 |
| 0x08006BF0 | 全局池分配+**前插** | 16 |
| 0x08006BB8 | 分配+指定节点后插 | 1 |
| 0x08006B38 | **池注册器** | 8 |
| 0x08006C28 / 0x08006C4C | 回收（全局/参数化） | 指针调用+2 |

## 3. C 匹配与集成（4 函数全 100% 字节匹配）

| 函数 | 大小 | 匹配 | 集成 |
|---|---|---|---|
| sub_08006C28 回收(全局池) | 30B | 30/30 | ✅ 36B（含池字） |
| sub_08006C4C 回收(参数化) | 26B | 26/26 | ✅ 26B |
| sub_08006BF0 分配+前插 | 52B | 52/52 | ✅ 56B（含池字） |
| sub_08006B38 池注册器 | 12B | 12/12 | ⛔ extent 规则 |

- **C 集成 31 → 34**；
- sub_08006B38 卡点：12B 函数体 100% 匹配，但产出的 4B 池字（0x0200001C 字面量）
  使转换汇编 extent=16B ≠ ELF 函数 extent=12B——integrate_c 的 extent 一致性
  检查拒绝。同构的 06C28（30B+池字+2B 对齐=36B）通过，差异在其 ELF extent
  含池字。处置：保持 asm 段 + C 源留档（卡点活档：字面量池 extent 规则）。
