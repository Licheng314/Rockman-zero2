# 阶段 2C：攻击模组接入条件（首批）

2026-11-08，Codex。用户授权继续推进后，在独立检查副本进行不依赖 2A/2B 验收的前置研究。**本批只闭合普通剑实体的基本关联与退场协议，不代表阶段 2C 完成，不实施改版。** 评分和连击规则仍由 ZCode 的 2A/2B 负责。

基线是美版原 ROM，SHA1 `c4d93a58f0f82c526dec8a3fdbda170336303689`。样本来自阶段 1 的普通难度序章状态，使用 RAM 把已有剑放在主武器槽；没有解锁新武器、改成长、保护计数或磁盘存档。普通首斩按一次攻击后放开；其余夹具另行列明。

## 身份、创建与关联

本样本身份固定为池句柄格 `0x0202F070`、类型表 `0x08336060`、类型字节 **3**。表项指向生命周期表 `0x08336564`，五个回调（清除 Thumb bit 后）依次为 `3A288 / 3A408 / 3A79C / 39088 / 06C28`，均为 `0x08000000` 地址空间。不能将其他池的类型 3 当成同一对象。

创建器 ABI 的静态读法为：`r0=所有者`，`r1/r2/r3` 写对象 `+0x10/+0x11/+0x12`；第五个参数写 `+0x13`，第六个参数交给 `0x08037DEC`，第七个参数写 `+0x66`。这些是原始参数位置，未证明每个参数都可任意组合或具有相同单位。

创建器从该池通过 `0x08006B50` 分配，成功后设置类型、初始回调、图形槽相关字段，写：

```text
weapon.owner(+0x28) = zero
zero.current_link(+0x2C) = weapon
return weapon
```

返回 NULL 的分支不写这些关联。运行中把武器池空闲链头暂设为 NULL，观察不到类型 3 生成，所有者指针和空闲数保持原值；这是**分配返回空的 RAM 夹具**，不是自然填满对象池的容量测试。池头、计数及链表的实际容量压力仍待验证。

## 保活与退场合同

`0x0803A994(weapon, owner)` 的原版条件是：

```text
允许继续 = owner[+0x0D] <= 4
           且 owner[+0x2B6] == 1
           且 owner[+0x2C] == weapon
```

三者有一项不满足就返回 1，更新函数转入 `0x0803A79C`。`+0x2B6` 在本样本充当门控，尚未验证它在全部动作中的完整角色，不把它笼统命名为“攻击开关”。这是读取合法 owner 指针之后的状态检查，不是空指针或悬空指针保护；不能传入任意地址期待安全返回。

验证使用一个原版剑对象，把其 owner 指向 RAM 中的角色结构副本，避免给真实 Zero 设置非法动作导致上层分派异常。保持关联正确时，副本 `phase=0, gate=1` 的对照仍为状态 1；只把 gate 改为 0，或只把 phase 改为 5，均在下一次对象更新进入状态 4。此结果验证所选输入，不声称自然游戏可进入这些人工状态。夹具暂存地址 `0x0203F400` 只服务本次可恢复快照，未证明可作为实际模组的永久空闲 RAM。

退场函数的顺序：

1. 把对象 `+0x0C` 整字设为 4，并把 `+0x14` 回调改为该类型表的退出项（本样本为 `0x08006C29`，含 Thumb bit）。
2. 清对象 `+0x8C/+0x90` 两个字与 `+0x94` 字节；清 `+0x0A` 的 bit 2 和 bit 0。
3. **只有** `owner[+0x2C]` 仍等于自己时才将其清零，不覆盖已经替换的新值。
4. 返回；真正归还池由后续更新调用 `0x08006C28` 完成，不是立即释放。

原版普通首斩样本从首次按攻击计：第 **19 次更新**进入状态 4，关联清零但仍在活动链；第 **20 次更新**才从活动链消失，空闲计数加 1。不是普适的“所有剑技持续 19 帧”。另一个 RAM 夹具把 Zero 的关联改成占位新值，旧剑在下一次更新退场并保留该值，再下一次更新归还池。占位值仅用于相等比较，没有把它作为新攻击对象运行。

因此，复用该原版剑处理器时必须同时满足所有者门控与关联协议，接管和销毁要避免旧对象清掉新对象。回收接口还依赖当前池上下文，不能把 `0x08006C28` 当作脱离调度环境的任意 free。

## 动画、碰撞与参数边界

初始化按对象 `+0x10` 从 `0x083375BC` 选择子处理；更新按同字段从 `0x083375D4` 选择子处理。更新仅在实体仍为状态 1 时继续跟随所有者坐标、调整朝向并推进动画。两个索引表的全部合法子型及其范围尚未列齐，不为新模组分配任意子型号。

更新前后比较 `+0x68` 和有符号 `+0x71` 两个索引，发生变化时经 `0x0803AA00` 更新描述符。它从 `0x08337584` 开始做双层指针索引；参数计算包含：

```text
amount = max(1, u8[0x08335AA6 + weapon[+0x13]]
                + s8[weapon+0x67] + u8[weapon+0x66])
```

随后把 body、选中描述符及 amount、0、`s16[weapon+0x64]`、`u8[weapon+0x66]` 交给共享 `0x08006E18`。这里保留原始类型和参数，不把这些值直接等同于敌人的实际 HP 损失；最终命中与连击仍待 2B 解释。

本批普通首斩观测到描述符 `0x08336594 → 0x083365F4 → 0x08336624 → 0`，可见“剑实体存在”和“当前有攻击描述符”不是同一条件。没有重新测量各描述符对敌人的伤害，没有据序列命名三连斩的三次按键。

## Z3 对照：结构线索与真实差异

固定参考 [mmzret/rmz3 提交 2a28700 的 saber.c](https://github.com/mmzret/rmz3/blob/2a28700e0a74edd9578737c3b3435ced9d074045/src/weapon/saber.c)。仅静态对照，没有 Z3 ROM 运行。`CreateWeaponSaber`、`Saber_Init`、`Saber_Update` 属 `NON_MATCH`/`MODERN` 解释分支，不能把其 C 代码直接当字节匹配证明。

| Z3 线索 | Z2 本批依据 | 结论 |
| --- | --- | --- |
| 创建、初始化、更新、退出分工 | 类型 3 生命周期表与原版更新样本 | 可复用这种问题拆法，不复用布局偏移 |
| 创建器有清旧剑调用，武器私有区保存 Zero 指针 | Z2 所选创建器写 `weapon+0x28` 与 `Zero+0x2C`，没有同样的清旧剑调用 | 创建策略与对象布局不同 |
| 更新时比较当前剑动作编号 | Z2 `3A994` 比较所有者 phase、`+0x2B6` 和关联指针 | 保活条件不同，不能照搬 |
| 动画驱动碰撞描述符变化 | Z2 观察到多段描述符并有 `3AA00` 刷新路径 | 职责相似；表范围与命中细节仍须独立验证 |
